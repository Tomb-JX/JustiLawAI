## 1. 现在可执行与启动条件

- 现在做：用无真实个人资料的合成案例演练提示、模型隔离、逐行落盘、schema/证据校验、仲裁合并、日志恢复和风险复核；定版候选抽样与字段口径。这些结果不计 500。
- 开始真实批次前，采用两条可选路径：来源线发布并经独立核验整版安全的版本；或对 r4 中独立选出的 50 件做**记录级隔离复检**。后者要求每件在冻结哈希上独立复核脱敏、主体、事实完整、事件关联，所有自动信号逐项关闭或替换。整版 r4 仍标“未独立放行”，只允许使用通过的 `pilot50-safe` 子集，不能把未检 r4 其他记录扩至 500。
- 50 件候选按 ID 与事件 ID 去重，源于 `pilot50-v2` 元数据；与旧代理试标只重合 7 件，**全批重新标**。冻结只读输入、每条正文 SHA-256、总文件 SHA256SUMS、schema/指南/提示版本。任何正文或脱敏改动使相应标签与证据失效。
- 真实原文、证据、模型请求/响应及仲裁理由只放受控数据区；仓库、跨线报告只写 ID、类别、版本、哈希和统计。不得复制原名到聊天或提交。

## 2. 三模型角色与隔离

| 角色 | 输入 | 产物与约束 |
|---|---|---|
| A、B 独立标注 | 同一冻结输入、同一字段指南和提示模板；不同模型家族/服务商，互不可见。冻结实际模型 ID、提供商、精确版本与配置 | 各 50/50 的原标 JSONL，逐件落盘。A/B 不能看旧代理标签、对方结果或仲裁结果 |
| C 独立复核与仲裁 | 第三模型家族；先在看不到 A/B 的情况下对关键字段或整件盲判，落盘后再读取匿名的 A/B 值、证据与原文 | 对全部分歧逐字段裁决；对高风险及抽样一致项复核。记盲判、最终值、采纳来源、证据、理由和不确定性 |
| 确定性检查器 | 冻结清单、A/B/C 输出、schema 与原文 | 检查 ID/事件/哈希、字段、类型、证据位置、重复、遗漏、仲裁实际拷贝；不作主观事实裁决 |

**本机 `qwen3.5:9b` 等小模型不得用于复检、标注、仲裁或放行。**本批异构组合：A `deepseek-v4-pro`、B `qwen3.8-max`、C `kimi-k3`。DeepSeek 使用自家官方 API；Qwen 和 Kimi 经百炼官方 API 调用，分属不同模型家族，但后两者共享平台和凭据，报告必须披露这一相关性。三个模型 ID 均经合成请求核验。采用 Kimi 作为第三路，是用户允许的百炼异构模型方案；会话内 GPT 缺少可重复核验的逐件 API 响应 ID 与独立运行清单，未充作正式第三路。依据：[DeepSeek 模型目录](https://api-docs.deepseek.com/api/list-models/)、[百炼 Qwen](https://docs.bailian.console.aliyun.com/en/model-studio/qwen3-8-max)、[百炼 Kimi K3](https://help.aliyun.com/zh/model-studio/kimi-k3)。D-001 中本机模型的历史方案已由[执行口径更正](../deviation-log.md)取代。G0.3 是否达标仍须按冻结输入、同一指南、独立 A/B 结果和原一致性指标计算，且不自动等同原人工试标门禁获批；500 件候选线的效力按 D-002 管理。

2026-10-16 初次检查时工作区未发现 API 凭据；此为历史快照。2026-10-17 三路合成测试和 r4 候选各 50 件逐件请求已完成，三方一致回执 17/50，未关闭 33，详见[复检结果](./pilot50-r4-candidate/flagship-review-outcome-20261017.md)。这不构成完整 50 件安全冻结或 A/B/C 标注完成。密钥仅在临时进程内读取，不写入仓库或运行报告。

已备脚本见[旗舰模型运行手册](./flagship-model-runbook.md)。三个模型须各自对 50 件独立做记录级安全复检；仅三方逐项一致通过、无风险代码、全部自动信号一致判为误报且模型 ID 匹配时，才生成可供冻结检查的候选回执。任一异议保持未关闭。安全冻结后，A/B/C 各自在盲态标注；C 的盲标先落盘，再看 A/B/C 分歧执行逐字段仲裁。终版由确定性脚本实际拷贝所采纳模型的完整字段并校验证据偏移、schema。字段口径按引擎 schema 1.1.0 与指南 v0.2 执行；仍有任何安全或校验错误时不得计入 500。

## 3. 单件标注协议

每个主体案卷一条，`event_id` 关联共同事实。同一冻结输入下逐字段输出 `value`、`status=明确/推断/未提及`、连续逐字证据、相对 `text_full` 的字符偏移；保留模型置信度但不把自报置信度当正确概率。只标本人事实，不以法条引用或处罚结论倒推事实；布尔 `false` 仅有明确否定证据时使用；金额以元记，禁止虚构开放上界或归属。

每个输出必须包含 schema 当前全部字段；有值必有证据，未提及必为空。开放上界金额按 schema 1.1.0 记 `max:null`，营利目的严格按指南 §2.1；无对应枚举、主体冲突、模糊起止日期写受控异常表并保持未决，不能靠强行填值提高覆盖率。未决异常可保留在工作集，但不计完成的 500。

## 4. 仲裁、复核与校验

1. **全量 A/B 校验**：各自 100% ID 覆盖、无重复/多余、每件输入正文哈希一致、字段齐全、类型与状态合法、证据逐字命中且偏移正确。失败行返工，不让错误进入一致性分母。
2. **分歧全裁**：计算每字段在场与取值分歧。C 的盲判先落盘，再逐字段裁决所有 A/B 分歧；A/B 同值但 C 不同也进入裁决。记录“指南歧义 / 模型读错 / 证据缺失 / 源文矛盾 / schema 不足”等类别。采纳 B 时实际复制 B 的值和证据；每条决定保留前后值、理由与来源。
3. **风险分层**：首批 50 件由 C 盲判全部关键字段，并复核所有金额、营利目的、前科日期、主体关联及法版本；对 A/B/C 一致但风险低的字段做预先随机抽样复核。扩至 500 时继续全量确定性校验与所有分歧裁决，C 对每件关键字段盲判，高风险记录整件复核；保留抽样种子、风险规则和覆盖率，不能只查模型已表示分歧的地方。
4. **终检**：仲裁输出逐件再跑 schema、证据、偏移、冻结哈希、事件去重、零未决分歧和异常闭环。发现脚本错误须从原始 A/B/C 与决定日志确定性重建，不手改终版。扁平试标 JSONL 转成 `GamblingElements` 后通过 Pydantic 校验，原标不可覆盖。
5. **抽样复核**：从一致项和仲裁项都抽样交独立异构模型盲审，报告发现的问题及分母；模型复审只能估计模型间稳定性，**不能估计事实错误率 ≤3%**。将来有人力时，从模型输出中独立抽取人工验证集，标注员不看模型答案，再评估真实性。

## 5. 指标与命名

- A/B 分类字段按“至少一方有值”算 κ(union)，关键数值字段按同一分母算完全一致率；另报每字段有值数、双方未提及比例、证据命中与不可计算字段。旧代理正确复算为 κ(union)=0.691、数值一致率=0.864（88 对），说明需要修订口径。此类指标是**模型稳定性/指南诊断**，不是准确率，也不替代原 G0.3/G1.2 的正式门禁判定。
- 交付文件和数据卡统一使用“模型仲裁标注集（项目内金标候选）”或 `model-adjudicated`，注明 `human_review=false`、模型组合、指南/schema 版本、仲裁与风险复核覆盖率、未决项和来源偏差；人工验证数量单列为 0。内部简称“金标”时也必须在同处显著标明这些限定。
- 该集可用于探索性训练、数据管线调试和模型相对比较；**不得把同一模型家族产生的候选当独立测试真值**。在人类验证集建立前，P2–P5 基于人工真值的性能声明、G1.2 错误率 ≤3%、B-H 人类基线及“测试集只用金标”均保持未通过/未执行。D-002 的项目门禁变更仍待周会和指导老师评审。

## 6. 可审计交付与 500 件扩展

每批受控目录保存：冻结输入及哈希、A/B/C 的精确模型标识、提示模板及 SHA-256、参数/种子、时间和调用 ID、逐件请求响应哈希、原标、盲判、逐字段分歧、仲裁决定、异常与复核日志、验证报告、版本化终版及 SHA256SUMS。失败重试记录原调用与新调用，不覆写；敏感原文不进入仓库日志。仓库内只存无原文的批次 manifest、数量、分布、门禁与退回 ID。

先跑 50 件，稳定后按 50–100 件一批扩到 500；目标省份累计 ≥300，保留新旧法、无处罚、不同严重程度和来源，并检查“有金额和处罚结果”比例 ≥80%。同一 `event_id` 或 `linked_ids` 连通组不得跨批次分割到训练/评测两侧；近重复与时间泄漏按 §7/R7 审计。**500 只统计通过全套模型仲裁和确定性校验的记录；人工验证计数始终单列。**
