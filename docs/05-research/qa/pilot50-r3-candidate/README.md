## 冻结关闭标准

1. 来源版本和主文件 SHA-256 固定；整版新发布或 r3 记录级隔离均可。金标线重跑 `audit_pilot_delivery.py` 与 `audit_safe_subset.py`；退回项按 ID、版本、正文哈希关闭，不凭同 ID 的旧回执关闭。
2. 独立复检最终 50 件的正文脱敏、本人主体、事实完整、事件关联，按 ID 留四项回执及自动信号处置。当前[记录级复检队列](./record-level-audit/record_review_queue.csv) 50 件均待关闭，其中 9 件有自动信号；[替换建议](./record-level-audit/replacement_suggestions.csv) 9 件也须复检。任何一件未关闭则整批保持候选。
3. 校验 50 个 ID、50 个唯一事件 ID、正文哈希与交付清单逐件一致；改动后重新生成清单，旧冻结作废。
4. 标准责任方统一标注指南与 schema 对营利目的的定义，并确定开放上界金额的表示法。未决金额入异常表，不用虚构上界补齐，也不计完成记录。
5. 满足以上条件后，用 `freeze_safe_subset.py` 在仓库外创建全新只读 `pilot50-safe` 子集及 SHA256SUMS；manifest 明示来源 r3、记录级通过、整版未通过。模型 A/B/C 的版本、提示哈希、输入哈希随后绑定此子集。r4 改动正文时保留旧子集为独立来源或按新哈希重标，不能迁移旧标签。

## 模型双盲标、仲裁与候选入库

1. 异构模型 A/B 在互不可见的输出目录处理同一冻结输入，每件一行；逐件校验 ID、字段、值类型、证据命中及 50/50 覆盖。原文与证据只留受控数据区。
2. 第三模型 C 先盲判关键字段，再逐字段仲裁 A/B 分歧及 C 反对的一致项；高风险字段和抽样一致项另做复核。所有提示、版本、原标、决定、重试与校验日志完整留痕。
3. `compute_agreement.py` 报告 κ(union)、数值一致率及未提及比例，作为模型稳定性诊断；不能据此宣称真实性准确率或原 G0.3/G1.2 通过。
4. 对仲裁输出复验 50/50 ID、事件去重、输入正文哈希、schema、证据命中和零未决分歧后，登记首批 **model-adjudicated 候选** 50 件；人工验证数量仍为 0，扩至 500 时分列计数。
