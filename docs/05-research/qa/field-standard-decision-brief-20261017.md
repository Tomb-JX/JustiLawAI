## 决议一：`intent.profit_purpose`

[指南 v0.2](../annotation-guideline.md) §5 已要求：仅凭金额、赌局规模、处罚结果或“为赌博提供条件”的定性不赋值；本人获利机制有事实证据但未明说目的时为 `true/推断`；明确否定才是 `false/明确`。目前 `schema.py` 对该字段的 description 却写“有抽头、收台费……为明确；仅凭金额大小判断时为推断”，两者直接冲突。标注脚本只向模型提供本人信息和事实段，因此还须明确事实段与说理段的证据边界。

**建议采纳指南口径并更新 schema 描述及版本**：

| 原文条件（仅限本人信息、事实段） | 值 / 状态 | 证据要求 |
|---|---|---|
| 明确叙述本人以营利为目的 | `true/明确` | 直接表述目的的连续原文 |
| 未明说目的，但叙述本人抽头、收台费或经营性收费等机制 | `true/推断` | 指向本人和获利机制的连续原文；仅有金额不够 |
| 明确叙述本人没有营利目的 | `false/明确` | 明确否定的连续原文 |
| 只有法律定性、处罚金额、赌资规模、未明确归属的获利，或完全没有线索 | `null/未提及` | 空；歧义记异常，不推断为 `false` |

待确认点：事实段出现的“以营利为目的”若只是转述机关认定，是否仍视为“明确”。建议要求可归属于本人的事实叙述，否则列为异常。批准后修订 `schema.py` description、提升 `SCHEMA_VERSION`、重生成指南字段表，并对受影响标签全量重校验；旧代理标签不迁移。

## 决议二：开放上界金额

当前 `AmountRange(min,max)` 两端都须是有限数；规则层及评测代码直接使用 `max`，所以仅把 `max` 改成可空会改变下游行为。指南已禁止捏造上界。建议分两阶段：

1. **首批 50 件暂行**：若相关金额字段只有“X 元以上／不少于 X 元”等下界，记录 `open_upper_bound_unrepresentable` 异常，整件暂不计入 50，优先替换同层样本并重做安全复检及标注。若该短语与目标金额字段无关，须按 ID、r4 正文哈希记录 `not_target_field` 关闭理由，方可计数。不得将已知下界静默当作“未提及”而宣称该件完成。
2. **后续扩至 500**：由 schema 和规则层共同设计真正的开区间表示（例如 `max=null` 加边界类型），同步处理规范层比较、均值特征、JSON Schema、抽取器、验证器和测试，再提升 schema 版本。未完成这些变更前，不把开区间硬塞进有限区间。

[r4 机械预筛](./pilot50-r4-candidate/standard-risk-screen.json) 在 50 件事实段中命中 2 件开放金额短语候选：`P-347`、`W-001059`。这是关键词预警，**不证明**短语属于目标金额字段；还需在同一正文哈希上做语义归属核验。另有 0 件事实段含明确“以营利为目的”短语、5 件含获利机制关键词；关键词数不等于最终标签数。

## 批准与执行门槛

标准责任方需给出指南 SHA-256、schema 源文件 SHA-256 与版本、上述两项选择、批准人与时间；若采纳指南口径，schema 描述须实际更新并提升版本。若采用暂行金额例外，逐个预警 ID 的 `text_sha256` 与 `not_target_field` 关闭记录必须齐全。`assemble_flagship_candidate.py` 已设校验：没有匹配的决议文件，或任一开放金额预警未关闭，`model_adjudicated_completed` 保持 0。安全复检回执 50/50 和旗舰模型 A/B/C 仲裁仍是独立前置门槛。r5 的新供给另做版本验收，不覆盖 r4 候选。
