# 学习笔记：M1 要素抽取原型（受限解码 + 证据校验）

> 2026-10-15 · 代码：`justilaw-api/app/discretion/extract.py` · 探针：`research/eval/anchor_a2/m1_probe.py`
> 配套：[引擎方案 M1](../../02-design/gambling-discretion-engine.md) · [门禁 P2](../sota-baselines-and-gates.md)

## 1. 任务

给定一段案情和目标人员，输出要素本体（schema v1.0.0）里能从原文找到的事实字段。对每个字段的要求是：
- 值必须能按字段类型解析，例如金额解析成区间、日期解析成具体日期；
- 必须附原文证据，证据要能在原文中定位到。

## 2. 受限解码是什么

**问题**：直接让大模型"输出 JSON"，它偶尔会漏括号、写错字段名、塞进解释性文字，程序无法解析。

**做法**：把 JSON Schema 编译成一个"语法自动机"。模型每生成一个 token 之前，推理引擎先算出"按语法此刻哪些 token 合法"，把不合法 token 的概率直接置零（logits 掩码），再从剩下的里面采样。这样输出**一定**符合 schema。
- Ollama 的 `format` 参数接收 JSON Schema，底层就是这样实现的；
- XGrammar、Outlines 用的也是同一原理，只是实现更快。

**代价**：语法只管格式，不管内容。模型若在某个字段里"不知道写什么"，语法仍会逼它写出合法字符串。实测中出现的 "],"、"},{" 这类残渣就是这么来的：模型想结束列表，但语法要求先把当前字段的值写完。所以**受限解码不能替代内容校验**。

## 3. 输出格式的设计：只列有信息的字段，值一律写字符串

```json
{"items": [{"path": "amounts.commission", "value": "三千余元", "status": "明确", "quote": "从中抽头渔利三千余元"}]}
```

- **只列有信息的字段**：本体有 37 个字段，一件案子通常只有 5–15 个有信息。
- **值一律写字符串**：同一个 schema 没法让"值的类型"随字段变化（金额、日期、枚举、布尔各不相同），所以统一成字符串，由代码按字段类型解析。这也是"大模型负责找、代码负责算"的原则。例如"三千余元"由 `parse_amount` 换算成 3000–3999，不让模型去算。
- **`minLength: 1`**：值和证据都不允许为空字符串，模型就无法输出"空字段"。

## 4. 证据定位：怎么判断"引文确实来自原文"

模型复述原文时会悄悄改格式。实测中遇到三种情况：
1. 在数字与汉字之间插入空格（"投注单 77 张"，原文为"投注单77张"）；
2. 改变引号样式（原文 “六合彩”，复述成 ‘六合彩’）；
3. 用"..."省略中间部分。

处理方法：
- **规范化**：对原文和引文做同样的处理。NFKC 统一全角和半角；各种引号统一成一种；去掉所有空白。同时记录"规范化后第 i 个字符来自原文第几个字符"的映射表，找到之后再映射回原文位置。
- **精确匹配优先，相似度兜底**：先在规范化后的原文里找完全相同的片段；找不到时，滑动比较每个等长窗口的字符相似度（`difflib.SequenceMatcher` 的 ratio = 2 × 匹配字符数 / 两串总长），≥ 0.9 才算找到。
- **省略号分段**：按省略号拆成几段，每段至少 4 个字，并且必须**按顺序**都能找到才成立。顺序颠倒或片段太短，一律不认。
- **找不到就丢弃这个值**，而不是降级保留。这就是"从源头防事实幻觉"。

- JSON 残渣（12 条），丢弃正确；
- 模型自己写算式，如 "math.ceil(173890/2)"；
- 解析器没覆盖"X余万"的写法（这是解析器的 bug，已修）；
- 写成"未知""≥55060"。

## 6. 性能

- 本机 RTX 5060 8GB，qwen3.5:9b（Q4_K_M），显存占用 6.6 GB，生成速度约 38 token/秒。
- **2 路并发没有提速**：单件延迟从 6.4 秒升到 16 秒，总吞吐基本不变。说明这块 GPU 已经满载，再并发只是排队。后续批量抽取用单路。
- 线上单件约 7 秒，满足门禁 G2.10（p95 ≤ 15 秒）的方向，正式结论以 P2 门禁测量为准。

## 7. 探针评估方法（结果待补）

- **公平对比**：文本模型和要素模型使用**同一批**已抽取的训练样本（约 1,200 件），在同一个验证集上比较，用配对自助法看差值。如果拿要素模型（1,200 件）去比全量训练的文本模型（3,306 件），差距里会混进训练量的差别。
- **缺失值记 NaN 而不是 0**："没提到赌资"和"赌资为 0"是两回事。梯度提升树在每次分裂时会为缺失值单独学一个去向（左或右），从而把"没提到"本身当作一种信息。
- **堆叠**：要素特征 + 文本模型的折外概率，喂给梯度提升树。
