# 学习笔记：规则生成特征与"只用规则结论"的实务校准

> 2026-10-28 · 连续任务 P2–P3 · 代码：`justilaw-api/app/discretion/rule_features.py`、`practice.py`；训练：`research/eval/rule_chain/rap_v2.py`
> 依据：ADR-010 决定 5、ADR-011 决定 3

## 1. 要解决的问题

实务模型（RAP）学的是"规则这样说时，实际怎么罚"。v1 的 31 个特征是手工挑的：规则读了哪些量、模型看哪些量，两者没有绑定。结果是规则补编了"累计赌资"，模型却看不到；反过来，模型里有参赌人数、场所等规则不用的量。

## 2. 做法：把规则的计算过程当特征

规则引擎对一个案件算一次（`assess`），计算过程里已经有所有中间量。特征名单**从规则文件枚举**，取值**从计算过程读出**：

| 规则声明 | 特征 | 例 |
|---|---|---|
| 规则结论 | 唯一种类 / 候选成员 / 无法定档（× 4 种处罚，共 9 维） | `rule:unique:罚款` |
| 每个计量 `measures` | 档位下界、档位上界、档内位置 log10(值 / 本档下限)、是否缺失 | `320000:参与赌博:measure:personal_or_per_capita:position` |
| 计量的取值来源 `sources` | 用的是累计 / 单次 / 人均哪一种 | `…:source:cumulative_stake` |
| 分类 `categories` | 落在哪类门槛 | `…:category:其他` |
| 升档 / 提示条件 | 成立、未知两维（不成立为 0） | `130000:参与赌博:elevate:method_online:true` |
| 国家法修正情节 | 每个触发项是否触发 | `nat:主动投案如实陈述` |
| 省份 | one-hot | `prov:130000` |

两省共 86 维，训练数据中非零的 55 维。名单的哈希存进参数文件；规则一改，哈希不一致，测试即失败，提醒重训——规则与模型不会再脱节。

**档内位置**为什么取对数比值：门槛是倍数关系（江苏其他类 500 / 2000 / 5000），"超出下限多少倍"比"超出多少元"更可比，也让不同类别、不同省份的门槛放在同一尺度上。

## 3. 结果（开发集 + 工单 B 共 475 条，交叉验证，描述性）

| 模型 | RPS（按事件分组） | RPS（按机关分组） |
|---|---|---|
| v1 手工特征 | 0.1145 | 0.1256 |
| v2 规则生成特征（86 维） | 0.1231 | 0.1228 |
| **只用规则结论（9 维）** | **0.1135** | **0.1158** |
| 边际分布 | 0.160 | 0.161 |

**只用规则结论最好**，与 C-40 同向。直观例子：江苏麻将、本人赌资 600 元（规则唯一结论为罚款），v2 全量给"拘留并处罚款"62%，只用规则结论给"罚款"87%。

## 4. 怎么理解

- **规则结论已经吸收了计量与条件的信息**：档位就是"数额 × 门槛 × 条件"算出来的。再把数额、条件单独放进去，475 条样本学不出稳定的额外规律，只会拟合噪声（典型的高方差：维数 55 有效 / 样本 475，且多数维度极稀疏）。
- **实务模型真正学到的是一张"校准表"**：规则说"唯一罚款"时，历史上 87% 罚款、6% 拘留、6% 并处；规则给出某组候选时，历史上各种类的比例。这正是 ADR-010 说的"学习层只做实务校准"。
- **这不否定规则生成特征**：名单仍由规则枚举，保证"规则用到的量模型可用"；只是在当前样本量下，按开发集选择，模型只用其中的规则结论部分。样本增多后可在预注册下重新比较。

## 5. 选择纪律

候选在开发集上选（按机关分组的 RPS 最低者），选定后写进工单 C 的预注册，只在工单 C 上检验一次；不在工单 C 上挑模型。

## 术语

- **校准表**：从"规则结论"到"实际处罚分布"的映射；多项逻辑回归在只有 9 个 one-hot 特征时，本质上就是按规则结论分组的平滑频率表。
- **高方差**：模型对训练样本的偶然波动过度敏感，换一批数据表现就变；特征多、样本少时尤其明显。
