# 裁判文书批量检索需求（第三方数据服务）

> 版本 v0.2 · 2026-10-15 · 依据：[行政案例数据交付规格](./data-spec.md)、[北大法宝手册](../04-plan/pkulaw-playbook.md)、CAIL 探针教训（[M1 学习笔记](./notes/M1-extraction.md) §8）、§0.1 检索实验
> 用途：向第三方数据服务提出检索需求，并在到货时验收。到货后的入库、脱敏由数据链路负责。

## 0. 先想清楚：裁判文书网能补什么

| 需要的数据 | 法宝现状 | 裁判文书网的价值 |
|---|---|---|
| 个人治安处罚决定书（行政金标主力） | 行政执法库已收录，"赌博 治安管理处罚法"命中 920 | **不在裁判文书网**：法院只公开法院文书，处罚决定书要靠法宝或执法公示 |
| 不服赌博治安处罚的**行政诉讼判决** | 司法案例库仅命中 25（学院订阅未绑定） | **核心价值①**：判决书会复述原处罚决定（事实 + 处罚），还附法院审查结论 |
| 赌博类**刑事判决全文** | 未系统检索 | **核心价值②**：CAIL 只截了事实段，完整判决的"本院认为"部分写有自首、坦白、退赃、主从犯等情节，能补上 CAIL 的信息缺口；同时用于刑事门槛边界（行刑衔接） |
| 刑事判决里提到的"曾因赌博被行政处罚" | — | 次要：可以拿到行政处罚的时间与结果，但没有当时的事实 |

## 0.1 检索实验（2026-10-15，裁判文书网登录后高级检索）

目的：确认检索条件的命中量、精度和年份分布，作为向卖家下单和到货验收的基准。只做了约 25 次检索和约 25 份文书的人工查看，没有批量下载。

### 网站本身的限制与能力

- 每次检索**只能翻看前 600 条**，所以网站界面不能用来批量取数，只能用来**估量和抽查**。
- 左侧分面直接给出按年份、地域、法院层级、文书类型统计的命中数，可作为"省份 × 年份"统计和到货核对的官方基准。
- 高级检索的全文检索可以限定范围：全文 / 首部 / 当事人段 / 诉讼记录 / 事实 / 理由 / 判决结果 / 尾部。**说明网站内部已经把文书切好了段**，可以问卖家是否能提供分段字段。
- 多个关键词用空格分隔，表示"且"；界面不支持"或"和"非"。
- 案由下拉（如"治安管理（治安）""开设赌场罪"）用脚本设置不生效，改用"案件名称含罪名"代替；"法律依据"字段按法条检索返回 0，不可用。

### 行政案件：抽查精度

| 检索式 | 抽查 | 真实的赌博治安处罚案 | 精度（95% Wilson 区间） |
|---|---|---|---|
| 全文"赌博" + 判决书 + 基层法院，最新 11 份 | 11 | 2（另有 7 份是管辖条款误命中，2 份只是顺带提到赌博） | 18%（5%–48%） |
| 全文"参与赌博" + 判决书，前 8 份 | 8 | 8（5 份驳回上诉、维持原判；3 份撤销下级法院判决，其中 1 份明确认定原处罚"畸重"） | 100%（68%–100%） |

"参与赌博"命中的 8 份判决，每份都复述了原处罚决定：拘留天数、罚款金额、收缴赌资金额、所依据的条款，以及法院结论。例如"行政拘留10日并罚款3000元，收缴赌资7704元""该处罚畸重……依法应予撤销"。这正是数据交付规格要的 `outcome` 与 `review.result`。

**结论**：全文"赌博"召回最全但噪声过半，**不能直接当金标来源**；到货后必须过滤，或者改用更精确的关键词组合（见 §1 Q1）。

地域高度集中（浙江一省占四分之一到三分之一），所以**必须按"省份 × 年份"分层抽样**，否则模型学到的基本是浙江的量刑习惯。

抽看 1 份 2025 年浙江赌博罪一审判决（1,472 字，26 段）：结构是"公诉机关指控 → 经审理查明 → 另查明（退缴违法所得） → 本院认为 → 判决如下"。"本院认为"部分写明了获利金额、自首、立功、认罪认罚、退赃和检察院量刑建议。**这些正是 CAIL 事实段缺失的量刑信息**，验证了 Q2 的价值。

## 0.2 卖家默认格式评估（样例文件"文书样例3.xlsx"，29 份民事、执行文书）

| 项 | 结果 |
|---|---|
| 列 | 案件名称、法院名称、案由、审判程序、案号、案件类型、发布日期、裁判日期、当事人、正文（共 10 列） |
| 正文 | **保留了分段换行**（判决书每份 20–79 段），完整到落款（审判人员、日期、书记员）；未发现乱码 |
| 三段可切分 | 15 份判决书都有"判决如下"，其中 9 份同时有"查明"和"本院认为"（民事判决写法较散，行政、刑事判决格式更固定） |
| 缺的字段 | **文书 ID 或原始链接**（去重、溯源必需，要求卖家补上）；法院层级、省市区县、文书类型、引用法条、关联文书均缺，但能从法院名称、案号代字、标题后缀和正文"依照……之规定""不服……号"推导，由我们处理 |
| 数据问题 | 同一案号的调解书出现 2 次，发布日期和正文都不同；案号格式不统一（有一条缺括号）；有一条标题写"二审"、案号却是"民初"；"当事人"列有一条切分错误；当事人列含真实姓名（入库时丢弃） |

**结论**：默认格式基本可用，最关键的"正文保留分段"已满足。只需补"文书 ID 或原始链接"；能提供网站的分段字段（事实、理由、判决结果）更好，但不是必需。

## 1. 检索条件（v0.2 按实验修订）

### Q1 行政诉讼：不服赌博类治安处罚（优先级最高）

| 条件 | 取值 |
|---|---|
| 案件类型 | 行政案件 |
| 文书类型 | 判决书、裁定书（通知书等不要） |
| 全文关键词 | **"赌博"**（全量约 3,970 份） |
| 裁判日期 | 2013-01-01 至最新 |
| 地域、审判程序 | 全国；一审、二审、再审、非诉审查都要（同一案件的多份文书由我们按案号合并） |

**为什么全量要"赌博"而不是更精确的组合**：总量只有约 4,000 份，买全量再本地过滤，召回最全，也不依赖卖家是否支持"或"检索。本地过滤规则：
1. 去掉"赌博"只出现在管辖条款"卖淫、嫖娼、赌博、毒品"里的文书；
2. 保留出现"参与赌博""为赌博提供条件""赌资""赌具""聚众赌博"之一，且有处罚结果（拘留、罚款、警告、不予处罚）的文书；
3. 其余人工抽查后决定。

**如果卖家按份计价、预算有限**，退而只买精确组合：全文含"参与赌博"或"为赌博提供条件"或"赌资"（三者合计不超过约 3,800 份，去重后更少），其中"参与赌博"抽查精度 8/8。

**为什么最重要**：每份判决都相当于一件"带复核意见的行政处罚案例"：
- 原处罚决定认定的事实与处罚结果，可直接作为金标；
- 法院的结论（维持、撤销、变更、确认违法）告诉我们原处罚是否合法；被撤销的不能当作正确答案。

### Q2 刑事：赌博类犯罪全文（第二优先，分层抽样）

| 条件 | 取值 |
|---|---|
| 案件类型 | 刑事案件 |
| 案件名称 | 含"赌博罪"或"开设赌场罪"（网站分别约 3.2 万、7.6 万份判决书） |
| 文书类型 | 判决书 |
| 审判程序 | 一审 |
| 裁判日期 | 2013-01-01 至最新 |
| **抽样** | 第一期每"省份 × 年份 × 罪名"最多 10 份，随机抽取（上限约 31 × 14 × 2 × 10 ≈ 8,700 份，实际更少）；不够再追加 |

**用途**：
- 刑事门槛附近的案件（例如抽头几千元、赌资几万元就被起诉的），用来刻画行政处罚与刑事追诉的分界；
- 完整判决里的量刑情节，用来重做锚点 A2；
- 后续的刑事扩展。

### Q3 刑事判决中的行政处罚前科（取消）

实验显示命中 2.3 万份且多为被告人前科记录，与本项目关系弱，v0.2 取消。

## 2. 每份文书需要的字段

| 字段 | 必需 | 为什么 |
|---|---|---|
| 文书唯一标识 | ✅ **卖家明确无法提供文书 ID 或原始链接**，改用替代主键：案号 + 文书类型 + 裁判日期 + 正文 SHA-1 | 去重、溯源（数据卡要记录）；样例中已出现同一案号对应两份不同正文，所以主键必须带正文哈希。真实性核对改为用案号在裁判文书网检索后比对正文 |
| 案号、标题 | ✅ | 合并同一案件的一审、二审文书 |
| 法院名称 | ✅ | 法院层级、省市区县由我们从法院名称和案号代字推导 |
| 案件类型、案由、审判程序 | ✅ | 筛选与分层 |
| 裁判日期、发布日期 | ✅ | 判断适用新法还是旧法 |
| **完整正文，保留分段和换行** | ✅ **最关键**（默认格式已满足） | 要能切出"原告诉称 / 被告辩称 / 经审理查明 / 本院认为 / 判决如下"各段。**只给摘要或去掉换行的全文没有用**（CAIL 的教训） |
| 网站的分段字段（事实、理由、判决结果） | 可选 | 有则可以直接用，减少切分误差 |
| 当事人姓名、身份证号、住址等 | ❌ **不需要** | 默认格式的"当事人"列含真实姓名，入库时丢弃；正文中的个人信息由数据链路脱敏 |

**格式**：卖家默认的 xlsx（每份一行，正文一个单元格）可以接受；JSONL 或 CSV（UTF-8）更好。附各检索条件的命中数统计。

## 3. 先买样例，验收通过再批量

每个检索条件先要 **20 份样例**，逐项检查：

| 检查项 | 合格标准 |
|---|---|
| 正文完整 | 20 份中至少 18 份能切出"查明""本院认为""判决如下"三段 |
| 编码 | 没有"?"、"�"之类的乱码（CAIL 原文里就有） |
| 字段 | §2 的必需字段齐全（文书 ID 用替代主键） |
| 真实性 | 随机抽 3 份，用案号在裁判文书网检索，核对正文一致 |
| 数量 | 卖家报的命中数与 §0.1 的官方基准相差不超过 5%（Q1 约 3,970 份；年份分布见 §0.1 表格） |
| 重复 | 替代主键不重复 |

**交易流程（卖家的要求）**：先下单 → 卖家统计数据量并发样例 → 我们验收 → 合格再确认收货。闲鱼在确认收货前由平台托管货款，所以风险可控，但要做到：
1. 下单前问清这一单的价格和内容（只含统计和样例，还是含全量），以及样例不合格能否退款；
2. 只在闲鱼内付款，不私下转账；
3. **验收通过前不确认收货**，留意自动确认收货的倒计时，来不及就申请延长；
4. 下单前请指导老师确认（§5）。

## 4. 到货后怎么用

```
到货文件 → 外置数据目录 inbox/wenshu/ → 数据链路导入台账（channel=C，来源注明"第三方数据服务，原始来源中国裁判文书网"）
        → 脱敏 → 按段切分 → 按数据交付规格 §1 产出：
           Q1：原处罚决定的事实（text_facts）、原处罚结果（outcome）、法院结论（review.result）
           Q2：查明事实（text_facts）、本院认为中的情节（作为情节要素）、判决结果（标签）
```

切分时注意三点（来自实验中看到的文书结构）：
1. 行政判决中"被告作出的处罚决定认定……"或"一审判决查明……"一段才是原处罚的事实与结果；法院"本院认为"是对它的审查。两者要分开：前者是题目和答案，后者是"答案对不对"的复核。
2. 二审判决的原处罚事实通常在"一审判决查明"或"一审认定"段，而不是"经审理查明"段（后者常常只有一句"一审查明的事实属实"）。
3. 同一次查处常有多名当事人分别起诉，判决内容几乎相同（如 2018–2019 年冷水江、温江的成批案件）。**按"处罚机关 + 违法行为日期"分组**，同组只能整体进训练集或测试集，防止泄漏。

## 5. 合规注意

- 裁判文书是依法公开的司法文书，但**第三方批量转售的数据来源是否合规无法由我们核实**。下单前请指导老师确认是否可以用于本项目；只作项目研究使用，不再分发，不用于任何营利目的。
- 文书中仍含个人信息。按《个人信息保护法》，处理已合法公开的个人信息应限于合理范围：入库前脱敏，只保留研究需要的字段（§2 已排除姓名、证件号、住址）。
- 数据卡如实记录来源（第三方数据服务）、下单日期、检索条件、数量；结题材料只引用案号，不附原文。
- 同样的检索如果在学院订阅的北大法宝中可以完成，优先走法宝（官方授权渠道）；第三方数据作为补充。
- 裁判文书网本身只用于人工规模的检索估量和抽查（§0.1），不做脚本批量下载。
