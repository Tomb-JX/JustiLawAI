## 0. 效力与修改规则

1. **预注册**：本文件中的方法选型、基线定义、测试集定义、指标公式和阈值，评审通过即冻结，作为验收的唯一依据。
2. **只能收紧，不能悄悄放宽**。放宽任何阈值或更换任何方法，必须同时满足：
   - 有证据说明原要求不可达（例如人类专家水平低于阈值、数据量不足、公开锚点无法复现），并附实验记录；
   - 在[偏离日志](./deviation-log.md)登记（改了什么、为什么、证据、影响）；
   - 周会评审通过，并经指导老师确认；
   - 原阈值保留在本文件中（划线），新阈值写在旁边，不得直接覆盖。
3. **阶段不可跳过**：门禁未通过时，依赖它的后续工作可以探索，但不得合入 `main`，也不得作为下一阶段的输入。每个门禁允许 1 周补救期，补救后仍未通过，由周会决定缩小范围或修改方案，并登记偏离日志。
4. **数字出处**：标 ✅ 的对照数字均由本组成员直接从原文表格读取（读取记录见[文献与资料库](./reference-library.md)）；标 ⚠️ 的是厂商自报或二手数字，只作参考，不作门禁依据。

## 1. 三层对照体系

| 层 | 回答的问题 | 怎么做 |
|---|---|---|
| **L1 公开锚点** | 我们的实现是否达到业界水平？ | 在别人的公开数据集上、按别人的协议，用别人发表的数字作对照（§4） |
| **L2 冻结基线** | 我们的方法在我们的数据上是否真的有增益？ | 一组固定配置的基线方法，在基线冻结日跑一次后锁定，此后不得改动（§5） |
| **L3 绝对门槛 + 人类专家** | 是否达到可用水平？是否接近专家？ | 预注册的绝对阈值，加上法律组专家在同一测试集上的预测水平（§5.3） |

**一个组件要通过，三层要求必须同时满足。**

## 3. 指标定义（统一实现于 `research/eval/metrics.py`，P0 完成并经单元测试）

### 3.1 抽取（M1）

| 指标 | 定义 |
|---|---|
| 字段准确率 | 规范化后预测值与金标完全相等的比例。数值字段：数值相等；区间表述（"三千余元"）：与金标区间重叠，且端点相对误差 ≤ 5% |
| 关键字段集 K | 行为类型、角色、赌博方式、个人赌资、现场赌资、抽头渔利额、参赌人数、营利目的、一年内受过治安处罚、年龄段（共 10 个，P0 可调整，冻结后不得删减） |
| 全字段 micro-F1 | 非空值视为预测；"未提及"视为负类 |
| 证据命中率 | 非空预测值中，其证据引文（空白规范化后）能在原文中逐字找到，或字符级相似度 ≥ 0.9 的比例 |
| 无依据值率 | 金标为"未提及"而模型给出非空值、且无证据命中的比例（即事实幻觉率） |
| 错误检测 AUROC | 以模型置信度区分"抽对 / 抽错"的 AUROC |

### 3.2 定性、档次与裁量（M2–M4）

| 指标 | 定义 |
|---|---|
| Ω 召回率 | 金标处罚落在由金标要素计算出的合法空间 Ω 内的比例 |
| 不合法输出数 | 输出的处罚或预测集落在 Ω 之外的次数 |
| 定性 Macro-F1 | 四类（不构成 / 参与赌博 / 提供条件 / 涉嫌犯罪需移送）的宏平均 F1；"不构成 / 不予处罚"类另单独报告 F1 |
| 移送召回率 / 精确率 | 针对"涉嫌犯罪需移送"类 |
| 拘留天数 MAE、Acc@±2 | 点预测（分布的中位数）与实际天数的平均绝对误差；误差 ≤ 2 天的比例 |
| **CAIL 对数分** | 采用 CAIL2018 官方刑期评分 ✅：d = \|log(t+1) − log(t̂+1)\|；d ≤ 0.2 得 1.0，≤ 0.4 得 0.8，≤ 0.6 得 0.6，≤ 0.8 得 0.4，≤ 1.0 得 0.2，否则 0；取平均 × 100。拘留按天、罚款按元分别计算 |
| RPS | 有序分布的排序概率评分（越低越好），衡量整个分布的质量，作为 M4 的主分布指标 |
| 罚款 ±20% 命中率 | 点预测与实际罚款相对误差 ≤ 20% 的比例 |
| 区间覆盖率 | 实际结果落在预测集内的比例；分组覆盖率按地域 × 档次计算 |
| 平均集合大小 | 预测集包含的天数（拘留）或数额跨度（罚款） |
| ECE | 15 个等宽分箱的期望校准误差（Guo et al. 2017） |
| 刑事区间准确率 | 公开锚点 A2 专用：按 PLJP/MSR² 协议的 10 个刑期区间计算 Acc 与 Macro-F1 |

### 3.3 检索、说理与鲁棒性（M5、M6）

| 指标 | 定义 |
|---|---|
| MAP、P@3、NDCG@3/5/10 | 与 KELLER 论文协议一致；用 `pytrec_eval` 实现 |
| 法条原文精确率 | 说理中引用的条文与规范库原文逐字一致，且在行为时有效的比例 |
| 数字一致率 | 说理中出现的数字与结构化结果一致的比例 |
| 事实支持率 | 说理拆成原子陈述后（FActScore 方法），能由 M1 证据引文支持的比例；幻觉率 = 1 − 支持率 |
| 单调性违例数 | 方向性测试中，加重情节（赌资 × 1.5 / 2 / 5、增加抽头、增加前科）后，期望拘留天数或"情节严重"概率下降的次数 |
| 不变性偏移 | 改动姓名、性别、民族、籍贯、与法律无关的职业后，输出分布的总变差距离（TVD） |
| 变形一致率 | 同义改写案情后（改写结果经人工确认语义不变），关键字段与最终档次保持一致的比例 |
| 可复现率 | 同一输入重复 20 次，结构化输出完全一致的比例 |

## 4. L1 公开锚点

### A1 抽取机制：LawBench（P2 必达）

使用与 M1 相同的抽取机制，只换成该任务的 schema。约束：**不得用 LawBench 测试数据调参**，提示与 schema 在第一次运行测试之前冻结；使用 LawBench 官方评测脚本。

| 任务 | 指标 | GPT-4 公开分数 ✅（零样本 / 单样本） | 门槛 |
|---|---|---|---|
| 2-6 命名实体识别 | soft-F1 | 76.60 / 79.96 | **≥ 80.0** |
| 2-9 事件检测（LEVEN） | F1 | 78.82 / 76.55 | **≥ 79.0** |
| 3-7 犯罪金额计算 | Acc | 77.60 / 77.00 | **≥ 85.0**（金额由代码计算，必须明显优于纯 LLM 计算） |

同时报告 B0（qwen3.5:9b 直接作答）在三个任务上的分数，作为增益参照。

### A2 裁量机制：CAIL2018 赌博子集（P3 必达）

- **数据与协议**：按 PLJP/MSR² 协议处理 CAIL2018（使用 exercise 与 final 子集，去掉死刑、无期和零刑期，去掉多罪名、多法条案件），取赌博罪与开设赌场罪的单罪名案件；10 个刑期区间沿用 PLJP 仓库 `data/output/meta` 中的定义。
- **公开数字 ✅**（MSR² 表 2，CAIL2018 全罪名测试集）：

| 方法 | Acc | Ma-F |
|---|---|---|
| MSR²（Qwen3-8B + GRPO） | 46.18 | 28.84 |
| TF-IDF + SVM | 42.05 | 26.66 |
| Qwen3-8B 微调 | 41.84 | 22.31 |
| Qwen3-235B-A22B 直接推理 | 38.05 | 26.82 |
| PLJP（GPT-4o-mini） | 27.53 | 18.03 |
| Qwen3-8B 直接推理 | 11.38 | 8.72 |

- **在赌博子集上复现的基线**：TF-IDF + SVM、中文 RoBERTa 微调、B0 直接推理、B0 + RAG。
- **为什么不直接在测试集上判显著**：A2 测试集只有约 414 件。实测两系统配对差值的 95% 置信区间半宽约 3.9 个百分点（[学习笔记 §7](./notes/A2-baselines.md)），3 个百分点的差别在这个样本量下无法检验，约需 1,300 件。
- **判定分两步**：
  1. **开发期比较（主要证据）**：在训练 + 验证部分（约 3,719 件，不含封存测试集）上做 **5 × 5 折重复分层交叉验证**（按事实去重后的 id 分组，5 个固定种子）。我们的系统与每个复现基线在相同的 25 个划分上逐折配对比较，用**修正的重复交叉验证 t 检验**（Nadeau & Bengio 2003）判显著，单侧 p < 0.05，多个基线做 Holm 校正。
  2. **封存测试集确认（只看一次）**：在训练 + 验证全部数据上重新训练，在测试集上评估；要求方向一致（不低于最强基线），且点估计不低于下方门槛减去测试集抽样误差（2 倍标准误）。
- **门槛**：**交叉验证平均 Acc ≥ max(46.2, 复现的最强基线 + 3.0)，且平均 Ma-F ≥ max(28.8, 复现的最强基线 + 3.0)**，相对每个基线的提升都显著；测试集确认通过。同时报告 CAIL 对数分（CAIL2018 竞赛刑期最高分为 77.70 ✅，仅作参考）。
- 说明：46.18 / 28.84 是 MSR² 在全罪名测试集上的数字，与赌博子集不是同一测试集，只作为下限参照。

### A3 检索机制：LeCaRDv2（P4 必达）

- **协议**：与 KELLER 论文一致（标签 ≥ 2 视为相关，160 个测试查询，MAP / P@3 / NDCG@3/5/10）。测试的是通用检索栈（召回 + 融合 + 重排），**不含**赌博专用的要素对齐。
- **公开数字 ✅**（KELLER 表 1，微调设定）：

| 方法 | MAP | NDCG@10 |
|---|---|---|
| KELLER | 68.29 | 87.61 |
| PromptCase | 62.25 | 81.26 |
| SAILER | 60.62 | 81.41 |
| BGE | 60.64 | 80.90 |
| BM25 | 55.20 | 79.85 |

- **门槛**：**MAP ≥ 62.3 且 NDCG@10 ≥ 82.0**（超过 KELLER 之外的所有方法）；挑战目标为达到 KELLER。

### A4 说理可靠性：外部参照（P4）

不复现，只作对照：斯坦福对商用法律 RAG 工具的评估中，幻觉率为 17%–33% ✅。我们的门槛是**说理幻觉率 ≤ 2%**（G4.5）。

### 5.2 冻结程序

## 6. 统计判定规则

| 判定 | 规则 |
|---|---|
| "显著优于 X" | 按事件分组的配对自助法（10,000 次重采样，Koehn 2004），差值的 95% 置信区间下限 > 0，**且**点估计差值 ≥ 规定增量；同时对比多个基线时用 Holm 校正 |
| "不劣于 X" | 差值的 95% 置信区间下限 > −δ（δ 在各门禁中给出） |
| 含随机性的训练组件 | 至少 3 个随机种子，报告均值 ± 标准差，门禁按均值判定 |
| 区间覆盖率 | 实测覆盖率 ĉ 满足 \|ĉ − 0.90\| ≤ max(0.02, 2√(0.09/n))（n 为样本数，即抽样误差的 2 倍标准差）；同时在开发池上做 20 次随机校准/测试划分，平均覆盖率须在 0.90 ± 0.01 内 |
| 分组结论 | 组内样本 n ≥ 50 才对该组下结论；不足 50 的组只报告、不判定 |
| 小测试集上的模型比较 | 若封存测试集上目标差值小于其配对 95% 置信区间半宽，显著性改由开发池上的 5 × 5 折重复交叉验证 + 修正 t 检验（Nadeau & Bengio 2003）判定，封存测试集只做方向与下限确认（同 A2）。修正 t 统计量：t = d̄ / √((1/k + n₂/n₁)·σ̂²)，k 为折数 × 重复次数，n₁、n₂ 为每折训练、验证样本数，自由度 k − 1 |

## 7. 测试集定义与治理

| 测试集 | 内容 | 规模下限 |
|---|---|---|
| D-dev | 开发迭代用，可随时查看 | — |
| **T-admin**（封存） | 行政案例，来源构成与总体一致；来自复议/诉讼的案例 ≤ 50% | 150 件 |
| **T-time**（封存） | 2026 年新法施行后的案例 | 50 件 |
| T-region | 留一省份外推（只有 ≥ 2 个省份时设立） | 每省 50 件 |
| **T-crim**（封存） | CAIL2018 赌博子集测试部分（A2） | 按协议 |
| T-behavior | CheckList 行为测试套件（单调、不变、变形） | 300 条 |

**封存规则**（依据 Dwork et al. 2015 关于重复使用测试集导致过拟合的结论）：

1. 封存测试集存放在仓库之外，由**测试集保管人**（建议由指导老师或组长担任）一人持有；每个文件的 SHA-256 记录在本节末尾。
2. 只能通过 `research/eval/run_gate.py` 评测；每次访问自动写入 `research/eval/access-log.csv`（时间、操作人、模型哈希、用途），该文件入库。
3. 查看预算：**每个门禁每个候选系统最多 2 次**（一次预检、一次正式）；整个项目对 T-admin 的访问**总计不超过 10 次**。预算用完需要采集新测试数据。
4. 封存测试集不得进入 CI，不得用于调参、选模型、选阈值、做错误分析。

**防泄漏检查**（依据 Kapoor & Narayanan 的 8 类泄漏分类）：

- 按事件分组划分（同一事件的多名违法行为人只能在同一份数据中）
- **测试集只用金标**：教师模型的银标只用于训练；被打过银标的案例若进入测试集，必须由人工重新标注，且该案例的银标不得出现在任何训练集中
- 训练与测试近重复检查：MinHash Jaccard ≥ 0.8 的配对数必须为 0
- T-time 中不得有决定日期早于训练集最晚案例的样本
- 所有预处理（TF-IDF 词表、标准化、校准器）只在训练集上拟合；共形校准集与训练集、测试集三者互不重叠
- 金标双人标注并仲裁，报告 κ
- **D-002 补充**：用模型仲裁标签构建的评测集，一律命名带 `-model` 后缀（如 `T-admin-model`），结论只算"开发性评测"。仲裁模型 C **不得**与教师模型 B1 同一提供方，A、B 中至多一个与 B1 同一提供方——否则学生模型学的是 B1 的银标，又在 B1 主导的标签上考试，学到的错误会被当成正确答案，分数虚高。人工参照出现后，再按原规则建立不带后缀的封存测试集
