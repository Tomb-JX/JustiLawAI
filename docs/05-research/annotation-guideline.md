## 1. 总原则

标注输入为冻结的依法公开文书原文；用记录中的 `subject_mention` 原写法定位本人。标注产物（L5 标签文件）只保存要素值、状态与必要的证据定位，不另设姓名、证件号或其他身份信息字段。原文证据引文可能含原文个人信息，仍按内部数据权限管理，对外发布须另行遮蔽与评审。

1. **只标事实，不标法律结论。** 例如标"上次受治安处罚的日期 2025-08"，不标"一年内受过处罚"；是否构成从重由规范层按适用的法律版本判断（2012 版是六个月，2025 版是一年）。
2. **每个有值的字段都必须附原文证据**：从案情中逐字复制一段连续文字，不改写、不拼接。一个值需要多处原文支持时，附多段证据。
3. **状态三选一**：
   - **明确**：原文直接写明；
   - **推断**：原文没有直接写明，但由上下文可以合理推出，仍须附据以推断的原文；
   - **未提及**：原文没有相关信息，值留空。**不确定时选"未提及"，不要猜。**
4. 一份案卷有多名违法行为人时，**每人一条标注**，只标该人自己的要素；涉及共同事实（如现场赌资、参赌人数）的字段，每人都标。

## 2. 数额

- 单位一律为**元**；"1.2 万"记 12000。数额记成区间 `{min, max}`。
- **上界为空（`max: null`）表示开口**：原文只给了下界。只在"以上、逾、超过、至少、不低于"这类写法时使用。**不要替它补上界**（不按数量级补成 9999、19999、99999）。下表各写法都按此记：

| 原文写法 | 记法 | 例 | 状态 |
|---|---|---|---|
| 确切数额 | min = max | "现场查获赌资 3910 元" → 3910–3910 | 明确 |
| X 以上 / 逾 X / 超过 X / 至少 X / 不低于 X | min = X，max 为空 | "赌资在万元以上" → 10000–空；"12500 元以上" → 12500–空 | 明确 |
| X 余元 / X 多元 | X 到"X 加上末位非零数位的一个单位，再减 1" | "三千余元" → 3000–3999；"一万二千余元" → 12000–12999；"1 万余元" → 10000–19999；"12500 余元" → 12500–12599 | 明确 |
| 约 X / X 左右 | X 的 90%–110% | "约 5 万元" → 45000–55000 | 明确 |
| 数 / 几 + 单位 | 2–9 个单位 | "数百元" → 200–999；"数千元" → 2000–9999；"数万元" → 20000–99999 | 明确 |
| 近 X / 将近 X | X 的 90% 到 X | "近万元" → 9000–10000 | 明确 |
| 不足 X / 不到 X / X 以下 | 0 到 X | "不足 1000 元" → 0–1000 | 明确 |
| 原文逐项列出多人或多笔数额，需要加总 | min = max = 合计 | "戊持有 350 元，丙 330 元，乙 600 元，丁 50 元" → 1330–1330 | 推断（证据附全部原句） |
| 列举后带"等" | min = 列出部分的合计，max 为空 | "甲持有 300 元、乙 200 元等" → 500–空 | 推断 |
| 金额被打码（"xx 元"） | 不记 | — | 未提及 |

- 原文给出"人均"而无个人数额时，个人赌资标"推断"，证据引用人均那句。
- 抽头渔利、头钱、"水钱"、台费都归入 `amounts.commission`。只有台费、场地费时也记在这里，但它**不能**作为"以营利为目的"的依据（见 §2.1）。
- **为什么不补上界**：规范层对金额做三值判断，即达到、未达到、可能达到。以"累计赌资 5 万元"这个涉刑提示门槛为例，"万元以上"记成 10000–空，结论是"可能达到"，这是如实的。如果补成 10000–19999，结论就成了"未达到"，这是原文没有说的确定性。数值特征由特征工程层另行处理（开口只取下界），不在标注时处理。

## 2.1 以营利为目的（`intent.profit_purpose`）

这个字段**只记原文认定和本人的获利事实，不由标注员做法律判断**。"以营利为目的"是治安管理处罚法第七十条（新法第八十二条）中"为赌博提供条件"的构成要件，也是刑法聚众赌博的要件，由规范层根据这个字段和其他要素去推。

| 情形 | 记法 |
|---|---|
| 原文对**本人**写明"以营利为目的""营利性赌博""并非娱乐消遣" | 是，明确 |
| 原文写明**本人**抽头、抽水、渔利、收头钱或水钱、坐庄获利 | 是，明确 |
| 本人是场所或条件的提供者、组织者，原文写了现场有抽头、头钱，但没说是谁收的 | 是，推断 |
| 原文写明"不以营利为目的""娱乐消遣"（指本人的行为） | 否，明确 |
| 以上都没有 | 未提及 |

**下列内容都不是依据**，单凭它们一律标"未提及"：
- 赌资多少、输赢多少、底注多大；赌博方式；被当场查获；
- 只收台费或场地费：最高法、最高检法释〔2005〕3号第九条规定，只收取正常场所和服务费用的经营行为不以赌博论处；
- 平台或场所名称里的"娱乐"二字；
- 所引法条原文，比如事实段里抄录的"第七十条规定，以营利为目的……"；
- "构成赌博""实施了赌博的违法行为"这类定性用语；
- **其他参赌人**的营利事实。按 §1 第 4 条，只标本人的要素。

例子：
- "甲以营利为目的，与乙、丙等人……以打麻将方式赌博" → 是，明确。
- "甲持有赌资 35000 元" → 未提及。
- 丁提供房间，"现场查获赌资 3910 元和头子钱 60 元"：对丁记"是，推断"；对参赌的甲记"未提及"。

## 3. 字段裁决规则（E-05，2026-10-18）

> 本节针对分歧率最高的七个字段（pilot50 数据），给出**唯一权威裁决规则**。
> JioNLP 等工具仅作实现选项，不得成为第二套权威规则。引擎侧规则通过协作记录交接，
> 后处理线照此实现，不编辑 `unify/**`。

### 3.1 `conduct.role`（pilot 分歧 91%）

枚举：组织者、提供条件者、抽头者、参赌者、望风者、放贷者、其他。

| 情形 | 记法 | 例 |
|---|---|---|
| 本人只是自己参赌 | 参赌者 | "甲与乙等人以打麻将方式赌博" → 参赌者 |
| 本人提供场所/赌具/资金 | 提供条件者 | "甲在其经营的棋牌室内为乙等人提供赌博条件" → 提供条件者 |
| 本人组织/召集他人赌博 | 组织者 | "甲召集乙、丙等人赌博" → 组织者 |
| 本人既是提供条件者又是参赌者 | 参赌者 | "甲在自家棋牌室与乙等人赌博" → 参赌者（提供条件是赌博的附带行为） |
| 本人既是组织者又是提供条件者 | 组织者 | "甲租用场地召集乙等人赌博" → 组织者（组织者优先于提供条件者） |
| 本人抽头/收头钱 | 抽头者 | "甲从每局赌资中抽取 10 元头钱" → 抽头者 |
| 本人同时是参赌者和抽头者 | 抽头者 | "甲参赌并从中抽取头钱" → 抽头者（抽头者优先于参赌者） |
| 以上都不确定 | 未提及 | — |

**多角色并存规则**：选最能代表本人在赌博活动中**主要获利方式**的角色。优先级：组织者 > 抽头者 > 提供条件者 > 参赌者。望风者和放贷者独立标注，不与其他角色合并。

### 3.2 `venue.venue_type`（pilot 分歧 91%）

枚举：住宅、经营场所、公共场所、交通工具、网络、境外、其他。

| 原文描述 | 记法 |
|---|---|
| "棋牌室""茶楼""宾馆""麻将馆" | 经营场所 |
| "甲家中""甲的出租屋""甲的住处" | 住宅 |
| "路边""广场""公园" | 公共场所 |
| "车上""船上" | 交通工具 |
| "网上赌博""通过微信赌博""赌博 APP" | 网络 |
| "境外赌场""澳门" | 境外 |
| 多场所时选赌博**实际发生**的主要场所 | — |

**多场所规则**：选赌博行为实际发生的场所，不选被抓获的场所。例如"甲在宾馆开房赌博，后在家中被抓获" → 经营场所。

### 3.3 `conduct.behavior_type`（pilot 分歧 85%）

枚举：参与赌博、为赌博提供条件、聚众赌博、开设赌场、以赌博为业、带彩娱乐、其他。

| 情形 | 记法 | 例 |
|---|---|---|
| 本人只是参赌 | 参与赌博 | "甲与乙等人赌博" → 参与赌博 |
| 本人提供场所/赌具 | 为赌博提供条件 | "甲提供麻将机供乙等人赌博" → 为赌博提供条件 |
| 本人组织多人赌博并从中获利 | 聚众赌博 | "甲召集 10 余人赌博并抽头" → 聚众赌博 |
| 本人开设赌场 | 开设赌场 | "甲开设赌场" → 开设赌场 |
| 少量财物输赢的亲友娱乐 | 带彩娱乐 | "甲与亲属打麻将，输赢数十元" → 带彩娱乐 |

**多行为规则**：同一人涉及多种行为时，选**最严重**的一项。严重性排序：开设赌场 > 聚众赌博 > 以赌博为业 > 为赌博提供条件 > 参与赌博 > 带彩娱乐。

### 3.4 `conduct.method`（pilot 分歧 70%）

枚举：麻将、扑克、骰子、赌博机、网络赌博、私彩、六合彩、赌球、其他。

| 原文写法 | 记法 |
|---|---|
| "打麻将""麻将" | 麻将 |
| "打牌""扑克""斗地主""炸金花""德州扑克" | 扑克 |
| "掷骰子""骰宝" | 骰子 |
| "赌博机""老虎机""捕鱼机" | 赌博机 |
| "网上赌博""赌博 APP""微信赌博" | 网络赌博 |
| "私彩""地下六合彩" | 私彩 |
| "六合彩" | 六合彩 |
| "赌球""竞猜" | 赌球 |

**多方式规则**：同一次查处涉及多种赌博方式时，选该次查处中**本人实际参与**的方式。"打牌"默认记为扑克。

### 3.5 `conduct.times`（pilot 分歧 68%）

类型：整数（场次）。

| 原文写法 | 记法 | 状态 |
|---|---|---|
| "两次""3 次""多场"中的明确数字 | 直接记为该数字 | 明确 |
| "多次""数次""经常" | **值记 null** | 推断 |
| "一场""本次" | 1 | 明确 |
| 未提及赌博次数 | 未提及 | 未提及 |

**"多次"不猜**：原文只写"多次"而无法确定确切次数时，值必须为 null、状态为推断。这是因为"多次"在法律上有特定含义（2012 版"多次参与赌博"可加重），标注员不应自行定义"多次"的数值范围。

### 3.6 `persons.participant_count`（pilot 分歧 51%）

类型：整数。

| 原文写法 | 记法 | 说明 |
|---|---|---|
| "甲与乙、丙等人赌博" | 3 | 甲（本人）+ 乙 + 丙 = 3 人 |
| "甲等 5 人赌博" | 5 | 含本人 |
| "多人""数人" | **值记 null** | 推断 |
| "甲与乙两人" | 2 | 甲（本人）+ 乙 = 2 人 |

**含本人**：本人是参赌者时，人数包含本人。围观者、未参赌的望风者不计入。"甲与乙、丙等人"中"等人"表示至少还有其他人，但确切人数未知时只能按已知人数记（3 人），状态为推断。

### 3.7 `person.age`（pilot 分歧 30%）

类型：整数（周岁）。

| 原文写法 | 记法 | 状态 |
|---|---|---|
| "甲，1990 年 5 月出生" + 行为日期 2026-03-15 | 35 | 明确（按行为日算周岁） |
| "甲，1990 年出生" + 行为日期 2026-03-15 | 35 或 36 | 推断（按 7 月 1 日估算） |
| "甲，三十余岁" | **值记 null** | 推断 |
| "甲，成年" | **值记 null** | 推断 |
| 未提及年龄 | 未提及 | 未提及 |

**年龄计算**：按**行为时**的周岁，不按决定时。只有出生年份时，按该年 7 月 1 日估算（取整数周岁）。模糊表述（"三十余岁""中年"）无法确定确切年龄，值记 null、状态推断。

### 3.8 日期归一化（引擎侧唯一规则）

引擎侧的日期归一化规则是权威规则，后处理线照此实现：

1. **存储格式**：所有日期统一为 ISO 格式 `YYYY-MM-DD`。
2. **只写到月份**：取该月 1 日，状态标"推断"。例如"2025 年 8 月" → `2025-08-01`，推断。
3. **只写到年份**：取该年 7 月 1 日，状态标"推断"。例如"2025 年" → `2025-07-01`，推断。
4. **持续时间**：原文写"持续三个月" → `duration_days` 记 90 天（按 30 天/月）。原文写"持续一年" → 365 天。
5. **日期合法性**：2 月 30 日等非法日期不记，标"未提及"。
6. **JioNLP 仅作实现选项**：JioNLP 的日期解析可作为工具调用，但其输出必须经上述规则校验后才能入库。JioNLP 不是第二套权威。

### 3.9 金额归一化（引擎侧唯一规则）

引擎侧的金额归一化规则是权威规则，后处理线照此实现：

1. **存储单位**：元（CNY）。
2. **中文大写数字**：先转为阿拉伯数字再记。例如"叁仟元" → 3000。
3. **万/亿单位**："1.2 万" → 12000；"3.5 亿" → 350000000。
4. **区间写法**：按 §2 的对照表记。"X 余元" → `[X, X + 末位非零数位的一个单位 - 1]`。
5. **开口写法**：`max = null`，不补上界。
6. **打码金额**：原文"xx 元"不记，标"未提及"。
7. **JioNLP 仅作实现选项**：JioNLP 的金额解析可作为工具调用，但其输出必须经上述规则校验后才能入库。JioNLP 不是第二套权威。

### 3.10 证据语义

证据是标注的基础。引擎侧的证据语义规则是权威规则：

1. **逐字连续**：证据必须是原文中的**连续片段**，逐字摘录，不得改写、拼接或省略。
2. **来源限制**：证据只能来自 `facts_text`（事实句）和 `meta_text`（当事人/身份句），不能来自 `reasoning_text`（说理）、`decision_text`（决定）或所引法条。
3. **多段证据**：一个值需要多处原文支持时，附多段证据。例如"甲持有赌资 350 元"和"现场查获赌资 3910 元"是两个不同的金额，分别对应不同字段。
4. **坐标定位（S2）**：`located=True` 时，每段证据须附 `start` 和 `end`，满足 `text_full[start:end] == quote`。坐标按 Python/JSON 字符串从 0 起、左闭右开。
5. **推断时的证据**：状态为"推断"时，证据是据以推断的原文，不是直接描述该值的原文。例如推断年龄时，证据是出生年份那句话。
6. **未提及时无证据**：状态为"未提及"时，`evidence` 必须为空数组 `[]`。

### 3.11 字段绑定语义

多人案卷中，每个要素字段的值天然属于两类之一：

- **场景级（shared_fact）**：该字段的值对在场所有人相同。如"现场查获赌资 3910 元"——甲、乙、丙看到的是同一笔钱。
- **个人级（target_specific）**：该字段的值因人而异。如"甲持有赌资 350 元"——只有甲的个人赌资是 350。

字段绑定语义表（`research/eval/binding_rules.py`）是引擎侧唯一权威定义。标注时不需要关心绑定类型——绑定是 pipeline 在抽取后处理时用的，不是标注时用的。

**怎么从文本判定一段证据是 shared 还是 target，是后处理线的实现职责**，不是标注员的职责。标注员按 §1 的总原则标注即可：只标目标本人的要素，每个有值的字段都附原文证据。

## 4. 日期与人员

- 日期只写到月份时取该月 1 日，状态标"推断"。
- 年龄按**行为时**的周岁；只有出生年份时按 7 月 1 日估算并标"推断"。
- "情节轻微 / 情节特别轻微"只在原文（如处罚决定书、复议决定书）明确写出时才标，不要自行判断。

## 6. 质量控制（门禁 G0.3 / G1.2）

- 试标：~~50 件双人独立标注~~ 50 件由两个不同提供方的高质量远程旗舰模型背对背标注（偏离日志 D-001 及其 2026-10-17 执行口径更正；本机 qwen3.5:9b 只是历史方案；确切模型 ID 与响应版本运行前确定、逐次留痕），两者都只看到本指南、`text_party` 与 `text_facts`（加 `text_party` 前用正文中事实段之前的部分代替），不看对方结果。分类字段 Cohen's κ ≥ 0.80，数值字段完全一致率 ≥ 95%，都只在至少一方非"未提及"的字段上计算；分歧逐项归类为"指南歧义 / 模型读错 / 证据缺失"，"指南歧义"一律补进本指南。不达标就修订本指南后重试，最多 2 轮。
- 数值一致的判定：`min` 和 `max` 都相同才算一致；两边都为空的上界算相同，一边空一边有值算不一致。
- 一致性一律用 `research/eval/agreement.py` 计算（门禁 G0.3 计算细则），判定只看 union 口径。
- **模型仲裁标注集（偏离日志 D-002）**：没有人工人力时，由不同提供方的模型 A、B 双盲标注，第三模型 C 盲判后逐字段仲裁，产物标 `model-adjudicated`、`human_review=false`，与人工金标分开计数。它不满足下一条的人工要求。仲裁模型 C 不得与教师模型 B1 同一提供方。
- 正式标注：至少 20% 双人标注；分歧由第三人仲裁，并把仲裁结论补进本指南。
- 指南每次修订都要在变更日志中记录；`schema.py` 改字段时同步提升版本号，并在[协作记录](../04-plan/collab-log.md)中通知数据链路。
