# 行政案例数据交付规格（数据链路 → 引擎）

> 版本 v0.1 · 2026-10-15 · 细化[分工文档](../04-plan/workstreams.md) §5"案例数据交付"
> 配套：[数据收集计划](../04-plan/data-collection.md) · [标注指南](./annotation-guideline.md) · [固定对照与阶段门禁](./sota-baselines-and-gates.md)

## 0. 为什么要这份规格：CAIL 探针的教训

在 CAIL2018 赌博子集上，M1 抽取 + 统计模型只比"永远猜最多的类"高约 1 个百分点。原因不在模型，而在数据本身：

| 统计（1,613 件） | 比例 |
|---|---|
| 事实是"检察院指控……××罪"式的公诉书摘要 | 57% |
| 一个金额都没有（赌资、抽头、获利都没写） | 26% |
| 自首、坦白、认罚、退赃一项都没写 | 69% |
| 金额和情节都没有 | 19% |

这 19% "信息空白"的案件，实际刑期从 1 个月到 27 个月都有。**输入一样、答案却不同，任何模型都学不会。**

所以行政案例采集的第一原则是：**决定处罚结果的信息必须在文本里，而且要分清哪部分是"事实"、哪部分是"结论"**。

## 1. 每件案例必须提供的信息

### 1.1 来源（缺一项就不能入库）

| 字段 | 说明 |
|---|---|
| `id` | 台账 manifest 中的 id |
| `source_type` | 处罚决定书 / 行政复议决定书 / 行政判决书 / 执法公示 / 合作案卷 |
| `source_ref` | URL 或文号 |
| `harvest_date` | 采集日期 |
| `deidentified` | 是否已按脱敏 SOP 处理（必须为是） |

### 1.2 时间与地点（决定适用哪部法律、哪个省的裁量基准）

| 字段 | 说明 | 为什么必须有 |
|---|---|---|
| `behavior_date` | 违法行为日期（至少到月） | 2026-01-01 前后分别适用旧法第七十条、新法第八十二条 |
| `decision_date` | 处罚决定日期 | 从旧兼从轻需要同时知道两个日期 |
| `authority` | 作出决定的机关，如"××县公安局" | 定位到省、市 |
| `region` | 行政区划代码，至少到省 | 选省级裁量基准 |

### 1.3 原文分段（最重要，防止"答案混进题目"）

文书要按内容切成下面几段分别存放，**不要合在一起**：

| 段落 | 内容 | 引擎怎么用 |
|---|---|---|
| `text_facts` | 查明的违法事实（"经查""查明"部分） | 模型输入：M1 从这里抽取要素 |
| `text_evidence` | 证据列举 | 辅助核对，不作为模型输入 |
| `text_reasoning` | 认定理由、情节认定、裁量说明（"本局认为""经审查"部分） | **不作为模型输入**（里面常写着"情节严重""从轻处罚"，等于答案的一部分）；用于标注情节和训练 M6 说理 |
| `text_decision` | 处罚决定原文（"决定给予……"） | 提取处罚结果标签 |
| `text_review` | 复议、诉讼机关的审查意见与结论（如有） | 判断原处罚是否被认可 |

切不准时，原文整篇保留在 `text_full`，同时标 `segmented: false`，引擎会单独处理。

### 1.4 处罚结果（标签，必须结构化）

| 字段 | 取值 |
|---|---|
| `outcome.type` | 不予处罚 / 不构成违法 / 警告 / 罚款 / 拘留 / 拘留并处罚款 / 移送刑事 |
| `outcome.detention_days` | 整数，没有填 0 |
| `outcome.fine` | 元，没有填 0 |
| `outcome.detention_not_executed` | 是 / 否（依法不执行拘留） |
| `outcome.confiscation` | 收缴的赌资、赌具描述 |
| `outcome.articles` | 引用的法条原文编号，如"治安管理处罚法第七十条""第八十二条""第二十条第五项" |
| `outcome.stated_circumstances` | 决定书中**明写**的情节认定：情节严重 / 从轻 / 减轻 / 从重 / 不予处罚（原文怎么写就怎么记） |
| `review.result` | 维持 / 变更 / 撤销 / 确认违法 / 无（复议或诉讼的结论） |
| `review.changed_outcome` | 被变更后的处罚（如有） |

**被撤销或变更的原处罚不能直接当作正确答案**，引擎会单独处理。所以 `review.result` 必须记录。

### 1.5 事实要素（按[标注指南](./annotation-guideline.md)标注；P1 阶段由教师模型预标、人工校正）

至少要能从 `text_facts` 中判断以下内容，文中没写的就记"未提及"，不要猜：

| 类别 | 要素 |
|---|---|
| 行为 | 参与赌博 / 为赌博提供条件；赌博方式；次数、持续时间 |
| 数额 | 个人赌资、每局输赢、现场查获赌资、抽头或台费、违法所得 |
| 人员 | 参赌人数、是否有未成年人参与、亲属之间与否 |
| 主观 | 是否以营利为目的（有无抽头、收费） |
| 本人 | 年龄、近期是否受过治安处罚（**要有日期**）、是否初次违法、孕期或哺乳 |
| 情节 | 主动投案、如实陈述、认错认罚、主动消除后果、立功、受胁迫诱骗、阻碍执法 |

## 2. 数据集整体要求

| 要求 | 数量 / 比例 | 依据 |
|---|---|---|
| 行政案例金标总量 | ≥ 500 件，目标省份 ≥ 300 件 | 门禁 G1.1 |
| 2026 年新法施行后的行为 | ≥ 50 件 | 门禁 G1.1（T-time） |
| 不予处罚、不构成违法的案例 | **必须收**，不能只收被处罚的 | 门禁 G3.2 要求这一类单独达标 |
| 一般档、情节严重档 | 两档都要有，每档至少 100 件 | 档次要能学 |
| 复议、诉讼来源占比 | 测试集中 ≤ 50% | 门禁 §7；这类案件偏争议、偏重罚 |
| 新旧法两个时期 | 都要有 | 时间效力与迁移 |
| **信息完整度** | 至少一项金额 + 处罚结果齐全的案例 ≥ 80% | CAIL 教训：信息空白的案例占比高时，模型学不到东西 |

## 3. 交付格式

- 每件一行 JSONL（注意每行末尾要换行），字段如 §1。
- 同目录附 `SHA256SUMS`。
- 文件名带标注版本号，如 `admin_cases.schema-1.0.0.jsonl`。
- 放在外置数据目录 `$JUSTILAW_DATA_DIR/admin/`。
- 每批交付在[协作记录](../04-plan/collab-log.md)留一行：件数、来源构成、信息完整度。

## 4. 引擎侧的验收检查（自动执行）

引擎读取每批数据时自动检查以下各项，不合格的批次退回：
- 必填字段齐全；
- 日期能解析；
- 处罚结果在该法律版本的合法范围内；
- `text_facts` 中不含"决定给予""情节严重"等结论性词句；
- 信息完整度达标。
