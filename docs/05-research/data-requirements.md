# 引擎侧需求 → 数据交付：对齐清单

> 版本 v0.1 · 2026-10-16 · 模型组
> 配套：[数据交付规格](./data-spec.md)（契约）· [数据链路全景](./data-flow.md)（as-built）· [固定对照与阶段门禁](./sota-baselines-and-gates.md)
> 工具：`research/eval/key_field_presence.py`（把任意交付 JSONL 丢进去，量出关键字段出现率）
> **原则：数据格式服从引擎约束，不是反过来。** 本文用引擎的真实依赖（M1–M6 的输入输出 + 门禁数值 + 红线）反推"最终要交什么"，再逐项标注当前对齐到什么程度。

## 0. 一句话（口语版）

引擎要的**不是**"一份有事实段的文书"，而是**五件事同时成立**：

1. **输入侧**——文本里**真的写着**模型要抽的那些要素（不然模型学不会没写的东西）；
2. **标签侧**——处罚结果要齐（拘留天数、罚款额、法条版本、情节认定），这是模型要学的答案；
3. **元数据侧**——行为日期、决定日期、地区、机关，这些是 M2 的**硬规则**（选哪部法、哪个省的裁量基准）用的；
4. **证据侧**——每条结论都能回到原文定位（M6 的三类校验、红线 R2/R3）；
5. **治理侧**——脱敏、台账 id、事件分组、测试集构成（合规与防泄漏）。

**当前实测：②③④ 基本达标，⑤ 未做，① 是硬缺口**——10 个关键字段里有 6 个在现在的数据里出现率不到 20%。

## 1. 逐层对齐（引擎依据 → 要什么 → 当前实测 → 差距）

### A 输入侧（M1 抽取、M3 定性辨析要"吃"的）

| 引擎依据 | 需要什么 | 当前实测（99 件 L1） | 差距 |
|---|---|---|---|
| 门禁 G2.1「关键字段准确率 ≥0.95」+ M4 的特征就是要素 | 10 个关键字段在 `text_facts` 里的正例 | 赌博方式 **96%**、现场赌资 **52%**、参赌人数 **30%**、行为类型 **28%**、角色 **9%**、营利目的 **2%**、个人赌资 **1%**、抽头渔利 **0%**、前科日期 **0%**、年龄 **0%** | **6/10 字段 <20% → 基本学不到**（模型只能学会输出"未提及"） |
| M2 的衍生量规则（人均赌资 = 现场赌资 ÷ 人数） | 现场赌资 + 人数同时出现 | **11%** | 人均赌资几乎算不出来 |
| M3 只做"没有结果标签、必须读原文"的定性辨析 | 营利目的、提供条件 vs 开设赌场的线索 | 营利目的 2% | M3 缺输入素材 |
| 规格 §2「信息完整度 ≥80%」 | 至少一项金额 + 结果齐全 | 法宝 A 口径 **98%** ✓；公开网页 **25%** ✗ | 按来源分层达标，混合时要加权 |

**为什么这条最要紧（口语）**：模型是从文本里"读"要素，不是从数据库里查要素。文书里没写"抽头"，模型永远学不会"抽头→从重"这条规律；标签再全也没用——**题干里没有信息，答案再准也学不到解题过程**。这正是 CAIL 探针的教训（19% 案件无金额无情节，模型学不动），现在以更细的粒度暴露出来了。

### B 标签侧（M4 要学的答案）

| 引擎依据 | 需要什么 | 当前实测 | 差距 |
|---|---|---|---|
| G3.5/G3.6：拘留天数 MAE、罚款 ±20% | `outcome.detention_days` / `fine` | **99/99 ✓** | — |

| G3.4 档次学习、G3.2 不予处罚单独达标 | 明写的情节认定（从轻/从重/认错认罚） | 待量（`stated_circumstances` 字段已在位） | 样本少 |
| 门禁 §7：被撤销/变更的原处罚不能当正确答案 | `review.result` + `changed_outcome` | 执法公示记"无"；判决书已能出"维持/撤销/变更" | 复议来源仍缺 |

### C 元数据侧（M2 的硬约束 / 防泄漏）

## 2. 硬缺口的两条对策（按可操作性排序）

### 对策一：**换检索词，而不是换模型**（最关键）

要素出现率低，很可能**不是数据不存在，而是我们检索的词选错了**。引擎要什么，就用什么词去搜：

| 想拿到的要素 | 用这些词检索正文 | 为什么 |
|---|---|---|
| 抽头渔利 / 营利目的 | `抽头`、`渔利`、`台费`、`抽成` | 词出现即含该要素（当前 0–2%） |
| 个人赌资 | `携带赌资` | 决定书原句"携带赌资 X 元" |
| 年龄 / 前科日期 | `周岁`、`因赌博被行政拘留` | 写明个人情况的文书才有 |
| 参赌人数 | `参赌人员`、`余人`、`聚众` | 聚众型案件才会写人数 |
| 角色（提供条件/望风） | `提供条件`、`望风`、`召集` | 角色型案件的标题/事实会写 |

**验证方法**：下一批用 `抽头`（或 `营利`）下 50 篇 → 跑
`python research/eval/key_field_presence.py --jsonl <产物目录> --tier L1` → 看 `amounts.commission` / `intent.profit_purpose` 是否从 0–2% 升到 60%+。若升上去，说明"数据可得、词选错了"，正式口径改成**要素导向的多词轮换**；若仍低，再走对策二。

### 对策二：指标与字段集按证据调整（门禁 §0 的正规流程）

G2.1 要求"关键字段准确率 ≥0.95"，但在"未提及占 90%"的数据上，模型全答"未提及"就能达标——**指标虚高、能力为零**。两条必须做的动作：

1. **报告口径**：任何抽取评测必须**同时给**「非空字段准确率」与「未提及占比」（工具已经在输出末尾提醒）。这条建议提交周会，作为评测报告的强制项。
2. **字段集与门槛**：若要素导向扩样后仍有字段 <20%，按门禁 §0 走**偏离日志**（附本工具的输出作为证据），收窄首版关键字段集（例如先做 `method` / `onsite_stake_total` / `participant_count` 三个达标字段），其余字段标注"数据不足、暂不设门槛"。

## 3. 对齐实现（谁产出、现在什么状态）

| 层级 | 需要的内容 | 产出者 | 状态 |
|---|---|---|---|
| A 输入 | `text_facts` + 要素出现率 | 各解析器（`harvest/parse.py`、`collect/pkulaw_ingest.py`） | 解析 ✓；**出现率不达标**（对策一） |
| B 标签 | `outcome` / `review` | 同上 | ✓（执法公示 99/99、判决书可出复核结论） |
| C 元数据 | 日期 / region / event_key | 同上 + `import_manual.py` 分配 id | 日期与地区 ✓；id 待分配 |
| D 证据 | `text_full` + 可定位 | 同上 + 发现层 `deid.py` | 原文 ✓；**脱敏位置映射未入库** |
| E 治理 | 脱敏标记 / 测试集划分 | 发现层 + 引擎 | **未做** |
| 度量 | 关键字段出现率 | `research/eval/key_field_presence.py`（本次新增） | ✓ 可用 |
