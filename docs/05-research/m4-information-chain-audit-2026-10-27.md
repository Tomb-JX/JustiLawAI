## 关键不一致案例

M2 有单一建议但与历史类型不符的 8 条集中在 **5 个事件**，全部为河北。三条属于辛集市同一 11,000 元现场赌资事件：规则结构按“现场总额或个人赌资取较高档”给出并罚档，而目标个人赌资仅 200/400 元、历史为罚款。另两条同属一场个人赌资 1,000/1,400 元事件，规则给并罚档、历史为拘留。其余涉及网络赌博 1,868 元而罚款、整场 1,020 元而罚款、提供条件获利 870 元而并罚。`cases.jsonl` 记录 ID 与规则输入；案情原文按 ID 回查冻结 v5。

这批冲突可能来自省基准的适用解释、个人/整场口径、未写出的减轻情节、历史实际偏离或银标错误；不能用单一解释覆盖。8 条在 5 个事件内相关，不能当成 8 个独立失败样本。省份来自现有 lake authority/城市联接，尚非每案经人工核对的行政区划证据。

## 归因与边界

1. **已证实的工程丢失**：字段本体已有方式，适配器仍不识别；参考个人赌资存在，服务大量弃判；元数据证据未进入本次 M4 文本输入。
2. **可疑的源头稀疏**：前科、特定从轻情节等在 139 条银标中极少有值；但银标并非金标，不能把这一比例叫作原判决书的客观缺失率。
3. **本体与规则接口还有缺口**：`conduct.method` 的标注说明要求“本人实际参与方式”，绑定表却一律按场景共享；36 字段没有覆盖部分省级特有条件（如机器台数、前次处罚是否因赌博）。
4. **历史决定不是规范规则的金标**：规则只给空间/已知要素建议档位；历史处罚的具体数额、天数可能依赖未见情节和机关裁量。38/46 是开发性“类型包含”对账，不是规则法律正确率，更不是模型泛化准确率。输出语义见 `docs/05-research/m2-output-contract-2026-10-27.md`。

**当前结论**：已有证据支持先修复“可见事实 → 目标人/事件字段 → 法律分支”的接口；不能宣称判决书先天无法训练，也不能宣称完善 36 字段就能逐点复现历史处分。若要定量划分源文缺失与参考漏标，只需对上述已冻结、已索引的少数争议 ID 做一次针对性复核，不重做全量样本。
