# ADR-011 台账与特征的边界放宽：缺口可挂起、描述性要素不需条文、实务特征经预注册可加

- **状态**：现行（取代 ADR-010 决定 5 的第三条与相关表述；ADR-010 其余不变）
- **日期**：2026-10-28
- **决策者**：负责人（"这种强制要求，每条法文都映射出规则，然后再收集要素特征，感觉还是太死板了"；认可三点放宽："先修"）
- **关联**：ADR-010、loops.md R9、C-38、Q-28

## 背景

ADR-010 决定 4、5 要求规则由逐条台账驱动、要素与特征由规则推出，并"禁止以某批数据上的错误作为加规则、加特征的理由"。这条容易被读成三种过度要求：每条法条都要编成规则；每个要素都要有条文依据；法律以外的因素一律不准进实务模型。实务模型的任务就是学实务，实务里确有法律以外的因素；一刀切禁止，与它的目的相悖。要防的只是"看了错误再补"这种做法。

## 决定

1. **台账要求的是"每条都有记录在案的决定"，不是"每条都编成规则"**。`gap`（能编未编）可以长期挂起，按该情形在数据中的出现频率和对结论的影响排优先级；`manual`、`not_applicable` 是正当终点。
2. **只有参与裁决的要素字段需要条文依据**。只用于记录、追溯、类案检索、审查展示的描述性字段，不需要条文依据，但不得进入规则；进入实务模型须按第 3 条。
3. **实务模型特征 = 规则生成的特征（默认） + 经预注册检验的实务特征（可选）**：
   - 规则生成的特征：规则结论、每个计量的档位与档内位置与来源、每个分类、每个升档 / 提示条件的三值、国家法修正情节触发、省份；由规则声明自动枚举，规则改了特征随之改；
   - 实务特征（法律没写、实务可能起作用的因素，如认错态度、参赌人数）：先在预注册中写明特征与判据，在未见数据上检验通过后才能加入；未通过的不得以"换个写法"重试；
   - 仍然禁止：看了某批数据的错误后，未经预注册就加规则或加特征。

## 后果

- 江苏台账 20 个缺口按频率排期，不要求一次补齐。
- RAP 下一版（rap-ruled-v2）只用规则生成的特征；C-38 显示赌资以外的通用要素当前无增量，不预先加入实务特征。
- 抽取提示随要素字段定义自动生成，台账只在新增字段或口径写明时才影响提示。

## 重开条件

规则生成的特征在未见数据上明显劣于手工特征（预注册检验），或出现大量"法律未写而实务稳定起作用"的证据。
