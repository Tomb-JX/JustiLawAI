# ADR-007 E 层采用规则锚定的实务模型（RAP），取代逐条补提示

- **状态**：现行（算法已通过检验；接入线上引擎待做，见 Q-23）
- **日期**：2026-10-28
- **决策者**：负责人指示（"输出的设计，不要一条一条的补上。核心先推算法"）；按预注册判据采纳
- **关联**：ADR-001、ADR-003、EXP-056、C-37

## 背景

C 层按原文给出的结论，在一些地方与实务系统不一致：江苏低额（C-03、C-28）、网络赌博（C-32）、河北升档且赌资不明（C-34）。逐条写提示或逐条改规则，既琐碎，也会让 C 层去迎合实务，违反 ADR-001。

## 考虑过的选项

| 选项 | 结论 |
|---|---|
| 每发现一处偏离，就补一条提示或特例规则 | 否：琐碎，覆盖不全 |
| 改 C 层规则来迎合实务 | 否：违反 ADR-001 |
| 概率版（缺失要素当隐变量，按原文推导） | 否：已关闭（Q-12） |
| **C 层结论作锚点，E 层用一个通用模型学"规则这样说时实际怎么罚"** | **采纳** |

## 决定

- **输入**：
  - M2 规则结论（唯一种类、候选成员、无分档）；
  - 省份、行为类型、方式组、国家工作人员、公共场所；
  - 金额（本人赌资、现场合计、获利，对数值加缺失指示）、参赌人数；
  - 文本四类概率。
  全部是部署时可得的信息，不使用由结果反推的量（C-13）。
- **模型**：多项逻辑回归（标准化，C = 1），用两省人工要素开发数据训练。
- **输出语义**：引擎同时给出
  - **成文结论**（C 层，照原文）；
  - **实务分布**（E 层，RAP）。
  两者不一致时就是偏离提示。不再为单个场景另写提示。
- 代码：`research/eval/rule_chain/rap_model.py`（a7b0dc0）。

## 证据

工单 B 新数据，84 条，预注册只运行一次：
- RPS 0.154 vs 第一版 0.196，差 −0.042（区间 −0.066 ~ −0.019）；
- 准确率 0.548 vs 0.464；
- 两省都更好；网络赌博子集 RPS 0.129 vs 0.190。

## 后果

- 江苏低额提示（`below_min_review`）属于输入口径提示，保留；以后不再新增针对单一场景的实务提示。
- 线上接入需要随引擎打包文本模型与 RAP 参数（Q-23）。
- 训练数据只有 391 条，换批数据后应重新训练并重测。

## 重开条件

在新数据上，RAP 的 RPS 不再优于"成文结论 + 文本"的第一版。
