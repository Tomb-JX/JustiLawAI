# ADR-009 应用形式：要素是裁量引擎的规范输入，文本模型退出引擎核心

- **状态**：现行
- **日期**：2026-10-28
- **决策者**：负责人（"统一规范的要素输入理论上来说，应该才是裁量引擎的规范……就算我们再继续调文本模型，实际应用方向会不会有偏差？"；认可本提议）
- **关联**：ADR-002、ADR-007、loops.md R8、C-13、C-38、C-40、Q-19、Q-25

## 背景

文本模型训练和评测用的都是**公开处罚决定书的事实段**：
- 处罚定了之后才写，由作出处罚的机关撰写，是一段为结论服务的摘要，一百多字；
- 免罚案件一般不出公开决定书，存在选择偏差（C-29）。

实际应用时的输入是**作出决定之前的案卷**（问答体笔录、几千字、情节未经筛选），或者办案人填写的要素。文本模型在公开数据上的分数，很大一部分来自"训练和评测是同一种文书、同一撰写者、同一时刻"。我们没有案卷数据，测不出偏移多大。

## 考虑过的选项

| 选项 | 结论 |
|---|---|
| 文本直接预测处罚（继续调文本模型） | 否：分布偏移不可测；不可审计、不能反事实；优化的是"回头预测已公开决定" |
| **要素为规范输入：人工填写为主线；案卷文本经大模型抽取成要素、人工确认后进入引擎** | **采纳** |

## 决定

1. 引擎核心的输入只有**要素 + 辖区 + 日期**。案卷文本只通过 A 层抽取进入，抽完必须经人工确认。
2. **文本模型退出引擎核心**：
   - 不再作为种类判断或实务模型（RAP）的输入；
   - 最多作为"相似公开文书的统计参考"单独展示；
   - 不再投入调优（Q-19 转搁置）。
3. **E 层实务模型改为无文本版本**（规则锚点 + 要素）：要素齐全时，与含文本版本相当（C-40）。
4. **要素缺失时不猜**：规则给出候选，同时提示"补哪一项要素能收窄候选"（Q-25，即原设计 M6 的追问排序）。
5. **评测口径**：
   - 主评测是"要素齐全、规则能定档"的记录，看准确率与 RPS；
   - 要素不全的记录，评候选覆盖率与追问有效性，不评点准确率。

## 证据

C-40，开发集事件 5 折，规则能定档的 224 条：
- RAP 无文本 RPS 0.061，含文本 0.063，只用规则 0.058，第一版 0.084；
- 文本只在"规则无分档"（缺要素）时有用。新数据上同向（事后描述）。

## 后果

- 在公开数据的整体指标上，要素不全的记录不再有点预测，整体准确率会显得更低，这是正确行为，不是退步。
- RAP 的检验结论（C-37）是含文本版本的；无文本版本在新数据上未做预注册检验，接入前补测（Q-23）。
- 上线时 A 层抽取在案卷文体上的准确率仍未知（Q-06），需要真实或模拟案卷再评。

## 重开条件

拿到真实案卷数据，并证明文本模型在案卷上相对要素引擎有稳定增益。
