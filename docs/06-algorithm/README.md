# 裁量引擎算法开发文档

> 版本 v1 · 2026-10-28 · 负责人批准建立（"按你的建议定，开始建文档体系"）
> 本目录管**算法**：事实怎么变成处罚建议、为什么这样设计、试过什么、哪些结论在什么条件下成立。进度和数字快照仍看 [引擎线现状](../05-research/engine-line-status-2026-10-26.md)，门槛仍看 [固定对照与阶段门禁](../05-research/sota-baselines-and-gates.md)。

## 为什么建这个目录

2026-10-14 到 10-28，裁量引擎试过约 50 项设计和实验，但设计反复绕回旧错误。回顾发现原因不是缺想法，而是五个结构性问题：

1. 结论被引用时丢了适用条件。例如"要素无增益"实际只测了"要素拼进线性文本分类器"。
2. 已知事实散在按日期命名的报告里。例如"江苏低额实务偏离成文"被发现了四次。
3. 停掉的路线没写重开条件。例如绑定线停了又被提起。
4. 关键设计讨论只在对话里，上下文压缩后就没了。
5. 评估口径没有统一版本，不同实验的数字不能直接比。

本目录用四样东西对付它们：**问题骨架**（每个提议先说改哪一层）、**结论台账**（每条结论带适用范围）、**问题台账**（关闭的带重开条件）、**决策记录**（只追加）。已发生的回路（R1–R10）见 [loops.md](./loops.md)。

## 新会话开工必读（约 20 分钟）

1. [problem.md](./problem.md)：搞清楚分层，以及法律在每层的角色。
2. [architecture.md](./architecture.md)：现在实际跑的是什么；§0 一句话定位（[ADR-010](./adr/ADR-010-positioning-ledger-driven-rules.md)）。
3. [loops.md](./loops.md)：哪些坑已经掉进去过。
4. [questions.md](./questions.md)：哪些问题开放，哪些已经关闭以及重开条件。
5. 动手前，在 [claims.md](./claims.md) 查与本题相关的结论，**看清适用范围**。

## 提议检查单（任何新算法提议先答这六问）

1. **改哪一层？** 对照 [problem.md](./problem.md) 的 A–F 层；其他层是否保持不变？
2. **碰到哪些已有结论和已关闭问题？** 列出 C-xx、Q-xx；涉及关闭项时，说明重开条件已满足。
3. **法律在本设计里是什么角色？** 硬边界、定档、特征还是提示？与 [ADR-001](./adr/ADR-001-law-first.md) 是否一致？
4. **输入在部署时可得吗？** 有没有用处罚结果反推要素（循环）？见 [C-13](./claims.md)。
5. **用哪一版评估协议，判据是什么？** 判据写进预注册，先于结果。
6. **先做哪个零成本证伪？**

答不出 2 和 3，不要开工。

## 维护规则

A1–A5 补充[文档维护体系](../04-plan/doc-maintenance-system.md)的 R1–R6。

- **A1 提议先过检查单**：上面六问写进提议或 ADR 的"背景"。
- **A2 结论带范围**：写进 claims.md 的结论必须填"接入方式"和"没检验什么"；引用结论时引编号，不复述成更宽泛的话。
- **A3 关闭必写重开条件**：停掉或否定一条路线，当场写进 questions.md。
- **A4 对话里定的设计当天落文档**：讨论中定下的原则、否定的方案，当天写成 ADR（可先标"提议"）或台账行，不允许只留在对话里。
- **A5 实验进索引**：每个实验结束时，在 experiments.md 加一行，结论进 claims.md。

本目录属于维护体系的 L2 权威层：与代码同提交（R1）；ADR 只追加，改决定写新 ADR 取代旧的（R6）。

## 编号

ADR-xxx（决策）、EXP-xxx（实验）、C-xx（结论）、Q-xx（问题）、EP-x（评估协议）。`D-` 前缀已被偏离日志和协作决策占用，本目录不用。编号只增不复用；作废的条目标"被取代"，不删除。
