# 规范规则化流程：逐条台账体系

> 版本 v1 · 2026-10-28 · 依据 [ADR-010](./adr/ADR-010-positioning-ledger-driven-rules.md) 决定 4、5 · 问题台账 Q-28
> 适用于国家层法律（治安管理处罚法、行政处罚法相关条款）与各省裁量基准。新增省份、规范修订、补编规则，都走本流程。

## 1. 为什么要有这套流程

此前省级规则是"照档位表抄门槛"编出来的：哪些条文编了、哪些故意不编、哪些编不了，没有记录。结果是新数据一报错就回头补一条（loops.md R9），例如江苏基准一（三）"每次赌博查实的赌资应当累计计算"直到 C-44 才补编。

本流程的目标：
1. **不漏**：原文每一条都有处置，漏了测试失败；
2. **可追溯**：每条规则指回原文条目，每个要素字段指回要求它的条文；
3. **可复用**：新省份按同一步骤、同一数据格式、同一测试接入；
4. **可复核**：法律组看一张表就能确认"编了什么、为什么不编"。

## 2. 总览

```
S0 取得完整原文 ─→ S1 确定性切分 ─→ S2 逐条处置 ─→ S3 编码规则 ─→ S4 要素映射
                                                        │              │
S8 数据检验 ←─ S7 法律组复核 ←─ S6 测试强制 ←─ S5 派生（补查提示、条款原文、实务特征）
```

| 步骤 | 产出 | 位置 | 关口（不过不能进下一步） |
|---|---|---|---|
| S0 原文 | 完整原文 + 文号、效力、施行日期、核验记录 | `norms/provinces/<代码>.yaml` 的 `documents`（国家层：`norms/national/`） | **完整原文，不是节选**；核验状态"已核验"（逐字比对官方来源） |
| S1 切分 | 条目骨架 | `norms/ledgers/<代码>.yaml`，`scripts/ledger_skeleton.py` 生成 | 条目拼接 = 原文（去空白后完全一致） |
| S2 处置 | 每条一个处置 + 指向 + 说明 | 同上 | 无空处置；encoded / element 有指向；gap / manual / not_applicable 有说明 |
| S3 编码 | 规则 | `norms/provinces/<代码>.yaml` 的 `rules`、`bands`、`clauses` | 指向可解析；条款原文逐字出自原文 |
| S4 要素 | 字段定义、标注口径、抽取提示 | `app/discretion/schema.py`、标注指南、工单 BRIEF | 新字段注明要求它的条文；改字段同步 schema 版本与抽取提示版本 |
| S5 派生 | 补查提示、trace 条款原文、RAP 特征 | `norm_layer`、`trace`、`practice` | 派生自规则声明，不手工另列 |
| S6 测试 | 台账测试、规则单元测试 | `tests/discretion/test_ledgers.py` 等 | 全部通过 |
| S7 复核 | 复核表 | `docs/06-algorithm/ledgers/<代码>.md`，`scripts/ledger_report.py` 生成 | 法律组填 `reviewed_by`，台账状态改"已复核" |
| S8 检验 | 预注册检验报告 | `$DATA/engine/development/…` | 有数据的省份：规则变更在未见数据上预注册检验 |

## 3. 台账数据格式

一部规范一个文件，`norms/ledgers/<代码>.yaml`：

```yaml
document: 苏公规〔2019〕1号
province: "320000"
province_rules: norms/provinces/320000.yaml
source_sha256: <原文 sha256>          # 原文一改，测试即失败，必须重切分、重复核
segmenter: ledger-seg-v1
status: 初版（引擎编制，待法律组复核）
reviewed_by: []
items:
  - path: 一.（三）                     # 由切分器生成的稳定编号
    text: （三）每次赌博查实的赌资应当累计计算。   # 逐字原文
    disposition: encoded
    refs: [rules.参与赌博.measures.personal_or_per_capita, field:amounts.cumulative_stake]
    note: 10-28 补编：累计赌资优先作为定档赌资（C-44）
```

**处置六类**：

| 处置 | 含义 | 必填 | 例子 |
|---|---|---|---|
| `encoded` | 已编成规则 | `refs`：规则路径（`rules.…`、`bands.…`）或代码（`code:模块.函数`） | 三.（一）.1 第一档门槛 |
| `element` | 由要素字段定义承接（标注、抽取时按此口径） | `refs`：`field:组.字段` | 一.（一）.1 赌注计入赌资 |
| `gap` | 已识别、尚未处理 | `note`：缺什么、跟进编号 | 四.（一）.3 赌博机台数（无字段） |
| `manual` | 需办案人判断，引擎只提示 | `note` | "其他情节严重的情形" |
| `not_applicable` | 与处罚种类、档位无关 | `note` | 赌资收缴、作案工具收缴 |
| `context` | 非规范文字 | — | 标题、发文语、日期、章节名 |

**`gap` 与 `manual` 的区别**：gap 是"能编、还没编"，是待办；manual 是"本来就该由人判断"，是设计。gap 可以长期挂起，按数据中出现频率与对结论的影响排期（ADR-011）。

**引用规则路径**：按 YAML 键逐级写；列表元素用其 `field` / `when` / `id` 取值定位，如 `rules.参与赌博.elevate.civil_servant`、`rules.参与赌博.measures.personal_or_per_capita.categories.其他`。

## 4. 切分规则（`ledger-seg-v1`）

- 三级标记：`一、`（行首）、`（一）`（前面不是"第"，排除"第（二）项"这类引用）、`1．`（全角点，前面不是数字）；
- 第一个"一、"之前按行切（标题、发文语、日期、立法目的）；
- 同一标记下的续段按行再切，编号加"段 k"；
- 切分是确定性的：同一原文永远得到同样的条目和编号。新文件格式不适用时，升级切分器版本，不手工切。

## 5. 规则编码约定（S3）

- **数额口径写成声明**：赌资怎么取（累计 → 单次 → 人均）写在 `measures[].sources`，每个来源的 `label` 写明条款，计算过程原样进入 trace。不在代码里硬编某省口径。
- **门槛与分类**：`measures[].lower_bounds`、`categories`（按方式 / 组织形式）。
- **升档、提示**：`elevate`（直接定档）、`floor_hint`（只提示，须核实）。
- **未达起罚**：`below_min` 与 `below_min_review`（口径核实提示）。
- **档位条款原文**：`clauses`，测试保证逐字出自原文。
- **通用机制写代码**（区间三值判断、"以上含本数"、时间效力），各省差异写 YAML。
- **没有条文依据，不编**。成文与实务不一致时，规则照原文，偏离交给实务参照与审查（ADR-010）。

## 6. 要素映射（S4）

- 只有**参与裁决**的字段需要条文依据；只用于记录、追溯、类案、审查展示的描述性字段不需要，但不得进入规则（ADR-011）。
- 要素表是各省**共用**的概念。先找现有字段能否表达；只有出现现有字段表达不了的概念才加字段，并在台账该条 `refs` 指向新字段、在 schema 描述里注明条文出处。
- 改字段定义或口径，要同步：schema 版本、标注指南、工单 BRIEF、抽取提示版本（提示指纹会变，需重跑的批次另行评估）。
- 台账里 `gap` 指向已有字段的（如 `conduct.role` 有"放贷者""望风者"），表示"要素已有、规则未编"，优先处理；没有字段的 gap 先评估数据里出现频率再决定。

## 7. 派生（S5）

| 派生物 | 来源 | 现状 |
|---|---|---|
| 补查提示 | 规则计量为"未知"的字段、未知条件 | 已实现（`trace.missing`） |
| trace 条款原文与计算过程 | `clauses`、`measures[].sources[].label` | 已实现 |
| RAP 特征 | 规则结论 + 规则读到的每个量 + 每个升档 / 提示条件（默认，`rule_features.py`，名单由规则枚举、哈希校验）；实务特征须预注册检验通过才能加（ADR-011） | **已实现**；线上模型只用其中规则结论 9 维（开发集选择、工单 C 检验，C-46）；规则改动后须重跑 `rap_v2.py` 重训 |

## 8. 测试（S6）

`tests/discretion/test_ledgers.py`：
- 每个已录入省份必须有台账；暂缺的列在 `PENDING` 并写原因（现为河北：只有节选）；
- 台账条目与重新切分的结果逐条一致；原文哈希一致；
- 处置齐全，指向可解析（规则路径、要素字段、代码符号）；
- 改写一条原文、清空一个处置、写错一个指向，测试都能抓到（自测）；
- 复核表与台账同步；
- 规则补编的单元测试（如江苏累计赌资：只有累计赌资时按累计定档，累计优先于单次，河北不用）。

## 9. 复核与变更（S7、S9）

- **复核**：`python scripts/ledger_report.py` 生成复核表（缺口单列在前）；法律组逐条确认"不编的理由"和 gap 优先级，在台账填 `reviewed_by`，状态改"已复核"。
- **原文变更**（省厅发布新版基准）：录新文件 → 哈希变了，旧台账测试失败 → 重切分、逐条处置、复核；旧版本作为历史文件保留，按施行日期选用。
- **规则变更**：先改台账条目的处置与指向，再改规则；提交时测试必须通过。
- **禁止**：以"某批数据上的错误"为由加规则；必须指出台账里对应的条目（loops.md R9）。

## 10. 新增一个省份（清单）

1. 取得完整原文与核验记录，写入 `norms/provinces/<代码>.yaml` 的 `documents`（S0）。
2. `python scripts/ledger_skeleton.py <代码>` 生成骨架（S1）。
3. 逐条填处置（S2）；能编的编进 `rules`（S3）；需要的要素先查共用表（S4）。
4. `python scripts/ledger_report.py`，跑测试（S6）。
5. 复核表交法律组（S7）。
6. 有该省数据时，写预注册、在未见数据上检验（S8）。
