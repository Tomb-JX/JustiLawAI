# 要素绑定 v2：弱监督方案详细计划（2026-10-27）

## 0. 为什么换路线

10-27 写的两套规则（现场口径 `onsite_caliber.py`、个人归属 `personal_attribution.py`）证明了一件事：问题的结构是“同一小句里的 人名—连接词—金额”加“金额的口径”。个人赌资规则在 T4 上 121/123，现场赌资“判未提及”206/207。

但规则本身不是可持续的方案，原因有三：
- 约 20 组关键词里不少是看着单条错例加的（面值、替代、主板9块、均摊、流水……）；
- H3 上出现过一次过拟合，只按 dev 调完后从 15/16 退到 13/16；
- 现场赌资的填值部分在 T4 上不达标，只有 88%。

本计划把规则从“判官”降为“标注员”：
- 规则只给大量无标注文书打带噪声的标签；
- 由统计模型估计每条规则的可靠度并合成软标签；
- 再训练一个只看原文的编码器模型去学这种结构；
- 最后在全新封存集上、按事先写好的判据检验一次。

## 1. 不叠补丁的硬约束（全程有效）

1. **规则冻结**：`onsite_caliber.py`、`personal_attribution.py` 以 10-27 版本冻结，不再改动，只拆成标注函数复用（见 §4）。
2. **改标注函数要过门槛**：只能新增或修改标注函数，不能改单条记录的处理。每次改动要同时满足：
   - 在 dev 池上修正至少 3 条同一语言现象的错误；
   - 用一句话写出它对应的通用写法；
   - 在 `LF-CHANGELOG.md` 记录改前和改后的覆盖率与准确率；
   - 一条错例对应一个补丁的改动一律不收。
3. **数据分工固定，不得互借**：

   | 集合 | 规模 | 用途 | 禁止 |
   |---|---|---|---|
   | dev 池 | 287 | 写标注函数、看错例 | — |
   | H3 | 80 | 标签模型与阈值的验证，只看汇总 | 不看错例 |
   | T4 | 260 | 退役，只在最终报告里列作对照 | 不再用于任何决定 |
   | F5（新封存） | ≥250 | 唯一的放行检验，一次 | 训练前封存，主会话不读逐条答案 |
   | U（无标注池） | 约 3–4k 条去重后事件 | 弱标签与训练 | 不得包含上面四个集合的同一事件 |

4. **数字必须事先写**：每个阶段开跑前，先写判据文件并钉住哈希，再运行。
5. **模型不许读规则输出**：模型的输入只有原文和标记，不把标注函数的投票当特征喂进去，否则学到的只是规则的复刻。

## 2. 任务重新定义

两个字段统一成在“候选对”上做分类，再按记录汇总：

- **A. 金额口径**（每个金额一个类别）：现场合计 / 个人持有 / 部分（共同、无主） / 规则数额（底注、封顶、每局） / 输赢额 / 抽头与获利 / 其他（罚款、硬币枚数、兑换比例）。
- **B. 人—金额归属**（每个“人名提及 × 金额”对一个类别）：持有 / 人人各出 / 输赢 / 无关。沿用现有 `train_pair_encoder.py` 的 CLASSES 并精简。
- **记录级汇总**：
  - 个人赌资：取目标人与“个人持有”金额的归属概率，在阈值以上、且只有一个数值时填；
  - 现场赌资：取口径为“现场合计”的概率，在阈值以上、且只有一个数值时填；全部金额都不是合计时判“未提及”。
  - 其余情况转人工。阈值按 §6 选定。

## 3. 阶段 1：数据底座（先做，否则后面全是空转）

### 1a 人名提及层重做
现状：人名靠遮蔽名正则加旧的 persons 逻辑，已见到“小树林内”被当成人、“彭英/应新法”这类不遮蔽的全名识别不到。

做法：
- 人名候选三路取并集：
  - 遮蔽名正则（现有）；
  - 中文人名识别工具（候选：jionlp 自带的人名识别、LTP 或 HanLP 的 NER 模型，按许可与本机可跑性选一个，NC 许可可用）；
  - 文书结构位置（“违法行为人X”“对X罚款”“X、Y、Z等人”）。
- 用目标名和 aliases 做归并，同一人的不同遮蔽写法合成一个实体。
- 检验：dev 池上人工可核对的指标是“目标人提及召回”和“非人名误识别数”，并抽查 50 条把结果写进报告。

### 1b 无标注池 U
- 来源：`lake/parsed/pkulaw/*`（约 5k 行，含重复批次）。web 来源 5k 行先测格式，能统一再纳入。
- 只保留赌博类行政处罚文书，按 `event_cluster_id` 去重。剔除 dev、H3、T4、F5 的同一事件，并留一份剔除清单。
- 产出：`U-20261028/inputs.jsonl` 和 MANIFEST，记录规模与哈希。

### 1c 新封存检验集 F5
- 来源：P8 批次（113 条，T4 未覆盖，**需先核实没进过 dev/H3/训练**），加上从 U 里按事件随机抽出、再从 U 剔除的部分，凑满 250 条以上。
- 参照：沿用 T4 协议，即 Claude 双盲（pass1/pass2）加独立仲裁、指南不变。主会话不读逐条答案。
- **必须在任何训练之前封存。**

## 4. 阶段 2：标注函数（LF）库

把现有规则和现有模型都拆成“只投票或弃权”的小函数，每个函数只代表一种语言现象：

| 组 | 例 | 来源 |
|---|---|---|
| 归属·点名 | LF_名字+连接词+赌资；LF_在X身上/从X处查获；LF_列表中X赌资Y元 | personal_attribution 拆分 |
| 归属·未点名 | LF_其个人赌资；LF_查获时身上有赌资；LF_共计充值 | 同上 |
| 归属·否定 | LF_他人点名（遮蔽/全名）；LF_每局/单次/封顶；LF_罚款句 | 同上 |
| 口径 | LF_合计标记；LF_其中领起的分项；LF_共同/无主；LF_人均/均摊；LF_输了/流水；LF_硬币枚数；LF_抽头 | onsite_caliber 拆分 |
| 结构 | LF_金额前最近人名距离；LF_句法主语（依存分析的主语是否为该人） | 新写（通用结构，不是词表） |
| 现有模型 | LF_frozen_chain、LF_softmax 路线、LF_pair_roberta（v1） | binding-v1 已有 |

要求：
- 每个 LF 在 dev 上报覆盖率、准确率、冲突率，并写进 `LF-REPORT`。
- LF 数量不追求多，一种现象一个函数。不同组之间尽量不相关：除词表类外，必须有结构类和模型类，否则标签模型会把相关的同源错误当成多票一致。

## 5. 阶段 3：标签模型（把多张带噪声的票合成软标签）

**原理（学习笔记会单独写一份）**：每个 LF 都是一个不完美的标注员。标签模型（Dawid–Skene 或 Snorkel 的生成式标签模型）只看各 LF 在大量无标注数据上的“同意/不同意”模式，用 EM 算法同时估计两样东西：
- 每个 LF 有多可靠；
- 每个样本真实标签的概率。

它不需要金标，靠的是“多个大体独立的标注员互相印证”。

做法：
- 用开源的 Snorkel LabelModel（Apache-2.0），或自己写约 100 行的 Dawid–Skene EM，二选一，在 dev 上比较；
- 对已知相关的 LF 组（同源词表）声明相关结构，或合并成一票，防止重复计票；
- 检验：
  - 标签模型在 dev 和 H3 上的准确率与校准（ECE），只看汇总；
  - 对比“多数投票”和“最强单条规则”两个基线，标签模型必须优于二者，否则这一步没有意义，退回检查 LF 设计。
- 产出：U 上每个候选对、每个金额的软标签，以及覆盖率统计。

## 6. 阶段 4：终端模型（真正的“算法”部分）

- **架构**：在现有 `train_pair_encoder.py` 基础上扩展。中文 RoBERTa 加实体标记（[人:目标]…[/人]、[额]…[/额]），沿用 Zhou & Chen 的“标记起点向量”表示，增加两个头：
  - 归属头：人—金额对；
  - 口径头：金额本身，输入是只标金额的窗口。
- **训练**：
  - 用软标签做噪声感知损失，即对软标签做交叉熵，不取硬标签；
  - 类别加权；
  - 按事件做 5 折交叉验证，固定种子。
- **只学原文**：输入里不放任何 LF 结果（§1 第 5 条）。
- **泛化证据（关键指标）**：在 dev 上单独统计“所有规则都弃权的样本”上模型的准确率。这一块如果明显好于随机，才说明模型学到了规则以外的东西。如果模型只在规则命中的样本上好，就判定为只是复刻规则，不进入下一阶段。
- **阈值与弃权**：在 dev 和 H3 的交叉验证预测上，选能达到目标精度（填值 ≥ 97%）的最低阈值，写进判据文件后冻结。
- **对照组**（同一 F5 上一起报告）：
  1. v1.1 服务；
  2. 10-27 冻结规则；
  3. 标签模型直接输出；
  4. 终端模型；
  5. 终端模型 + 规则一致性门（两者一致才填）。
- **鲁棒性**：复用已有反事实套件（换名、删证据、他人改名、改标签），要求终端模型不比规则差。
- **算力**：本机 RTX 5060 8GB 足够微调 base 规模的编码器。**按约定开跑前先征求你同意。**

## 7. 阶段 5：F5 一次性放行检验

- 判据（运行前写入 F5 目录并钉哈希），逐字段：
  - 填值：可计分 ≥ 30，精度 ≥ 95%，Wilson 下界 ≥ 88%；
  - 判未提及（现场赌资）：可计分 ≥ 50，精度 ≥ 97%，Wilson 下界 ≥ 93%。
- 同时报覆盖率、转人工构成、与 §6 各对照组的差。
- 不达标就维持影子推理，并且不在 F5 上改任何东西再测。

## 8. 阶段 6：接入与冻结（达标后才做）

- binding v1.2：模型、阈值、layout_wraps、人名层一起重新冻结（钉哈希）；
- 服务输出保留每个字段的“依据”：模型概率，以及与规则是否一致；
- 维护态口径不变：放行字段可以自动用，其余照旧只作建议。

## 9. 需要你拍板的事

1. **携带额与剩余额并存时取哪个**：dev 和 H3 的参照前后不一致。建议定为“以查获时持有为准”，写进审核指南。这一点不定，标签和参照都会自相矛盾。
2. **本机 GPU 训练**：阶段 4 开跑前单独征求同意。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| LF 都是词表类、彼此相关，标签模型过度自信 | 强制加入结构类和模型类 LF；声明相关组；与多数投票基线对比 |
| 模型只是学会复刻规则 | 输入不含规则；单独考核“规则弃权样本”上的表现 |
| U 太小（去重后可能只有 2–3k 事件） | 先量出规模；不够就补采集（P9+）；同时把 web 来源格式统一后纳入 |
| 参照本身有噪声（Claude 审核，非真人金标） | 所有结论注明；口径问题先修指南（§9 第 1 条） |
| 检验集被反复使用 | T4 退役，F5 只用一次；以后每个大版本新封一批 |
