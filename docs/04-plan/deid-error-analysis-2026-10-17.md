# 脱敏层错误汇总与算法客观评估（2026-10-17）

> 应"对由脱敏引起的错误做详细汇总、并客观评估算法精密度/复杂度（不能只看文档阐释）"的要求产出。所有数字均为本次实测，来源标注到文件。另先回答前置问题：**"预脱敏"就是 build 的脱敏算法换了个调用时点**——同一套规则（deid.py）、同一函数，在模型外呼前先跑一次、产物只给模型不回写管道；正式交付的脱敏仍从原文态 parsed-1 独立执行。管道里**不存在两道持久脱敏**。

## 3. 客观评估结论

1. **精密度/复杂度定性**：多模式正则（43 模式/99 正则调用/70 环视/10 级优先级）+ 词表闸门（413 姓氏+176 停用词+54 处硬编码）+ 扩展循环。**类别=模式匹配系统，无学习能力**——你的判断成立。
2. **实测触发画像**：21.6 次遮蔽/件，人名占 47%；衍生标记（265+585）说明**含糊处理已占交付的相当比例**。
3. **已证实的失败率**：漏网侧——金标 50 件抽样即暴露 4 类真缺口 + R6 盲区 58%；误伤侧——265 ambiguous + 585 variants + 3 白名单。**两个方向的总体精密度/召回率都未知，因为不存在隐私标注金标准**——这不是测了隐瞒，是根本没测过，也正是候选 B（200 件标注测试集）的定义。
4. **范式判定**：v2 架构方向不变且更坚定——语义识别（人名/分段）交模型，确定性校验（证件/电话/门牌/日期/文号哈希/一致性）留规则。deid.py 现有 43 模式中，确定性类别（id/phone/bank/plate/email/url/date/docno/house）**保留为校验器与快速通道**；语义类别（person/place 边界）转模型 NER 复核。
5. **预脱敏澄清**：S1 = 同一算法提前一次调用、产物只外呼不回写；正式脱敏仍从原文态独立执行——不会产生"二次遮蔽"的叠加效应。
