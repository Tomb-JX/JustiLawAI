# 恶性循环断路协议 + 人工金标不可行（永久记录）

> 日期：2026-10-25。来源：负责人对"反复修复→生产→被毙→再修复→旧批作废"恶性循环的质询，
> 及协调线的复盘分析。登记为 DECISIONS.md 的 **D-004、B-12**，对所有线（含协调线自身）生效。
> 本协议约束的是"以后怎么决定要不要修、要不要产、要不要重产"，不是某一条管线的技术方案。

## 0. 永久事实：人工金标不可能（D-004）

负责人 2026-10-25 陈述，永久记录在案：

- **没有专业标注人力。**
- **负责人本人（非专业标注者）尝试人工标注，效果不及模型标注。**

由此三条推论，永久有效：

1. 任何计划不得以"人工金标"为前置或待办。500 金标计划因此已归档；协调线 2026-10-25 上午
   提出的"100–150 条人工双标最小金标"建议**据此正式撤回**。
2. 任何根因分析、质量讨论**不得把问题归结为"缺人工金标/只是银标"**。质量问题必须落到
   机器可检测的具体错误（如 S3 no_decision 113 条、facts_leak 94 条）上，用工程手段和
   模型共识解决；"没有 gold"不是解释，是既定条件。
3. 质量锚点只有两类机器可行物：
   - **确定性可校验字段**：金额/日期/引文与原文逐字核对、文号对 M0 规范库核对——机器可查，不需要人；
   - **多模型一致参考集**：D-001/D-002 的双盲+第三模型仲裁机制，用在一次性冻结的小测量集上（见断路 6），不用于批量生产。

## 1. 循环长什么样（用本项目实测账目描述）

> 修复管线 → 全量付费生产 → 校验器事后毙掉大批 → 诊断 → 再修复 → 旧批成"旧版本"作废 → 循环

实测成本：

| 循环轮次 | 花费 | 结果 |
|---|---|---|
| 706 旧根 `lake-text-706-20261021` | pilot 部分烧掉 | provider 配置一变（execution_settings_changed）整根作废，不能原地续 |
| 706b `lake-text-706b-20261022` | ¥10.62、634 次调用、2 天 | 567/706，139 条被 Arrearage/超时/预算毙 |
| resume139（进行中） | ~¥2、10-22→10-25 | 补 131 条 |
| S3 事后门禁（今天 15:46 实测） | — | 581 条 S1 产出只有 **147 条 accepted（25%）**；434 条的 S1 调用费已烧、按现行规则整条作废 |
| 909 标签 | 生产+timesfix 重标（离线） | 原计划还要按新视图**第三轮**重标 57 复议+89 字段表（本协议冻结之） |
| S1 语义 | 一个月内 meta_fields、prior_sentence_ids 两次改动 | 每次改动 view_hash 变，旧产出技术上不可比 |

循环的三个发动机：
**(a)** 用全量生产批当测试——失败在生产之后才被发现；
**(b)** 校验器全有全无——一条被毙，整条已付费的 S1 产出归零；
**(c)** 修复使旧数据作废——每次修好管线，上一批就成旧版本，重产又烧一轮钱。
协调线此前的失职：每轮复盘都输出"下一个修复"，从不输出"冻结与止损"，本身就在给循环上发条。

## 2. 六条断路（B-12）

### 断路 1：版本冻结——治"修复使旧数据作废"

- 每个生产批永久携带管线版本号（`prompt_version` + 视图契约 hash + execution manifest），
  产出**对该版本永久有效**。后续任何修复只向前生效。
- "旧批要按新视图重产/重标"不再是默认动作。重产需同时满足两个前置：
  ① 有**具名下游实验**声明需要这批数据并给出假设；② 费用核准。缺一即拒绝。
- 依此条：**909 的 57 复议 + 89 字段表按新视图重标计划冻结**（既有标签降级为 Tier B，见断路 3）。

### 断路 2：先金丝雀后花钱——治"生产完才知道被毙多少"

- 任何 >50 条的付费批，先跑**按渠道/文书类型分层**的金丝雀（每层 ~30 条），
  报的不是"S1 跑通率"而是"**S3 accepted 率（分渠道）**"。
- 达标渠道（阈值由消费方实验写明）才进生产；不达标渠道**当场排除出训练范围**，
  不排"以后修"的队。要修，走断路 4 的具名需求。
- 706 教训：pilot12 只验证了 S1 能跑通，没验证 S3 能收。今天实测 accepted 里
  pkulaw 139 / web 8 / 公示复议 ≈0——若当初按渠道金丝雀看 S3 收率，非 pkulaw 渠道的钱根本不会花。

### 断路 3：分级验收——治"毙掉即烧掉"

- S3 拒收 ≠ 整条作废。产出分三级：
  - **Tier A**：全部门禁通过 → 训练；
  - **Tier B**：部分通道可用（如有 facts 无 decision）→ 文本观察/语料/前科挖掘，**不进训练**；
  - **Tier C**：废弃。
- 今天 434 条拒收里，113 条 no_decision、94 条 facts_leak 多数属 Tier B 料：
  钱已花，价值部分回收，不需要任何重跑。
- 各线消费数据时必须声明消费的 Tier；Tier B 数据混入训练视为事故。

### 断路 4：需求驱动生产——治"为修而修、为产而产"

- 任何扩产、任何管线语义修复，立项时必须回答三问：**哪个实验消费？假设是什么？预期哪个指标动？**
- 实证依据（2026-10-25 M4 实验）：train 868→1062（+22%），type_correct 恒为 107/168，
  macro F1 0.358→0.351，罚款 MAE 仍输给中位数基线（384.6 vs 341）。
  **当前信号结构下，加银标数据已被证明无效。**
- 因此在具名实验给出"数据/修复能改变什么"的假设之前：不再扩产银标、不再改 S1 语义。
- 唯一例外：resume139 收尾——队列已冻结、钱已花，把 706 账收口是止损不是扩产。

### 断路 5：范围收缩——治"什么都要修好"

- **训练范围宣布为 pkulaw 渠道单渠道。** 这不是妥协，是今天数据说的：accepted 147 条里 139 条是 pkulaw。
- web/公示/复议渠道：Tier B 或排除；**不再为其修改管线、不再为其重产 S1**。
  复议文书的正确处置是"路由出训练范围"，而不是"修到能进训练"。
- 管线修复义务从无限（所有文书类型都要修好）变有界（只服务 pkulaw→训练这一条通道）。

### 断路 6：机器参考集替代人工金标——治"盲打、无法归因"

- 一次性建 **~100 条冻结参考集**：D-001/D-002 双模型背对背 + 第三模型逐字段仲裁，
  只收"确定性字段可校验"或"多模型一致"的记录，分歧即弃。
- 用途仅两个：校准 S3 门禁阈值、校准 M4 验证口径。不进训练、不扩量、建成即冻结。
- 成本：100 条 × 2 个额外模型，按现行 qwen/DeepSeek 混跑价为几十元量级，一次性。
- **S1 生产保持单模型单次调用**（当前 qwen3.8-flash，resume139 即此配置）。
  三模型只出现在两处：L5 仲裁（既有）与本参考集（一次性）。任何"S1 也上三模型"的理解都是错的。

## 4. 对协调线自身的约束

复盘输出的默认动作从"下一个修复"改为：**先问要不要冻结、要不要排除、要不要止损，
再问要不要修。** 任何新的"修复→重产"建议必须自带断路 2/4 的前置，否则不得提出。
