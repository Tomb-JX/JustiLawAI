# I-20 网页线→引擎线 接口包（2026-10-18）

> 用途：答复 [I-20 问题单](../../../../data-coordination/docs/04-plan/issues/I-20-element-label-gap-2026-10-18.md) §6.1/§6.2，并交付引擎写**要素教师提示 v1 + 输出 Schema + 验收脚本**所需的全部管线接口事实。引擎侧开工不再需要等网页线任何信息；§6.3/§6.4 属引擎答复项，本文附网页侧约束供其决策。
> 生产方：网页线（unify/ 管线）。实测基线：seg-v2 批次 s1-20261018-segv2-ds300（deepseek-flash 294 件）+ unified_raw web-r3 2,325 放行件。

## 1. §6.1 粒度答复（实测钉死）

| 问题 | 答复 | 证据 |
|---|---|---|
| unified_raw 粒度 | **一文一人，一条记录=一个人的要素集** | 放行 2,325 件 subject_mention 含顿号 **0 件**（渠道层保证一人一份；多人共载页=拆条泄漏，已登记渠道工单，非粒度问题） |
| 多行为人案卷 | 每份决定书一条记录，同事件多记录由组装层 `event_id` 关联（r6 已有）；**要素不跨记录合并** | build 层两级事件签名 |
| `subject.aliases` 语义 | **同一人多写法**（非同案多人） | seg-v2 实测 19/300 非空、每条 1–2 项；`[本人]` 目标参数上线后不再出现名单填充 |
| target 参数 | `subject_mention` 即 M1 `extract(target=…)` 的 target，已进 unified 契约与 user prompt（`[本人] …outcome 各值只填本人`） | s1.py seg-v2 |

**要素提示输入形态可直接定**：每请求一人一目标，无消歧负担。

## 2. §6.2 当事人段答复（实测）

- **当事人段在 zones 句表内**：ds300 实测 184/294 件 facts 前有句子（当事人段/文书头归入 meta/facts 前部），17 件 facts 从 S1 起，93 件无 facts 区间（公示/硬骨头件）；
- **要素输入建议 = facts + meta 区间句子**（中位覆盖全文 50% 句子），或直接喂全文句表——**无需另拼 text_party**；
- **要素文本可得率基线**（release 2,325 件，正则存在性口径，供 §5.3"未提及比例告警"定阈）：

| 字段族 | 文本可得率 | 备注 |
|---|---|---|
| 出生日期字样 | 46.5% | 多数源头已遮（spec 旧测 278/1036），实际可得值远低于字样出现 |
| 参赌人数 | 26.3% | |
| 前科/违法经历 | 11.1% | |
| 营利目的词（抽头/牟利/台费…） | 4.3% | |
| 年龄"N岁/周岁"写法 | 3.1% | 年龄主要靠出生日期推（也多已遮）→ **age 未提及预计 >90%** |
| 未成年 | 0.9% | |

**给提示设计的硬约束**："未提及是正常且主要状态"必须写进教师提示预期与空值规则，否则模型会编造（v1 引文时代已实证金额幻觉模式）。

## 3. 管线接入接口（引擎提示交付后即插，网页侧改动面）

1. **新增 stage**：`--stage elements`（或独立 run-mode）：输入=该记录 **facts+meta 句表**（编号句表复用 seg-v2 的 `sentences`，坐标现成）+ `[本人]` target；输出=37 字段三态 JSON；
2. **复用件（全部现成，零新轮子）**：s1 客户端（per-provider 参数/重试带反馈/熔断/心跳 progress.json/费用计量）、缓存键 `text_clean_sha256 + prompt_version + model`、回执三件套；
3. **证据锚定**：要素 `evidence` 给**编号句引用**（如 `"evidence_sentences":[10,11]`）优于长引文——句表坐标确定性映射原文（v2 接口教训：区间锚定比自由引文稳），S3 `value_grounded` 已有条号/金额/日期反向解析可扩到要素数值域；
4. **双标/仲裁纪律**（D-002，已按用户改令更新）：生成=deepseek-flash；**裁判/第二标=mimo-v2.6-pro（小米）**；deepseek 自裁禁止由代码断言保证；
5. **验收脚本挂载点**：输出写 `s1_runs/<run_id>/elements.jsonl` 一行一记录；§5.3 四指标中三项（结构合法/证据命中/未提及对照 key_field_presence）本管线 S3+对照脚本可直接算。

## 4. 网页侧对 §6.3 的建议（parsed-2 存放，供引擎定夺）

建议顶层 `elements: {字段: {status, value, evidence:[句id], source_span:[原文起,止]}}`——平铺会碰 37 字段×嵌套值的序列化坑；坐标由管线从句表自动带（引擎不必定引文规范）。**随 r7 交付走 parsed-2**，不污染 r6（format-only 基准已定）。

## 5. 网页侧对 §6.4 的事实供给（M1/蒸馏关系）

- 教师提示跑通后，**200–300 件金标即蒸馏训练集原料**（云旗舰产标→本地学生=用户既定路径，协调已更正"本地 9b 非违规"）；
- 同一提示模板即 M1 教师版——学生版只换模型加载，**schema 不变**是本管线的接口要求（parsed-2 契约稳定性）；
- `extract.py` 改学生加载的时机=要素金标验收通过后（引擎定）。

## 6. 引擎交付物清单（回给网页线的接口件）

1. 要素教师提示 v1（37 字段逐字段定义+三态+空值口径，依 schema 1.1.0）；
2. 输出 JSON Schema（含 evidence 句引用形态，与本文 §3.3 对齐或提出修改）；
3. 验收脚本（对 `elements.jsonl` 跑 §5.3 四指标）；
4. 版本登记规则（element-v1 升版判据）。
