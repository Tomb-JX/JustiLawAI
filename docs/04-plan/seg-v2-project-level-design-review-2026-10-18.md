# 从项目目标重新审查模块设计与阶段依赖（2026-10-18）

> 用户要求：跳出当前 seg-v2 链路，从主线目标、阶段目的和模块职责判断复杂度与偏差。只写评审分支；本次未修改共享规划、模块代码、数据或门禁，未启动模型调用。
>
> 本文对前两轮评审作优先级修正：[工程方案](./seg-v2-engineering-solutions-2026-10-18.md)的 EP-01–12 是解决手段目录，**不能整体变成阶段二首跑的前置任务**。此前对局部接口的分析仍然有效，但局部方案应接受本次目标层审查。

## 1. 判断：当前阶段存在明显的职责混合、依赖扩大和部分过早设计

**复杂度已经超过“第一份带质量数字的闭环结果”所需的程度。** 长期 M0–M6 的基本分工有理由；当前推进方式把数据供给、语义抽取、模型产标、独立评测与正式发布捆成一条串行流水线，使引擎首跑等待全量数据工厂完成。继续优化每一站，可能得到更完善的数据系统，而核心裁量方法仍未被行政数据验证。

判断依据：协调的 `stage-plan-v2 §0` 明确阶段目标为首跑并量化失败；同文 §2 却把全量 2,451 件 parsed-2、I-20 要素标注放在 M1、M4 之前，并称只有两项可并行。引擎现行门禁 v0.6 定义的 **B4 是 TF-IDF＋SVM/LR 文本基线**，其输入不依赖 36 要素标签。I-20 问题单也明确：缺要素参考阻断“字段准确率”与蒸馏，M1 仍可报告证据命中和丢弃率。这里的阶段依赖扩大有直接文档证据。

这不意味着可以绕过发布验收。应提出依赖规划修订，让开发性实验与正式发布各走相应条件；本评审没有自行执行新路线，也没有将 r6 或旧 regex 结果升级为标注真值。

## 2. 目标应该分成三个层级

| 层级 | 应回答的问题 | 所需证据 |
|---|---|---|
| 项目主线 | 给定处罚前可获得的案情，能否提供可追溯、有不确定性说明的定性/处罚辅助结果？ | 可用输入、有效规范、经过验证的预测与解释；长期还需正式评测及产品验收 |
| 阶段二 | 现有行政材料能否支持这条路线；首跑失败在哪；值得先改哪一环？ | 冻结开发样本、真实基线、逐环节诊断、实际输出与局限。允许结果差、允许关键指标暂不可测，须说明原因 |
| 模块任务 | 本模块为上述判断提供哪一项最小必要能力？ | 输入/输出、消费方、独立失败语义及退出证据；没有当前消费方的增强不自动升为前置 |

完整 36 字段本体、全库统一分区、全量高质量教师标签、多个专家融合、概率校准、共形区间、检索重排、生成式解释，都是不同层级与成熟度的工作。把它们同时排进“第一轮可跑”的定义，会推迟反馈并扩大调试变量。

原引擎设计的产品输入是案情/证据材料；当前主要数据是已形成处罚结果的公开文书。两者的事实完整度、叙述方式和结果泄漏风险并不相同。阶段二应先验证这种数据条件是否足够，不能默认只需把文书解析得更干净就能解决。

## 3. 五个需要修正的方向性偏差

### A. 将全量生产设为首跑前置，反馈回路过长

现规划要求先把供给链做到全量可交付，再获得 M1/M4 的首份数字。实际依赖要按消费者拆开：

- B4 文本基线需要隔离好的事实输入、可靠的历史处罚目标、事件分组与可用划分；无需等待 36 字段教师标签。
- M1 行政诊断需要合格的本人事实输入；没有独立参考仍可测格式、引用、丢弃及可观测性，准确率明确暂缺。
- M2 接口可用冻结的真实输入及显式未知状态检查；现实现已有三值逻辑与 `needs_review`，缺事实不要求先猜齐 36 项。
- 监督蒸馏、字段准确率与特征模型比较需要对应标签；这些依赖不能反向扩大为“所有开发首跑都不能做”。

**建议修订依赖为“合格开发切片驱动并行首跑”，全量与正式放行继续按原流程推进。** 合格切片仍须核对原文、本人、事实/答案隔离、处罚目标及事件去重；切片资格是明确的，不把未过内容检查的 r6 标签拿来训练。挑出的切片与总体差异要报告，不能将其表现推广到全库。

### B. 数据模块承担了过多研究与模型职责

网页线目前同时做源获取、文本治理、章节解释、处罚标签抽取、36 要素教师标注、仲裁、法律锚与质量报告。I-20 发生后，“接上现成管线”让教师任务继续并入来源链。技术复用合理，但责任边界已不清楚：来源是否可用，与教师是否正确，是两种失败；同一 parsed-2 版本号不能替两者作证明。

更合适的逻辑边界是：

| 逻辑职责 | 承诺 | 不应代为承诺 |
|---|---|---|
| 来源与案例准备 | 原文不变、出处可追、本人/事件可定位、输入视图及历史结果各有证据 | 模型标签已经正确、要素特征一定足够 |
| 抽取能力 | 从被允许的事实视图抽取当前契约，输出可验证候选及未知 | 源头没有写的事实、法律应然结论、自己给自己判准确率 |
| 教师与参考标注作业 | 在冻结案例上生产单独有版本的训练/开发参考及分歧记录 | 把来源格式通过等同于标签通过，或将模型共识称作人工真值 |
| 规范与预测 | 根据已知事实计算规范结论；根据训练数据预测历史结果的统计规律 | 修改原文事实以适应规范或预测 |
| 独立评测与报告 | 对特定能力、数据及版本给结论与局限 | 用管线内部“ok”数量替代外部正确性 |

这是职责划分，**不要求新增五个服务、五套 schema 或重搭框架**。现有代码、A/B 文件和 JSONL 可以复用，先把谁负责什么、各自产物证明什么写清楚即可。

### C. 标注工厂与 M1 正在出现重复能力建设

云教师和本地学生都要做“从事实中抽取同一本体”，差别主要在模型、用途和质量控制。现教师在网页链另建输入构造、数值/证据处理和合并；引擎 M1 又有自己的值解析、证据定位、字段投影。这些共通语义若分别演进，会产生两套“相同字段”的真实含义。

前一轮已见具体证据：网页 S3 能处理部分大写金额，引擎 `parse_amount` 在合成探测中对同类写法返回 null；教师缺组变未提及，学生存在无法解析即丢弃。两端的失败未形成同一种可对照报告。

建议只保留一套共享的**字段定义、归一化和最终证据验证规则**，教师/学生采用不同模型与运行策略。训练教师可更重，线上学生可更轻；两者仍须保持独立预测与评估隔离。代码共享不代表答案共享，测试集与实际处罚不得进入学生事实输入。

不必立即统一所有生产代码。先在一个开发切片上对拍两端输出和失败原因，找出真正需要抽成公共函数的部分，再迁移；避免为了统一再做一轮通用抽取框架。

### D. 优化指标逐渐替代了项目成效

| 当前常看指标 | 实际能证明 | 对主线仍缺的证据 |
|---|---|---|
| zones 铺满、JSON 合法 | 结构满足约束 | 本人事实是否保留，处罚答案是否泄漏 |
| decision 与 regex 的 F1 | 与一个参考分段的重叠程度 | 当前消费者需要的结果/依据能否可靠取得 |
| 引文坐标命中 | 片段存在且可回放 | 片段是否支持该字段，是否属于本人 |
| A/B 一致、C 未决少 | 当前流程内部的一致性和完成度 | 共同错误、参考独立性、字段实际正确性 |
| 标签覆盖条数 | 处理规模 | 标签是否改善 M1，特征是否改善 M4 |
| S3 硬失败率 | 当前规则查出的失败 | 未覆盖错误及端到端任务收益 |

这些指标都值得保留；它们应被消费需求解释。例如：decision F1 低只有在影响处罚目标获取、事实隔离或当前产品消费时才是首跑的关键阻塞，不能天然要求把全文六分类先做到完美。S3 门槛继续约束其原定的发布，不将局部合格率提升解释成裁量引擎已有增益。

### E. 将信息不足当成抽取或模型能力问题

协调分布文档显示，部分关键字段在网页正文中极少出现，新补法宝子集密度更高。这些是关键词代理，不能当真值；但足以要求先检验可观测性，而不是默认加仲裁或提高模型档次。

阶段二首先应回答两个不同问题：

1. **有证据的事实，系统能否可靠抽出？** 这是抽取问题。
2. **即使把公开文书中可得事实都抽对，它们对处罚预测有多大增益？** 这是数据和研究路线的可行性问题。

如果第二问没有增益，继续扩大 36 字段标注规模可能收益很低；若第二问有增益、第一问拖累，才优先改善 M1/蒸馏。CAIL 的既有 M1 笔记已记录要素方法未显著优于文本方法、信息不完整等现象；那是刑事数据上的历史结果，**不能外推成行政任务已经失败**，却足以说明行政领域需要先做比较而非先假定要素化必胜。

## 4. M0–M6 的职责合理性与阶段化处理

| 模块 | 长期职责判断 | 当前阶段需要的最小能力 | 现在可推迟的部分 |
|---|---|---|---|
| M0 知识与数据 | 规范、本体、案例资产都有必要；统一置于 M0 是概念归类，不宜成为所有事项的审批入口 | 当前切片所需规范版本、案例来源、本体版本可追溯 | 全来源全地域完整覆盖、通用资产平台 |
| M1 抽取 | 必要；主要负责有证据的事实及受控归类 | 首次行政输入诊断，共享字段含义和归一化，保留未知；与参考在同事件对照 | 全 36 字段均有足够正例、全量教师蒸馏、全面分组调用 |
| M2 规范 | 有清晰独立价值；应与历史事实抽取解耦 | 复用已实现能力，当前输入不足时显式 needs_review；只对依据齐全范围下结论 | 为缺事实案件伪造精确合法空间；为全省全版本泛化再做大扩建 |
| M3 开放性辨析 | 属于可检验增强；与 M1 的角色/行为/营利字段存在语义交界 | 先由 M1 标“明示事实/需辨析”，记录争议；主跑不自动叠加新辨析器 | 多轮采样与概率校准。原门禁已要求无下游增益则不上线 |
| M4 裁量预测 | 项目核心研究对象，当前得到直接反馈过晚 | 已定义 B4 文本基线；在有参考要素的同切片上加入一个简单特征基线作比较 | 四专家、堆叠、全套校准和共形保证同时开工 |
| M5 类案 | 产品及后期方法有价值；当前不是首个基线的必要依赖 | 若已有可靠检索即可展示真实来源；没有就明确未实现 | 为首跑先建关键词＋向量＋重排＋要素对齐全栈 |
| M6 解释与校验 | 核验必要；自由生成解释是后续能力 | 输出结构化结果、规范依据、输入缺失及限制；卡片可由确定性渲染生成 | 因果式措辞、反事实影响和信息价值排序；没有相应模型便不能编造 |

应把 **“核验结果”** 与 **“生成丰富解释”** 在 M6 内区分，前者不能省，后者不应阻塞首跑。同理，M4 的首轮不具备覆盖率保证时应明确未校准，不能将一般模型概率包装成最终产品承诺。

M1/M3 之间建议按“原文支持程度与推理性质”划界：M1 记录可回指的事实和按固定规则可得的归类；需要开放性权衡、类案或法律解释的判断交 M3。某字段既有事实值又有推断时要记录其来源性质，不能让 M1 先作结论、M3 再为相同结论做一轮生成。此建议需引擎确认语义，不在评审中直接改本体。

## 5. 必须显式区分两种结果

**公开文书的实际处罚是历史观察值；规范层计算的是在给定事实、适用规范下的可行或待确认结论。** 统计模型首先拟合前者，产品最终还需处理后者，两者不能混成一个“正确答案”。

若法律锚将历史处罚改成另一个合法数字，训练目标就被规范层重写；若再用这些标签评测，容易得到自洽而非独立的质量数字。既有 F5 是这一职责偏差在代码里的表现。正确做法是原观察值保留，规范冲突及适用性另报，对应训练资格按既有规则处理。

同样，处罚决定中“情节严重”“从轻”等既成认定可作为文书记载标签或待预测目标；在研究“处罚前事实能否预测结果”时，不能未经论证当作输入特征。变量在法律上相关，不等于部署时已知。字段清单应逐项写明其**使用时点、来源和消费任务**。

最终对模型能力的表述也应匹配数据：公开文书上的历史处罚预测结果，还不足以证明系统掌握完整案情条件下的规范裁量能力。应报告文书选择偏差、事实缺失和部署输入差异，不能靠更多处理层抹平这些限制。

## 6. 建议的阶段二最小闭环

建议用两个可并行的开发实验推进，正式交付另走原验收；这是对规划的修订建议，未在本会话执行。

```text
冻结合格开发切片：原文 / 本人 / 事件组 / 事实视图 / 历史处罚 / 元数据
       ├─ 事实文本 → 多数类参照及 B4 文本基线 → 历史处罚预测的首份数字
       └─ 事实视图 → M1 → 现有 M2 → 结构化结果、未知项及证据诊断

单独的参考标注子集 → M1 字段评估与一个特征基线
                         → 与同切片文本基线比较，决定后续投入

正式 r7 / 蒸馏扩量 → 保留原正式试点、I-20 及发布门禁
```

开发切片可从现有冻结原文候选中逐件建立，不承诺固定凑满数量；先写清 N、可用目标数、事件数、来源和排除原因。如果样本不足以估计性能，结果就是“暂不具备可靠估计条件”，仍然是有用的阶段结论。不得把挑出的富要素样本当作总体代表。

一个特征基线可以复用既定 B5 的简单配置；不新增“更容易过”的研究门禁。参考特征若来自模型，只称开发参考，不叫 B8 人工金标 Oracle。文本、参考特征、M1 特征三种输入尽量在同一事件切片与同一划分比较，避免把数据差异误认成模型增益。

M2 的未知与规范条件分开报告：知识未核定、输入缺失、角色待辨析不是同一种失败。三张卡片必须来自真实运行结果，未实现的类案、覆盖率、情节影响就显示未实现，不能用模板编出数值来补齐“五项输出”。卡片用于验证接口与可读性，不作为算法质量证明。

本阶段最有决策价值的结果是：

- 可用事实—处罚配对覆盖率及事件数：数据是否足以形成研究样本。
- M1 的证据/结构/丢弃诊断，以及有独立参考时的字段指标：抽取是否成为瓶颈。
- 文本、参考特征与抽取特征的同切片表现：结构化路线是否有增益，抽取损失有多大。
- M2 能明确处理与需要复核的比例：规范能力和信息缺失的边界。
- 总成本及失败去向：下一笔工作应投在信息补缺、抽取、模型还是根本任务定义。

没有独立参考就保留“字段准确率暂缺”；样本不够就不报显著提升。第一份质量报告允许包含这些否定结论，不以扩量或加模型把不可测包装成已达标。

## 7. 对前一轮 12 项工程建议的收缩

| 处理 | 内容 | 理由 |
|---|---|---|
| 立即保留 | EP-01/02 的契约真传递、非法状态隔离；EP-03 的坐标修复；最小必要的原响应/版本/费用留痕 | 已证实错误会破坏任何切片和质量结论，属于基础正确性 |
| 消费驱动接入 | EP-04/05 日期金额中文解析；EP-06 目标归属；EP-09 字段有效性与最终校验 | 从首跑实际失败例触发；先采用轻量适配，不先造通用时间/事件平台 |
| 收缩为规则记录 | EP-07 字段边界、EP-08 分区细化、EP-10 缺失原因、EP-12 回放 | 保留可验证契约和当前用例，不要求所有语义边界、全库可观测性及工具链一次建完 |
| 暂不作为前置 | 全 elements 分组调用、多后端解析器对照平台、完整 typed IR 普遍迁移、通用事件关系层、新工作流/状态平台 | 尚无当前消费者或净收益证据；前轮提出可选方案不等于必须实施 |

EP-11 的最小可靠写盘与有限重试要保留；SQLite 等具体索引方案可等恢复复杂度证明需要后再选。JioNLP/cn2an 能节省某些实现成本，无法回答项目路线是否有效，因此开源工具选型不应继续成为主线工作本身。

## 8. 架构决策与生效边界
