## 3. 硬伤与分歧（本轮新发现）

1. **event_key 跨源公式不一致——阻塞跨源事件合并（最高优先级新发现）**
   - web（`to_parsed1.py:65`）：机关｜首个日期（`\d年\d月`，可无日）｜**首个**金额；日期与金额皆无时返回**空串**（命中率 77.6%）。
   - pkulaw（`pkulaw_ingest.py:1338`）：机关｜首个**完整日期**（必须到日，缺则 '-' 占位）｜**金额集合**（先找"赌资/资金/款"前缀，逗号拼接排序集合，无则 '-'；**永不返回空**）。
   - 后果：同一事件两源各出一键、永不相等；跨源事件合并与 linked_ids 关联在现有键上不可用。修复方向：键生成收敛到 build 层单一实现（归一为"机关｜日期到日｜金额集合"），或废弃源端 event_key 由 build 统一重算。
2. **tier 枚举拼写不一致**：web "L2-只有结果" vs pkulaw "L2-结果only"（28 件）。
3. **quality.form 语义分歧**：web 复制 source_type 当 form；pkulaw 是真形态值。模型的分段提示需要形态感知（公示字段表 / 情节档次汇总 / 叙述 / 复议），web 必须补真值。
4. **extra 双写冗余**：两源都把 outcome 复制进 extra.outcome（web 4,989 / pkulaw 738），pkulaw 还复制了 quality。
5. **去重盲区**：web L1/L2 有 199 件无 doc_no_hash（其中 179 件公示）——按文号的跨源去重对它们无效。当前跨源文号交集为 0（暂无实际撞车），但该交集为 0 的前提是**两源文号规范化实现一致**（同写法应产出同哈希）——尚未抽查验证，应抽 1–2 例反查后才能把"无重复"当结论。

## 4. 各源还需哪些解析才能到达统一模型输入

**共同（S0）**：空白/全角归一；分段坐标一律由模型层 S2 统一生成（两源源端分段先验都不再进模型输入）。

**web 专属**：
1. 导航样板移除（L1/L2 16 件）；
2. 公示两种子形态的确定性归一：字段表式（17 词模板已实测：违法事实/处罚依据/处罚内容/处罚类别/案件名称/决定书文号/罚款金额/执法主体名称/决定书名称/处罚结果/证件类型/证件号/处罚决定日期/违法嫌疑人/当事人/一般/赌博…）→键值行；情节档次式（一般/从重/从轻/较轻/较重/严重）→结构化提示；
3. 复议本人解析（申请人→本人）——模型任务，规则不接；
4. outcome 未解析（warn 标记 1,121 件，全库口径）——模型重抽取目标。

**pkulaw 专属**：
1. 两栏管道表→键值归一（77 件）——机制与 web 公示字段表同类、词表不同，应做成同一个"模板词表驱动的表→键值"确定性组件、两套词表注册；
2. 逗号尾换行续接（67 件）；
3. authority→region 编码（729 件全缺）；
4. tier 拼写归一（28 件）；
5. articles_not_parsed 35 件——模型重抽取目标。

**修完即同构**。统一模型输入契约（建议）：

```
输入 = cleaned_text + offset_map + form 提示 + 源中立元数据
form 提示取 pkulaw 口径：叙述式-独立成篇 / 叙述式-结果栏内 / 字段式公示 / 情节档次汇总 / 叙述式-复议
分段先验（web 坐标、pkulaw 段文本）不进模型输入，降级为免人力分歧对照的参考集
```

## 5. 截止"模型批注"边界的问题台账（累计）

- **老账**（parse.py 时代产物，模型重抽取覆盖）：未分段 357（锚点定义性盲区）、定性句混入 132、证据/理由边界过度延伸 93、标签字/拼接尾 ~119、outcome 变体 90+（warn 1,121）、逗号尾 251（全库）、OCR 99。
- **新账**（本轮实测）：event_key 跨源公式不一致、pkulaw 分段坐标 0%、pkulaw 区划编码 0%、tier 拼写、web form 未填、extra 双写、199 件无文号盲区、复议本人 16.4%。
- **数据固有限制**（解析修不了，设计要绕）：公示行为日期缺失（仅 22% 有）；公示无文号；复议文书本身常不含处罚结果（outcome 仅 31.7%）——复议记录的标签必须经 linked_ids 关联到原处罚决定书取，因此**跨文书/跨源关联是刚需**，event_key 硬伤必须先修。
