## 0. 结论先说（v0.4 更正：法宝的定位，以及我上一版判反的地方）

**先按引擎侧的设计原文把角色钉死**（三处，互相印证）：

| 出处 | 原文 | 含义 |
|---|---|---|
| [文书体系研究](../05-research/gambling-documents-and-retrieval.md) §2 | 文书 1「公安行政处罚决定书（赌博，个人）」→ **"行政金标主力：M4 训练集与测试集"，P0** | **主力是公安行政处罚决定书**，不是判决书 |
| 同上 §2 | 文书 4/5「行政一审/二审判决书」→ "金标（**测试集中占比 ≤ 50%**）+ 复核标签 + M6 说理素材"，P0 | 判决书是**受限的补充**，不是主力 |
| 同上 §2 结论 | "行政金标的主力（1、2、3）**都不在裁判文书网**，要靠发现层的执法公示和北大法宝" | 主力只能从公开网页与法宝找 |
| [引擎方案](../02-design/gambling-discretion-engine.md) §6 | "公安机关公开的处罚决定、执法公示 → 处罚结果，**事实通常较简略** → 主要用于分布校验" | **警告过**：公开的"执法公示"类事实贫乏 |
| [门禁](./../05-research/sota-baselines-and-gates.md) §7 | T-admin"来源构成与总体一致；复议/诉讼来源 ≤ 50%" | 判决书（诉讼来源）不能独占测试集 |

**这两处看似矛盾（"决定书是主力" vs "公开的决定书事实简略"），其实分的是两类不同的东西**——这正是必须梳理清楚的地方：

| 类别 | 形态 | 有没有事实 | 在项目里的角色 | 现实来源 |
|---|---|---|---|---|
| **A 叙述式公安行政处罚决定书** | "现查明：×年×月×日…以打麻将方式赌博，现场查获赌资 3,078 元…" | ✅ 有 | **行政金标主力（M4 训练集与测试集）** | **公开网页收割**（叙述式 441 件，河北/新疆集中）+ 合作案卷（搁置）|
| B 字段式决定书 / 执法公示 | 表格：文号/被处罚人/事由/依据/结果/日期 | ❌ 无 | 结果-only 层（分布校准、省份普查、T-time 计数） | 公开网页收割的字段式公示 144 件；**法宝行政执法库（本次实样）** |
| C 法院判决书 | 经审理查明 + 本院认为 + 判决结果（法宝已分段） | ✅ 有（复述原处罚） | 金标**补充**（测试集 ≤50%）+ **复核标签** + M6 说理素材 + 行刑边界 | **法宝司法案例库**（学院账号长期）、裁判文书网、采购 |
| D 复议决定书 | 事实 + 原处罚 + 复议结论 | ✅ 有 | 复核标签（P1）；T-admin 构成的复议侧 | 公开网页 73 件；法宝是否收录待试检（R2） |
| E 不予处罚决定书 | 不处罚的理由 | ✅ 有 | 下界案例（G3.2 单独达标）**最稀缺** | 全网 0 件；法宝"不决字"定向是唯一线索 |

**所以上一版（v0.3）把"判决书=行政金标主力"是错的**：判决书量最大（司法案例库约万份级）但它是**诉讼来源**，偏争议、偏重罚，门禁明确限制在测试集的 50% 以内 → 它是"量大但受限的补充"。**真正的主力是 A 类（叙述式处罚决定书），而法宝行政执法库给不了 A 类——它导出的只是 B 类摘要**（本次实测：7 行字段、无违法事实、无行为日期）。

**由此法宝在项目里的准确定位是三条**：

1. **结果-only 层的最大来源**（B 类摘要）：省份普查、T-time 计数、新法/旧法分片、分布校准——目录还带**法律版本**（"…(2012修正)第70条" / "(2025修订)第82条"），是**唯一能按法条版本大规模分片**的来源。不进金标。
2. **反查原文的索引（把 B 升级成 A 的通道）**：法宝目录给了「执法机关 + 发文案号」，用它去原发布机关（县/区公安局公示栏）检索即可取到含事实的全文——这正是引擎在协作记录里给的用法①，也是[A 类主力]扩容的现实路径（待验证：县级公示是否可检、命中率多少）。
3. **判决书补充（C 类）**：学院账号长期权限、量足够（行政一审 4,986 / 二审 6,604），用于复核标签、被撤销/变更的原处罚、M6 说理素材；不占三天窗口。

其余要点（与 v0.3 一致的实测结论）：

- **MCP 只能计数与抽样**：20 条/次不能翻页，返回正文是节选（`Ascertain` 中位 302 字、367 条缓存里 79 条为空）→ 批量正文必须走网页导出。
- **判决书含真名**（律师、法官也在）→ 脱敏 + R6 必做；执法公示的人名是遮挡过的。
- **2026 新案**：判决书 2026 年审结仅 12 份 → T-time（≥50 件）只能靠 B 类（法宝执法库 2026 年"赌博"8,292 条）+ 公开网页（行为日期在 2026 年的 162 件）。
- **采购 C′**：Q1 行政（~3,970 份判决）与法宝司法案例库重叠 → 行政部分建议不采购；Q2 刑事 19 万份 v1 用 CAIL 4,133 件已够 → 暂缓。（A 类主力不受采购影响，它靠公开网页。）

## 1. 实样解剖（三种形态到底给了什么）

### 1.1 目录列表 `.xls`（行政执法库："北大法宝V6-行政执法-行政执法字段表单"）

- 形态：BIFF8 二进制。读取用 **xlrd 直读**（`pip install xlrd`）；`pkulaw_xls2csv.ps1`（Excel COM）只作兜底——COM 在无人值守时会因受保护视图或残留进程卡死（实测卡死过一次，孤儿 EXCEL.EXE 占 468MB）。
- 结构：第 1 行子库名；第 2 行**搜索条件 + 下载时间**（数据卡 G1.4 的溯源信息）；第 3 行字段名；数据行；末尾版权与二维码页脚（按标记截断）。
- 字段（11 列）：序号 / 标题 / 执法机关 / 发文案号 / 公布日期 / 行政相对人 / **执法依据（带 2012修正 / 2025修订 版本字样）** / 处罚种类 / 执法地域 / 原文链接 / **罚没总金额（万元）**。
- 实测 8 行：`罚没总金额` 0.03 万 = 300 元；拘留档为 0；`序号` 形如 `_1`（不作主键）。

### 1.2 文书 `.doc`（行政执法库的处罚决定书公示）

- 真 OLE2 二进制；`antiword` 取文本完好（表格保成 `|字段|值|` 行），失败退 Word COM。
- 内容 = 元数据块 10 项 + 决定表 7 行（文号/被处罚对象/处罚事由/处罚依据/处罚结果/处罚决定日期/处罚机关）+ 页脚（版权 + 原文链接）。
- 引证码（`FBM-CLI.ALE.47644244`）在**文件名**里 → 稳定主键。人名已遮挡。

### 1.3 目录列表 `.xls`（司法案例库，另一套列）

- 字段 9 列：序号 / 标题 / 审理程序 / **案由（层级串）** / 文书类型 / 审理法院 / **案件字号** / 审结日期 / 省份（填的是法院全名）。
- **实测噪声率 3/7 ≈ 43%**（检索式是"全文：赌博"，命中的是民间借贷、建设工程纠纷）→ 司法案例库检索**必须以案由为主**。
- 全部为 2026 年审结 → 法宝司法案例库更新到 2026 年。

### 1.4 司法案例库的判决书本体（MCP 实测，比目录表丰富得多）

法宝司法案例记录有 29 个字段，**已经按判决书结构分好段**：

| 法宝字段 | 内容 | 对应 data-spec |
|---|---|---|
| `Ascertain` | **经审理查明**（含原处罚的完整复述：拘留日数、罚款额、收缴赌资、前科） | `text_facts` + `outcome`（原处罚） |
| `Identified` | **本院认为**（法院审查意见、情节认定） | `text_review` + `stated_circumstances` |
| `RefereeResult` | **判决结果**（驳回=维持 / 撤销 / 变更 / 确认违法） | `review.result`、`review.changed_outcome` |
| `RefereeBasis` | 裁判依据法条 | `outcome.articles`（**须剔除程序条文**） |
| `TrialAfter` / `PlaintiffClaims` / `DefenseViewpoint` | 审理经过 / 原告诉称 / 被告辩称 | 不入模型输入，留作出题与核对 |
| `Category` / `CaseGrade` / `CaseFlag` / `Court` / `LastInstanceDate` / `CriminalPunish` | 案由层级 / 参照级别 / 案号 / 法院 / 审结日期 / 法宝主题标签 | `region`、`doc_no`、`court`、筛选 |

实测样例（李四军案，法宝引证码 `…a25051f3…`）：`outcome` 提取到「拘留并处罚款 / 12 日 / 1900 元 / 治安管理处罚法第七十条 / 旧法 / 情节严重·从重」，`review.result=维持`，`behavior_date=2017-10-30`，`decision_date=2017-10-30`，`region=湖南省`。

**注意两处陷阱**：① `RefereeBasis` 里混着法院的程序条文（行政诉讼法第六十九条、治安管理处罚法第九十三条举证规则）——直接当 `outcome.articles` 会污染标签，代码已改为优先从事实段"根据《…》第X条…作出处罚决定"里取；② 判决书的"查明事实"是**诉讼后**的版本，与处罚决定书原文可能有出入，且被撤销/变更的原处罚不是正确答案 → `review.result` 必须记录（规格 §1.4 已要求）。

口径说明：法宝的"全文"与裁判文书网不完全同义（含法宝主题标签），且二审总量高于一审提示有重复或含再审，**精算须靠网页导出的目录表**（按案号去重）。精度：法宝样本以公安处罚诉讼为主，但"全文赌博"仍有管辖条款噪声，须沿用[文书体系研究](../05-research/gambling-documents-and-retrieval.md) §5 的本地降噪规则（排除只命中《公安机关办理行政案件程序规定》第十条的；要求出现"参与赌博/为赌博提供条件/赌资/赌具/聚众赌博"之一）。

## 3. 真正需要的形式与内容（需求侧，不拟合样本形式）

**目标不是"把法导出转成 JSON"，而是凑齐四件套：** 事实段（`text_facts`）+ 行为日期 + 处罚结果精确标签 + 情节认定。四件套缺哪个，那条记录就只能降级使用。

三类子库分工（法宝内部也是三条不同的数据线，别混为一谈）：

| 子库 | 给什么 | 在项目里的位置 | 优先级 |
|---|---|---|---|
| **司法案例库（法院判决）** | 行政判决：事实 + 原处罚 + 审查结论，法宝已分段 | **金标补充**（非主力）：诉讼来源受门禁 §7"≤50%"约束；用于复核标签、被撤销/变更的原处罚、M6 说理素材、行刑边界 | **高**——学院账号**长期权限**，按周节奏导，不占三天 |
| **行政执法库**（处罚决定书公示） | 处罚结果 + 元数据 + 法律版本，**无事实**（B 类摘要） | ①**结果-only 层**（D6）：省份普查、T-time 计数、新法/旧法分片、分布校准；②**反查原文的索引**（机关+文号 → 原公示页 → A 类全文） | 三天窗口内把目录导全（便宜）；反查通道待验证 |
| 司法案例库-复议？ | 复议决定：事实 + 原处罚 + 复议结论 | 若收录：复核标签（P1）+ T-admin 复议侧 | 三天内试检是否收录 |
| 法律法规库 / 地方法规库（R4/R5） | 规范原文（含省级裁量基准） | 清 G0.1 待核验；法律组录 YAML，不走案例管线 | 顺手导 |
| 检察文书库（不起诉决定书） | 行刑边界的负样本 | M2"是否移送"判断的补充 | 可选（MCP 75 分/次） |

**注意：A 类主力（叙述式处罚决定书全文）法宝给不了**，它来自公开网页收割（发现层，叙述式 441 件）与合作案卷（搁置）；法宝在这条线上只能当**索引**（反查通道）。

**导出形式的选择原则**（形式服从内容）：
- **每个检索式先导"目录列表 xls"**——它是索引 + 元数据 + 结果标签，几乎不耗时间，且本身就是有用的结果-only 数据。
- 正文按目录挑着导。**先试检 1 份"纯文本"导出**：若纯文本已含元数据块与决定表，后续优先导纯文本（省掉 .doc 解析与 antiword 依赖）；PDF 只在扫描件场景用（`harvest/ocr.py` 已有 OCR）。
- 解析器不绑定文件形式：`doc_to_text()` 支持 antiword / Word COM / docx / txt 四种取文本方式，解析按"标签 → 值"抽取，换排版只影响抽取规则，不影响字段映射与产出。

## 4. 数据化链路

```
法宝网页（人工检索/勾选/官方导出，不写抓取脚本）
   │  【行政执法库】目录 .xls ──xlrd 直读──┐        【司法案例库】目录 .xls ──xlrd 直读──┐
   │  处罚决定书 .doc/.docx/.txt ──→ inbox/pkulaw/… │      判决书导出 Word/文本 ──→ inbox/… │
   │            │                                  │              │                    │
   │      import_manual.py（入台账 channel=C、算哈希、分配 id）  │      （同上）            │
   ▼            ▼                                  ▼              ▼                    │
pkulaw_ingest.py catalog                      pkulaw_ingest.py catalog                  │
   → worklist.csv（工作清单 + 已下全文标记；按法条/省/年份/案由统计）  ←── 同一套解析       │
   ▼                                                                                     │
pkulaw_ingest.py docs（处罚决定书公示）        pkulaw_ingest.py cases（判决书）           │
   → admin_cases.jsonl（有事实=金标候选）         → pkulaw_cases.pre_deid.jsonl（行政）    │
   → admin_outcomes_only.jsonl（无事实=D6）       → pkulaw_crim.pre_deid.jsonl（刑事）     │
   → SHA256SUMS + stats                          → 按 pkulaw_id 去重 + stats              │
                                                          │
                        脱敏（D1–D5 拍板后）+ R6 扫描 ←── 判决书含**真名**，必做
                                                          ▼
                                                  交付引擎（data-spec v0.1）
```

命令（仓库根目录）：

```bash
# 依赖：pip install xlrd（读 .xls）；没有 xlrd 的机器先用 pkulaw_xls2csv.ps1 转 CSV，再喂 --xls 指向 CSV
# 1) 目录 → 工作清单与统计（行政执法库与司法案例库共用）
python research/discretion/collect/pkulaw_ingest.py catalog \
    --xls "inbox/pkulaw/R1/【北大法宝】目录列表.xls" --out $JUSTILAW_DATA_DIR/pkulaw/R1
# 2) 行政执法库的处罚决定书公示 → 结果-only 层
python research/discretion/collect/pkulaw_ingest.py docs --docs inbox/pkulaw/R1/docs \
    --worklist $JUSTILAW_DATA_DIR/pkulaw/R1/worklist.csv --out $JUSTILAW_DATA_DIR/admin
# 3) 司法案例库的判决书 → 金标候选（MCP 响应 JSON / JSONL / 目录都可作输入）
python research/discretion/collect/pkulaw_ingest.py cases --src inbox/pkulaw/cases \
    --out $JUSTILAW_DATA_DIR/admin
```

**主键与去重**：判决书用原文链接里的 `pfnl` 哈希；处罚决定书公示用文件名里的法宝引证码（`FBM-CLI.…`），无引证码时退文号。同一 URL 重复下载视为同一条。
**事件分组**（门禁 §7 防泄漏）：同机关 + 同决定日期 + 文号/案号连号多为同一次查处（实样 00289/00290 即两人同一次），脚本输出 `event_hint` 供划分时聚合。
**质量门**：脚本按组统计 `outcome_only` 占比、原处罚类型分布、法律版本分布、`信息完整（有金额+结果）`件数与 `parse_warnings`（facts_missing / outcome_not_parsed / articles_not_parsed / decision_date_not_found / fine_mismatch / not_in_manifest），交付前人工看一遍。

## 5. 检索与导出计划（按权限性质分两条节奏）

**前提**：司法案例库 = 学院账号**长期权限**（不急，按日限额周节奏导）；行政执法库 = 本次 **3 天**权限（要抢时间）；MCP 积分 8,300（11-15 过期，只用于计数与定向）。

**A. 3 天窗口内必须做完（行政执法库 + 试检）**

| 顺序 | 做什么 | 为什么 |
|---|---|---|
| A1 | **试检复议决定书是否收录**（R2） | 含事实 + 复议结论，T-admin 构成的另一半；只在窗口内能查 |
| A2 | **新法分片目录**：`执法依据=2025修订 第82条` 全量导目录 xls | T-time ≥50 件的唯一大规模来源（判决书 2026 年只有 12 份） |
| A3 | **不予处罚定向**：文号含"不决字"（MCP `documentNo`）+ 标题/关键词导目录 | G3.2 要求该类单独达标，目前全网 0 件 |
| A4 | **省域普查目录**：R1 按"执法地域"分省导目录 xls | 定量回答目标省（数据收集计划 §2 待决策项） |
| A5 | R4/R5 规范文件（法律组）+ 每条检索式记录命中数/导出数/日期（数据卡 G1.4） | G0.1 待核验清零 |

**B. 长期节奏（司法案例库，不占 3 天；定位是"补充与复核标签"，不是主力）**

| 顺序 | 做什么 | 为什么 |
|---|---|---|
| B1 | **先导 1 份行政判决正文**（Word / 纯文本各 1），确认导出是否含 `Ascertain`/`Identified`/`RefereeResult` 分段与元数据块 | 决定解析走"法宝分段字段"还是"自切原文"（两条路的解析器不同） |
| B2 | 按**案由**导目录：行政（治安管理处罚/行政处罚类）× 省，统计各省件数与年份分布 | 目标省决策 + 工作清单；实测全文检索噪声 43% |
| B3 | 按省分批导正文（受日限额约束，排周节奏），优先"被撤销/变更"与"含金额"的案件 | 复核标签 + M6 说理素材；判决书补充（不追求全量——测试集只能用 ≤50%） |
| B4 | 刑事判决（赌博罪/开设赌场罪）目录与正文 | 行刑边界与后续刑事扩展；v1 不阻塞 |

**C. 与主力线（A 类全文）的衔接——法宝反查通道（待验证，价值最高）**

法宝执法库目录已给出「执法机关 + 发文案号」，用它去原发布机关（县/区公安局公示栏）检索取全文，可把 B 类结果-only 记录**升级成 A 类含事实案例**，直接补金标的信息完整度（现为 25%）。验证方法：任取 20 条法宝目录行，用「文号 + site:gov.cn」检索，统计能取到含"现查明/违法事实"的全文的比例；命中率可接受就纳入发现层/数据链路的例行流程。

**采购（C′）的对账**：Q1 行政（~3,970 份）与法宝司法案例库（约 1.1 万份，长期权限）重叠 → **建议行政不采购**；Q2 刑事 19 万份用于刑事扩展，v1 用 CAIL 4,133 件已够锚点 A2 → **建议暂不下单**，把预算留给 2026 新案与不予处罚类的定向补采。是否下单仍由用户与指导老师决定（指导老师需确认来源合规）。

**额度纪律**：每批导出前记 `检索式 + 命中数 + 拟导出数`；导出后目录 xls 与正文文件数核对一致；导出文本**不二次分发**（手册 §5）。

## 7. 风险与合规

- **二次分发**：导出文本只存仓库外 `$JUSTILAW_DATA_DIR`，仓库只提交脚本与台账哈希（手册 §5）。
- **账号与权限**：学院账号已绑定**司法案例库**权限（长期）；**行政执法库**是购买的三天权限——两者的条款与导出额度不同，批量导出前先确认限额（待确认 #2、#8）。
- **判决书含真名**：司法案例库的判决书是**未脱敏**的（实测样本含当事人真名、律师姓名、法官姓名），与执法公示的"陈\*英"不同 → 必须走脱敏 SOP + R6，交付前 `deidentified` 一律 false。
- **结果-only 层不得混入金标**：脚本按事实段自动分流，`admin_outcomes_only.jsonl` 与 `admin_cases.jsonl` / `pkulaw_cases.pre_deid.jsonl` 分开落盘；引擎侧按 D6 只用于分布与计数。
- **诉讼来源占比**：判决书全部是诉讼来源，门禁 §7 要求测试集中复议/诉讼合计 ≤50% → 测试集构成必须混入公开网页与执法公示来源。
- **积分纪律**：MCP 积分与引擎共用（余额 8,300，11-15 过期）；本次普查用 225 分，全部经共用调用层记账（`research/eval/pkulaw_mcp/`，`--workstream data`）。
