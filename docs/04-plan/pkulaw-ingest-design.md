## 0. 结论先说（v0.4 更正：法宝的定位，以及我上一版判反的地方）

**先按引擎侧的设计原文把角色钉死**（三处，互相印证）：

| 出处 | 原文 | 含义 |
|---|---|---|
| [文书体系研究](../05-research/gambling-documents-and-retrieval.md) §2 | 文书 1「公安行政处罚决定书（赌博，个人）」→ **"行政金标主力：M4 训练集与测试集"，P0** | **主力是公安行政处罚决定书**，不是判决书 |
| 同上 §2 | 文书 4/5「行政一审/二审判决书」→ "金标（**测试集中占比 ≤ 50%**）+ 复核标签 + M6 说理素材"，P0 | 判决书是**受限的补充**，不是主力 |
| 同上 §2 结论 | "行政金标的主力（1、2、3）**都不在裁判文书网**，要靠发现层的执法公示和北大法宝" | 主力只能从公开网页与法宝找 |
| [引擎方案](../02-design/gambling-discretion-engine.md) §6 | "公安机关公开的处罚决定、执法公示 → 处罚结果，**事实通常较简略** → 主要用于分布校验" | **警告过**：公开的"执法公示"类事实贫乏 |
| [门禁](./../05-research/sota-baselines-and-gates.md) §7 | T-admin"来源构成与总体一致；复议/诉讼来源 ≤ 50%" | 判决书（诉讼来源）不能独占测试集 |

**这两处看似矛盾（"决定书是主力" vs "公开的决定书事实简略"），其实分的是两类不同的东西**——这正是必须梳理清楚的地方：

| 类别 | 形态 | 有没有事实 | 在项目里的角色 | 现实来源 |
|---|---|---|---|---|
| **A 叙述式公安行政处罚决定书** | "现查明：×年×月×日…以打麻将方式赌博，现场查获赌资 3,078 元…" | ✅ 有 | **行政金标主力（M4 训练集与测试集）** | 公开网页收割（叙述式 441 件）+ **法宝行政执法库的叙述式省份**（浙江 73,583 / 河北 35,626 / 湖南 13,770 条"现场查获赌资"命中）+ 合作案卷（搁置）|
| B 字段式决定书 / 执法公示 | 表格：文号/被处罚人/事由/依据/结果/日期 | ❌ 无 | 结果-only 层（分布校准、省份普查、T-time 计数） | 公开网页收割的字段式公示 144 件；法宝行政执法库的**表格形态省份**（如上海，"现场查获赌资"命中仅 15 条） |
| C 法院判决书 | 经审理查明 + 本院认为 + 判决结果（法宝已分段） | ✅ 有（复述原处罚） | 金标**补充**（测试集 ≤50%）+ **复核标签** + M6 说理素材 + 行刑边界 | **法宝司法案例库**（学院账号长期）、裁判文书网、采购 |
| D 复议决定书 | 事实 + 原处罚 + 复议结论 | ✅ 有 | 复核标签（P1）；T-admin 构成的复议侧 | 公开网页 73 件；法宝是否收录待试检（R2） |
| E 不予处罚决定书 | 不处罚的理由 | ✅ 有 | 下界案例（G3.2 单独达标）**最稀缺** | 全网 0 件；法宝"不决字"定向是唯一线索 |

**两个必须纠正的判断（我都先判错过，记录在此以免重犯）**：

1. ~~"判决书=行政金标主力"~~（v0.3 的错）：判决书量最大，但它是**诉讼来源**，偏争议、偏重罚，门禁限制在测试集 50% 以内 → 它是"量大但受限的补充"，不是主力。主力是 **A 类（叙述式处罚决定书）**。
2. ~~"法宝行政执法库给不了 A 类，只有摘要"~~（v0.1–v0.4 的错，**源于 n=2 归纳**）：我只有 2 份**上海**样本（同机关、同日、同形态），却断言了全库。**实测推翻**——法宝执法库的检索按**正文全文**做，用只可能出现在叙述式事实段的短语检索：
   | 检索短语 | 命中总数 |
   |---|---|
   | `现查明` | **8,256,962** |
   | `现场查获赌资` | **359,148**（首条样本为"龙口市公安局公安行政处罚决定书(龙公（开）行罚决字〔2025〕437号)"） |
   | `现场查获赌资` + 河北省 | **35,626**（阜城县、武强县派出所的叙述式决定书） |
   → **法宝行政执法库并存两种形态**：表格形态（上海：10 个元数据字段 + 7 行决定表，无事实）与**叙述式全文形态**（浙江/山东/河北/湖南/内蒙等：含"现查明…现场查获赌资…以上事实有…"）。**后者就是 A 类主力**——3 天窗口的最大价值正在于此。
   → **方法论教训**：n=2、单一来源、单一形态的样本只能支撑"该样本如此"，不能支撑"全库如此"。下规模性结论前先做**计数型勘察**（MCP 返回的 `total` 就是现成工具，见 §1.5 的分省表）。

**由此法宝在项目里的准确定位是四条（v0.5 修正）**：

0. **叙述式正文：索引里有，网页端也确实能下载到（2026-10-16 用户实测已证）**。用户从网页下载的 6 份执法库文书 + 1 个司法案例批量包（7 份判决书）证明了三层：
   - **索引层**：短语级证伪测试——`以打麻将的方式进行赌博` 命中 153,315，同词形乱语 0 → 库内存的是逐字正文；
   - **网页层（关键，已验证可下载）**：下载到的文书里含"现查明…现场查获赌资…"全文（湖南屈原管理区 屈公（青）决字[2023]第0267号、河北阜城 阜公（崔）行罚决字〔2018〕0459号），也有整段案情被塞进"处罚结果"栏的形态（浙江嵊泗、湖北咸丰）→ **法宝能交付含事实的正文，只是"落位"分省不同**；
   - **通道层**：MCP 只有 `search_enforcement`（目录 + 正文链接），**批量正文走网页导出**——这不妨碍结论，因为网页导出是通的。
   → **法宝执法库 = A 类主力来源**；三天窗口优先按省导叙述式省份的决定书全文，上海式纯摘要记录只导目录（结果-only 层）。判决书批量包另有第四种形态（结构化头 + 小节标题全文，见 §1.5）。

1. **结果-only 层的最大来源**（B 类摘要）：省份普查、T-time 计数、新法/旧法分片、分布校准——目录还带**法律版本**（"…(2012修正)第70条" / "(2025修订)第82条"），是**唯一能按法条版本大规模分片**的来源。不进金标。
2. **反查原文的索引（把 B 升级成 A 的通道）**：法宝目录给了「执法机关 + 发文案号」，用它去原发布机关（县/区公安局公示栏）检索即可取到含事实的全文——这正是引擎在协作记录里给的用法①，也是[A 类主力]扩容的现实路径（待验证：县级公示是否可检、命中率多少）。
3. **判决书补充（C 类）**：学院账号长期权限、量足够（行政一审 4,986 / 二审 6,604），用于复核标签、被撤销/变更的原处罚、M6 说理素材；不占三天窗口。

其余要点（与 v0.3 一致的实测结论）：

- **MCP 只能计数与抽样**：20 条/次不能翻页，返回正文是节选（`Ascertain` 中位 302 字、367 条缓存里 79 条为空）→ 批量正文必须走网页导出。
- **判决书含真名**（律师、法官也在）→ 脱敏 + R6 必做；执法公示的人名是遮挡过的。
- **2026 新案**：判决书 2026 年审结仅 12 份 → T-time（≥50 件）只能靠 B 类（法宝执法库 2026 年"赌博"8,292 条）+ 公开网页（行为日期在 2026 年的 162 件）。
- **采购 C′**：Q1 行政（~3,970 份判决）与法宝司法案例库重叠 → 行政部分建议不采购；Q2 刑事 19 万份 v1 用 CAIL 4,133 件已够 → 暂缓。（A 类主力不受采购影响，它靠公开网页。）

## 1. 实样解剖（三种形态到底给了什么）

### 1.1 目录列表 `.xls`（行政执法库："北大法宝V6-行政执法-行政执法字段表单"）

- 形态：BIFF8 二进制。读取用 **xlrd 直读**（`pip install xlrd`）；`pkulaw_xls2csv.ps1`（Excel COM）只作兜底——COM 在无人值守时会因受保护视图或残留进程卡死（实测卡死过一次，孤儿 EXCEL.EXE 占 468MB）。
- 结构：第 1 行子库名；第 2 行**搜索条件 + 下载时间**（数据卡 G1.4 的溯源信息）；第 3 行字段名；数据行；末尾版权与二维码页脚（按标记截断）。
- 字段（11 列）：序号 / 标题 / 执法机关 / 发文案号 / 公布日期 / 行政相对人 / **执法依据（带 2012修正 / 2025修订 版本字样）** / 处罚种类 / 执法地域 / 原文链接 / **罚没总金额（万元）**。
- 实测 8 行：`罚没总金额` 0.03 万 = 300 元；拘留档为 0；`序号` 形如 `_1`（不作主键）。

### 1.2 文书 `.doc`（行政执法库的处罚决定书公示）

- 真 OLE2 二进制；`antiword` 取文本完好（表格保成 `|字段|值|` 行），失败退 Word COM。
- 内容 = 元数据块 10 项 + 决定表 7 行（文号/被处罚对象/处罚事由/处罚依据/处罚结果/处罚决定日期/处罚机关）+ 页脚（版权 + 原文链接）。
- 引证码（`FBM-CLI.ALE.47644244`）在**文件名**里 → 稳定主键。人名已遮挡。

### 1.3 目录列表 `.xls`（司法案例库，另一套列）

- 字段 9 列：序号 / 标题 / 审理程序 / **案由（层级串）** / 文书类型 / 审理法院 / **案件字号** / 审结日期 / 省份（填的是法院全名）。
- **实测噪声率 3/7 ≈ 43%**（检索式是"全文：赌博"，命中的是民间借贷、建设工程纠纷）→ 司法案例库检索**必须以案由为主**。
- 全部为 2026 年审结 → 法宝司法案例库更新到 2026 年。

### 1.4 司法案例库的判决书本体（MCP 实测，比目录表丰富得多）

法宝司法案例记录有 29 个字段，**已经按判决书结构分好段**：

| 法宝字段 | 内容 | 对应 data-spec |
|---|---|---|
| `Ascertain` | **经审理查明**（含原处罚的完整复述：拘留日数、罚款额、收缴赌资、前科） | `text_facts` + `outcome`（原处罚） |
| `Identified` | **本院认为**（法院审查意见、情节认定） | `text_review` + `stated_circumstances` |
| `RefereeResult` | **判决结果**（驳回=维持 / 撤销 / 变更 / 确认违法） | `review.result`、`review.changed_outcome` |
| `RefereeBasis` | 裁判依据法条 | `outcome.articles`（**须剔除程序条文**） |
| `TrialAfter` / `PlaintiffClaims` / `DefenseViewpoint` | 审理经过 / 原告诉称 / 被告辩称 | 不入模型输入，留作出题与核对 |
| `Category` / `CaseGrade` / `CaseFlag` / `Court` / `LastInstanceDate` / `CriminalPunish` | 案由层级 / 参照级别 / 案号 / 法院 / 审结日期 / 法宝主题标签 | `region`、`doc_no`、`court`、筛选 |

实测样例（李四军案，法宝引证码 `…a25051f3…`）：`outcome` 提取到「拘留并处罚款 / 12 日 / 1900 元 / 治安管理处罚法第七十条 / 旧法 / 情节严重·从重」，`review.result=维持`，`behavior_date=2017-10-30`，`decision_date=2017-10-30`，`region=湖南省`。

**注意两处陷阱**：① `RefereeBasis` 里混着法院的程序条文（行政诉讼法第六十九条、治安管理处罚法第九十三条举证规则）——直接当 `outcome.articles` 会污染标签，代码已改为优先从事实段"根据《…》第X条…作出处罚决定"里取；② 判决书的"查明事实"是**诉讼后**的版本，与处罚决定书原文可能有出入，且被撤销/变更的原处罚不是正确答案 → `review.result` 必须记录（规格 §1.4 已要求）。

### 1.5 法宝行政执法库的**两种形态**（2026-10-16 计数勘察，v0.5 新增）

同一个库里并存两种形态，**分省不同**，处理方式完全不同：

| 形态 | 长什么样 | 事实 | 省份（实测） | 解析路径 |
|---|---|---|---|---|
| **叙述式·独立成篇** | 元数据块后直接是决定书原文（含"被处罚人××，男…现查明…以上事实有…根据…现决定…"） | ✅ 有 | 湖南屈原管理区、河北阜城（本次实样） | `parse_doc()` → **A 类** |
| **叙述式·结果栏内** | 决定表的"处罚结果"单元格被塞进整段案情（跨多格长文，含"主要违法事实：…""行政处罚的种类和依据：…"） | ✅ 有 | 浙江嵊泗、湖北咸丰（本次实样） | `parse_doc()`（跨格合并）→ **A 类** |
| 字段式公示 | 10 个元数据字段 + 7 行决定表，结果栏只有结果本身（"罚款三百元"／"收缴赌资 210 元，罚款 200 元"） | ❌ 无 | 上海长宁、南昌新建 | `parse_doc()` → **B 类（结果-only）** |

**第四种形态：判决书（司法案例批量导出，实测 7 份包）**——结构化头（案由/案号/审理法官/文书类型/**审理法院**/审结日期/案件类型/审理程序/权责关键词/**刑罚摘要**）+ 正文按**独占一行的小节标题**切分（当事人 / 审理经过 / 检察院指控｜本院查明 / 被告辩称 / 本院认为 / 裁判结果 / 落款）→ `parse_judgment_doc()`；刑事判决另出 `criminal`（主刑/月数/缓刑/罚金，实测"有期徒刑一年四个月"=16 个月），民事判决标 `in_scope=False` 单独存放（实测 3/7 是民事噪声，与目录表 43% 一致）。

**分省计数（工具：MCP `search_enforcement` 的 `total`，短语"现场查获赌资"只出现在叙述式事实段）**：

| 省份 | 命中 | 含义 |
|---|---|---|
| 全国 | 359,148 | 库里叙述式赌博决定书的总体量级 |
| 浙江 | **73,583** | 叙述式最丰富——**比公开网页链路在浙江拿到的 16 件多三个数量级** |
| 河北 | **35,626** | 与公开网页的河北富矿（156 件）同源，法宝侧更全 |
| 湖南 | **13,770** | 叙述式可用 |
| 上海 | 15 | 表格形态（解释了两份实样的成因） |
| 云南 | 0 | 无叙述式（公开网页侧云南 354 件也几乎全是无案情汇总条目——两侧一致） |

**这就是选省的现成工具**：`queryText="现场查获赌资"` ＋ `lawRegional=[省]`（75 分/次，结果进缓存），比导目录再统计便宜且直接；建议数据链路在普查时把它与"赌博＋2026"组合使用（前者回答"该省有没有事实"，后者回答"该省有多少新法案件"）。

**注意**：`queryText` 的 `total` 含跨年度、含其他治安案件（正文顺带提到赌博的，如反电诈、偷越国边境），选省时看量级即可，精确抽样仍要导目录表按文号去重。

### 1.6 形态的**分省分布**与记录级分级（v0.8：过滤规划）

**一、形态由来源省决定（8 省实测，2026-10-16）**。判据用两个检索短语的命中数对比（MCP `total`，75 分/次）：

| 省份 | `现查明`（有叙述式版面的记录） | `现场查获赌资`（赌博叙述式） | 结论 |
|---|---|---|---|
| **江苏** | — | **80,155** | **叙述式最富**（用户实测"南京大部分有详细内容"得到印证） |
| 浙江 | — | 73,583 | 叙述式 |
| 河北 | — | 35,626 | 叙述式 |
| 湖南 | — | 13,770 | 叙述式 |
| 山东 / 湖北 | — | 有量（龙口/咸丰实样） | 叙述式（含"结果栏内"变体） |
| 上海 | — | 15 | 摘要形态（→ 只导目录） |
| 山西 | 915 | 1 | **法宝几乎未收录该省执法公示** |
| 安徽 | 955 | 0 | 同上 |
| 云南 | 1,620 | 0 | 同上 |

**判别法**（给数据链路普查用，替代原"31 省 × 2026"的单一计数）：每省两次调用——`现场查获赌资` 回答"该省有没有可用的叙述式赌博文书"，`现查明` 回答"法宝到底收没收该省的执法公示"。
- 两列都高 → 叙述式富矿，**值得导全文**；
- `现查明` 高而 `现场查获赌资` 低 → 收了公示但赌博案少或为摘要 → 只导目录；
- 两列都低 → 该省在法宝路线基本不可用，转别的渠道。

**二、记录级分级（代码已实现 `tier`，落盘分流）**：

| 级别 | 判据 | 产物 | 用途 |
|---|---|---|---|
| **L1 金标候选** | 有事实段 + 处罚结果可解析 + 赌博命中 | `admin_cases.jsonl` | **训练/测试原料**（M1 输入、M4 特征） |
| **L2 结果-only** | 无事实段但有结果 | `admin_outcomes_only.jsonl` | 省份/年份/处罚种类**分布校准**、**T-time 计数**（2026 新法案件，判决书只有 12 份，这类是唯一大规模来源）、新法/旧法分片、跨源核对 |
| **L3 范围外** | 非赌博 / 民事判决 / 无事实且无结果 | `pkulaw_out_of_scope.jsonl` | 不进任何训练（全文检索的已知噪声） |
| **L4 待核** | 有事实但结果未解析（或反之） | `admin_needs_review.jsonl` | 人工过一眼，补规则 |

**三、"只有结果"的记录：过滤出金标，但不丢弃**。理由分三层：
1. **对训练：确实无意义**——没有事实段就没有输入特征，学不到"要素→处罚"；规格 §2 要求金标"信息完整度 ≥80%"，所以**必须从金标线过滤掉**（这是硬约束，不是偏好）。
2. **但有非训练用途**（引擎侧 D6 已定）：分布校准、T-time 计数、跨源合并（同一文号若在公开网页/判决书里有事实，可与本层记录拼成完整案例）。
3. **成本极低**：导目录几乎不耗时，所以"顺手导、分层放"比"不导"更划算。

**四、对目标省决策的直接影响**（数据收集计划 §2 的候选是山西/湖南/云南/安徽/浙江/上海）：
- 候选六省里**只有湖南（13,770）与浙江（73,583）在法宝路线上有叙述式富矿**；
- 山西（1）、云南（0）、安徽（0）**两列都低**——法宝基本未收录，公开网页路线也很薄（山西 0、云南 43、安徽 46）→ 建议不作为首选目标省；
- **建议把江苏（80,155）新增进候选**，与浙江、湖南（外加河北/山东/湖北作备选）一起做"裁量基准可得性 + 复议专栏质量"的二次筛选。

### 1.7 一次 50 篇的下载约束下的链路设计（v0.9）

**两个约束**：① 网页批量导出**一次最多 50 篇**；② **下载前看不出文书是否含事实**（形态由来源省/机关决定，随机挑 50 篇会掺进摘要记录）。

**破法：用正文短语检索预先锁定含事实的文号。** 法宝检索是全文索引（§0 已证），而"现场查获赌资""现查明"这类短语**只出现在叙述式事实段**——检索它们，结果列表里每一条都必然含事实。于是问题从"下 50 篇里有多少能用"变成"下的 50 篇全都能用"。三条实现路径：

| 路径 | 成本 | 做法 |
|---|---|---|
| **① 网页端（主路径）** | 免费 | 检索框输入正文短语（`现场查获赌资` 或 `现查明`）＋ 地区 ＋ 公布日期范围 → 勾选该页 50 篇 → 批量导出。**分片 = 省 × 时间窗**，逐窗下到空 |
| ② MCP 枚举（备选） | 75 分/次 | `search_enforcement(queryText=现场查获赌资, lawRegional=[省], start/endPunishmentDate=…)` → 20 条/次（含文号、机关、日期、依据法条）→ 落成工作清单（**脚本已就绪**：`pkulaw_ingest.py worklist --src <MCP响应或缓存目录>`）→ 按文号在网页勾选 |
| ③ 单条核验（兜底） | 75 分/条 | `queryText=现场查获赌资` + `documentNo=<文号>`，命中即证明该文含事实；只用于抽查 |

**五步链路（含回写）**：

```
① 枚举：网页正文短语检索（省 × 时间窗）或 MCP 检索 → worklist.csv（文号 + 「叙述式=是」）
② 下载：按窗口勾选 50 篇/批 → 导出 → inbox/pkulaw/<省>-<时间窗>/（同批记检索式与命中数，供数据卡）
③ 入库：import_manual.py（算哈希、分配台账 id）→ pkulaw_ingest.py docs --worklist → tier 四路落盘
④ 回写：docs 自动把已下文号在 worklist 标「已下全文」→ 下一批只看未下，避免重复
⑤ 交付：L1（admin_cases.jsonl）→ 脱敏 + R6 → 引擎；L2 另送结果-only 层；L3/L4 单独存放
```

**时间分片的实测依据（江苏，「现场查获赌资」口径）**：全部 80,155｜≤2021 **59,195**｜2018 单年 14,293｜≥2022 20,960｜**2025 Q1 = 0**。
→ 两个结论：**库存集中在早年，分片必须按省实测**（不能假设近几年最多）；**T-time（2026 新法案件）不能靠这类省**，要按"依据法条含 2025修订第 82 条"另做定向检索（浙江 2026 已有实例：善公(干)行罚决字[2026]02973号）。

**50 篇测试方案（建议尽快跑，两批对照）**：

| 批 | 检索方式 | 预期 | 判读 |
|---|---|---|---|
| **A** | 正文短语（`现场查获赌资` 或 `现查明`）＋ 某省 ＋ 某年 | **L1 接近 100%** | 成立 → 后续全按此法下载 |
| **B** | 常规检索（处罚事由=赌博 / 全文"赌博"） | L1 明显偏低 | 量化"不筛选的浪费率"，作为不筛选的对照 |

两批分别放 `inbox/pkulaw/test-A/`、`test-B/`，各跑一次
`python research/discretion/collect/pkulaw_ingest.py docs --docs <批次目录> --out $JUSTILAW_DATA_DIR/admin --harvest-date <日期> --manifest ""`，
看报告里的 **tier 分布**与**批次指标**（事实段中位长度 / 含金额比例 / 缺决定日期比例 / L1 占比）→ 据此估算"要下多少批才够金标 ≥500"。报告脚本已内置这些指标。

### 1.8 首批 50 篇实测（南京，2026-10-16，v1.0）

**样本**：南京 9 个分局/派出所 2023 年赌博处罚决定书 50 份（常规检索下载，未做任何预筛选）。

| 指标 | 结果 | 判读 |
|---|---|---|
| 形态 | **叙述式 48 / 字段式公示 2** | **96% 含事实**——用户"南京大部分有详细内容"完全成立，且**常规检索就够**，无需预筛 |
| 分级 | **L1 48 / L2 2** | 只有江宁东山派出所 2 份是"对××罚款贰佰元"式纯结果 |
| 事实段长度 | P25 70 / **中位 95** / P75 127 字 | **偏短**：多为"时间+地点+方式+行为"一句话，缺金额与情节 |
| 含金额 | **27/50（54%）** | 距规格 §2 的"信息完整度 ≥80%"有差距 |
| 分局差异 | 高淳分局 8 份**平均 962 字**（多人多次"进园子"麻将，含逐次明细与金额）；江宁 19 份平均 80 字 | **同一市内也有富矿分局**，可按执法机关挑 |
| 结果分布 | 拘留 2–12 日、罚款 100–3000 元、拘留并处罚款 | 档次覆盖可用 |

**对训练的意义（重要）**：
- **96% L1 说明"有输入可学"**（对比 CAIL 教训：19% 案件无金额无情节）；
- 但**中位 95 字的信息量对 M1 抽取训练只能算中等**：行为类型/赌博方式/时间地点类字段有值，**赌资/抽头/参赌人数类字段大量会是"未提及"**；
- **完整度是当前的瓶颈**（54% < 80%）：靠单一口径下载达不到，需要三招组合——
  1. **检索式换成金额导向短语**：`现场查获赌资`（该短语后几乎必然跟数额）→ 预期同时提高"含事实"与"含金额"（待 A 批验证）；
  2. **按执法机关挑富矿**（网页端可按机关筛，如高淳式长文）；
  3. **省际混合**：江苏/南京给规模，湖南（实样 399 字含逐笔金额）、河北（225 字含三档赌资）、山东/浙江给细节。

**批次产出率换算（定下载量的依据）**：金标 ≥500 件、完整度 ≥80% ⇒ 需要约 **400 件含金额样本**。
- 按本批口径（每 50 篇得 27 件含金额）→ 需约 **15 批（750 篇）**；
- 若 A 批把含金额率提到 80% ⇒ 需约 **10 批（500 篇）**。
→ 三天窗口够用，但要**先做 A 批验证**再定正式口径。

**同时修掉一个真 bug**（批次实测暴露的）：导出件首行常为空，`gambling_hint` 取首行导致标题里的"赌博"看不到 → 2 份真赌博案被误判"范围外"；已改为"首个非空行 + 关键字段，兜底整篇"。

### 1.9 A/B 两批对照与下载口径定稿（2026-10-16，v1.1）

| 指标 | **A 批**：正文=`现场查获赌资` | **B 批**：常规检索（南京） | 结论 |
|---|---|---|---|
| 篇数 → 独立文号 | 50 → 49（1 组同文号两变体，去重正确） | 50 | — |
| L1 金标候选 | **48（98%）** | 48（96%） | 两批都不缺"事实" |
| **含金额** | **98%**（49/50） | **54%** | **A 口径完胜**；金额导向短语后面几乎必然跟数额 |
| 事实段中位长度 | 95 字（最长 194） | 94 字（最长 **1084**，高淳长文） | 两者都偏短；长文只在个别富矿分局 |
| **独立事件数** | **16（折算率 33%）** | **32（64%）** | **A 口径的代价：集中行动批量决定书占满结果** |
| 地域 | 江苏 42、北京 5、浙江 2、黑龙江 1（**未限地区**） | 南京各区 | 正式口径必须限省，否则构成不可控 |

**A 批重复事件的实况**（为什么折算率只有 33%）：临港派出所 2022-07-27 一次查处 → 8 篇；2022-07-22 → 5 篇；新坝派出所 2023-03-07（赌资 7600）→ 5 篇；清河分局 2023-01-16（赌资 4745）→ 5 篇 → **44/50 篇落在 10 个重复事件里**。一次抓赌产生十几份决定书、金额相同，所以全部命中金额导向短语。

**定稿的下载口径与排期**：
1. **口径**：正文 = `现场查获赌资`（保金额，达成规格 §2 的完整度 ≥80%）＋ **限定省份**（江苏/浙江/河北/湖南）＋ **限定时间窗**（按年或半年）；
2. **分片要细、要跨窗跨省**：同一派出所一次行动就占掉 8 篇，所以每窗只取 1 批（50 篇）就换窗换省——**降重靠分片，不靠后处理**；
3. **排期换算**：每批 ≈ 48 件 L1 / ~16 个事件（A 口径）。金标 ≥500 件 ⇒ **10–12 批**（跨 2–3 省 × 4–6 个时间窗）⇒ 约 160–190 个独立事件，足够支撑按事件分组划分与 T-admin（≥150 件）的独立性；
4. **长文补充**：A 口径事实仍偏短（中位 95 字），需要"含逐笔金额、多人多次"的长文时，按机关挑富矿（高淳式）或按案情特征（"进园子"/"斗牛"等聚众形式）另开小批；
5. **交付带上事件键**：代码已把 `event_key`（机关 + 事实段首个日期 + 赌资金额集合）写进每条记录与批次报告，直接服务门禁 §7 的"按事件分组划分"；批次报告新增**事件产出率**指标。

## 3. 真正需要的形式与内容（需求侧，不拟合样本形式）

**目标不是"把法导出转成 JSON"，而是凑齐四件套：** 事实段（`text_facts`）+ 行为日期 + 处罚结果精确标签 + 情节认定。四件套缺哪个，那条记录就只能降级使用。

三类子库分工（法宝内部也是三条不同的数据线，别混为一谈）：

| 子库 | 给什么 | 在项目里的位置 | 优先级 |
|---|---|---|---|
| **司法案例库（法院判决）** | 行政判决：事实 + 原处罚 + 审查结论，法宝已分段 | **金标补充**（非主力）：诉讼来源受门禁 §7"≤50%"约束；用于复核标签、被撤销/变更的原处罚、M6 说理素材、行刑边界 | **高**——学院账号**长期权限**，按周节奏导，不占三天 |
| **行政执法库** | **叙述式省份：含事实的决定书全文（A 类主力）**；表格省份：只有结果与元数据（B 类） | ①**A 类主力来源**（浙江/山东/河北/湖南/内蒙…）——3 天窗口优先导这些省的赌博决定书；②表格省份：结果-only 层（D6）与新法/旧法分片（带法律版本）；③**反查原文的索引**（机关+文号 → 原公示页） | 三天窗口最高优先级 |
| 司法案例库-复议？ | 复议决定：事实 + 原处罚 + 复议结论 | 若收录：复核标签（P1）+ T-admin 复议侧 | 三天内试检是否收录 |
| 法律法规库 / 地方法规库（R4/R5） | 规范原文（含省级裁量基准） | 清 G0.1 待核验；法律组录 YAML，不走案例管线 | 顺手导 |
| 检察文书库（不起诉决定书） | 行刑边界的负样本 | M2"是否移送"判断的补充 | 可选（MCP 75 分/次） |

**注意：A 类主力（叙述式处罚决定书全文）法宝给不了**，它来自公开网页收割（发现层，叙述式 441 件）与合作案卷（搁置）；法宝在这条线上只能当**索引**（反查通道）。

**导出形式的选择原则**（形式服从内容）：
- **每个检索式先导"目录列表 xls"**——它是索引 + 元数据 + 结果标签，几乎不耗时间，且本身就是有用的结果-only 数据。
- 正文按目录挑着导。**先试检 1 份"纯文本"导出**：若纯文本已含元数据块与决定表，后续优先导纯文本（省掉 .doc 解析与 antiword 依赖）；PDF 只在扫描件场景用（`harvest/ocr.py` 已有 OCR）。
- 解析器不绑定文件形式：`doc_to_text()` 支持 antiword / Word COM / docx / txt 四种取文本方式，解析按"标签 → 值"抽取，换排版只影响抽取规则，不影响字段映射与产出。

命令（仓库根目录；**输出默认按批次隔离，不再写共享目录**——见 §7 的输出保护）：

```bash
# 依赖：pip install xlrd（读 .xls）；没有 xlrd 的机器先用 pkulaw_xls2csv.ps1 转 CSV，再喂 --xls 指向 CSV
# 1) 目录 → 工作清单与统计（行政执法库与司法案例库共用）
python research/discretion/collect/pkulaw_ingest.py catalog \
    --xls "inbox/pkulaw/R1/【北大法宝】目录列表.xls" --batch R1
    # 默认 → $JUSTILAW_DATA_DIR/catalog/R1/worklist.csv
# 2) 行政执法库的处罚决定书公示 → 结果-only 层
python research/discretion/collect/pkulaw_ingest.py docs --docs inbox/pkulaw/R1/docs \
    --worklist $JUSTILAW_DATA_DIR/catalog/R1/worklist.csv --batch R1
    # 默认 → $JUSTILAW_DATA_DIR/ingest/R1/…；跨批累积加 --append，重跑同批加 --force
# 3) 司法案例库的判决书 → 金标候选（MCP 响应 JSON / JSONL / 目录都可作输入）
python research/discretion/collect/pkulaw_ingest.py cases --src inbox/pkulaw/cases --batch pfnl-2026H2
    # 默认 → $JUSTILAW_DATA_DIR/cases/pfnl-2026H2/…
```

**主键与去重**：判决书用原文链接里的 `pfnl` 哈希；处罚决定书公示用文件名里的法宝引证码（`FBM-CLI.…`），无引证码时退文号。同一 URL 重复下载视为同一条。
**事件分组**（门禁 §7 防泄漏）：同机关 + 同决定日期 + 文号/案号连号多为同一次查处（实样 00289/00290 即两人同一次），脚本输出 `event_hint` 供划分时聚合。
**质量门**：脚本按组统计 `outcome_only` 占比、原处罚类型分布、法律版本分布、`信息完整（有金额+结果）`件数与 `parse_warnings`（facts_missing / outcome_not_parsed / articles_not_parsed / decision_date_not_found / fine_mismatch / not_in_manifest），交付前人工看一遍。

## 7. 风险与合规

- **输出隔离与防覆盖（2026-10-16 整改）**：解析脚本的默认输出按 `$JUSTILAW_DATA_DIR/<kind>/<batch>/`
  隔离（docs→`ingest/`、cases→`cases/`、catalog/worklist→同名目录）；显式 `--out` 指向已有产物时
  **拒绝写入**，除非 `--append`（按 引证码/文号 去重合并）或 `--force`（覆盖重写）。
  背景：旧默认 `--out $DATA/admin` 与数据链路（发现层）的交付目录相同，且 L2 产物与 `SHA256SUMS`
  与其**同名**，默认运行会互相覆盖。
- **二次分发**：导出文本只存仓库外 `$JUSTILAW_DATA_DIR`，仓库只提交脚本与台账哈希（手册 §5）。
- **账号与权限**：学院账号已绑定**司法案例库**权限（长期）；**行政执法库**是购买的三天权限——两者的条款与导出额度不同，批量导出前先确认限额（待确认 #2、#8）。
- **姓名遮挡不可假设**：司法案例库判决书**未脱敏**（实测含当事人真名、律师、法官姓名）；执法库的表格形态样本是遮挡过的（"陈\*英"）；而**叙述式省份的决定书原文多为"李xx"半脱敏、也有真名**（发现层实测 385 件真名）→ 一律走脱敏 SOP + R6，交付前 `deidentified` 恒为 false。
- **结果-only 层不得混入金标**：脚本按事实段自动分流，`admin_outcomes_only.jsonl` 与 `admin_cases.jsonl` / `pkulaw_cases.pre_deid.jsonl` 分开落盘；引擎侧按 D6 只用于分布与计数。
- **诉讼来源占比**：判决书全部是诉讼来源，门禁 §7 要求测试集中复议/诉讼合计 ≤50% → 测试集构成必须混入公开网页与执法公示来源。
- **积分纪律**：MCP 积分与引擎共用（余额 8,300，11-15 过期）；本次普查用 225 分，全部经共用调用层记账（`research/eval/pkulaw_mcp/`，`--workstream data`）。
