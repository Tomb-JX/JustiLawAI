# 批量采集运维计划：站点台账与定期适配

> 版本 v0.1 · 2026-10-15 · 由**数据链路**工作流执行（[分工文档](./workstreams.md) §1）
> 配套：[数据收集计划](./data-collection.md) · 采集工具与已知坑见 [`research/discretion/collect/README.md`](../../research/discretion/collect/README.md)
>
> 背景：复议专栏赌博案密度实测 <1%（234 件全量仅 ≈1 件强命中），渠道 B 要为金标 ≥500 件（G1.1）供料必须规模化收割 3–6 万件。采集框架已就绪，本计划解决"管起来、转起来"。

## 1. 目标与度量

| 项 | 目标 |
|---|---|
| 总目标 | 渠道 B 累计全量收割 ≥3 万件，供金标筛选（赌博案 ≥300 件供目标省） |
| 节奏度量（每周报周会） | 新增适配站点数 / 本周新收割件数 / 台账累计 / 赌博强命中累计 |
| P1 末（约 W4） | 已通站点 ≥8，累计收割 ≥5,000 件 |
| P2 末（约 W8） | 已通站点 ≥15，累计收割 ≥20,000 件 |

## 2. 站点台账（机器可读：[`collect/sites.csv`](../../research/discretion/collect/sites.csv)）

状态机：`候选 → 探查中 → 已通（有适配器）→ 休眠（改版/失效）→ 放弃（无公开栏目或条款禁止）`

| 状态 | 数量 | 说明 |
|---|---|---|
| 已通 | 3 | 浙江省司法厅、北京东城区、北京门头沟区（合计 234 件） |
| 已定位待适配 | 8 | 北京市司法局（全文 PDF）、丰台、南京、济南、广州、宜兴、朝阳、大兴 |
| 候选（未探查） | ~20 | 各省司法厅 + 治安处罚量大的地市（优先公安分局所在地城区） |
| 受阻 | 3 | 湖南（Python TLS）、信用中国（JS 盾→浏览器半自动）、需登录站（不爬） |

**选站优先级**：大城市城区（治安处罚基数大）> 市司法局 > 省司法厅（案件层级高、治安类少）。

## 3. 新站适配 SOP（单站 0.5–1 天）

1. **探查**：`probe_sites.py` 或搜索引擎定位列表页；判断 CMS 家族（TRS 静态 / 汉网 jpaas / JCMS / JS 壳）；结果写入 `sites.csv`（状态=探查中，附 URL 与 CMS 备注）
2. **结构分析**：找到真实列表（首页多为 JS 壳；汉网走 unit 接口 + `paramJson`；TRS 是 `index_N` 静态翻页）
3. **写适配器**：`crawl_reconsider.py` 增加 `iter_<site>()`——翻页失败按存档末尾处理；编码统一走 `decode_html`；请求只经 `common.session()`
4. **试点**：`--pages 2` 抽查 .txt 正文、文号、事实完整性 → 全量 `--list-only` 建索引 → 下载
5. **质检**：manifest 行数 = 落盘文件数；`filter_gambling.py` 出初筛报表；失败条目重跑一次
6. **登记**：`sites.csv` 状态改已通；新坑写进 collect/README「已知坑」

## 4. 定期节奏（每周例行约半天，周一适配窗口）

| 动作 | 内容 |
|---|---|
| 适配新站 | 2–3 个待适配站（按 §2 优先级） |
| 增量收割 | 已通站点重跑——全部幂等：索引重建、manifest 按 URL+哈希去重、已存文件跳过，只拿新增决定 |
| 失效巡检 | 每个已通站抽 1 页比对条目数与解析健康；结构改版 → 标记休眠，当周修复 |
| 汇报 | 四项度量写入周会纪要（对应数据收集计划 §7 时间表） |

## 5. 合规红线（不变，写进每个适配器的默认行为）

- 只抓**公开专栏**；请求间隔 ≥1.5s；不绕过登录/验证码/JS 盾（如信用中国 → 真实浏览器半自动）
- 请求头对齐浏览器是为通过基本可达性检查，身份如实记录（manifest `harvest_by`）
- 站点条款明确禁止批量获取的，在 `sites.csv` 标记放弃并写明依据

## 6. 风险与预案

| 风险 | 预案 |
|---|---|
| 站点改版导致适配器失效 | 适配器按站点隔离，坏一个不坏一批；休眠标记 + 当周修复窗口 |
| IP 被限流 | 间隔 ×2、错峰采集；仍不行转浏览器人工导出（渠道 C 流程兜底） |
| 密度持续过低 | 连续 4 周强命中 <5 件/千件 → 分工文档 §6 留言提议调整渠道配比（渠道 C 商用库关键词检索转主力） |
| 数据目录单点 | 外置目录（`JUSTILAW_DATA_DIR`）每周随增量收割核对文件数与台账行数；重大迁移沿用前后哈希审计流程 |

## 7. 与验收/标注的接口

- 收割件 → 资格筛选（数据收集计划 §4）→ 教师预标注 → 法律组校正 → 金标
- 每月更新数据卡来源构成表（复议各站占比、赌博命中率），供 G1.4 与偏差加权使用
- 台账 manifest 是唯一交付索引：案例 JSONL 的 `id` 必须对应 manifest id（分工文档 §5）
