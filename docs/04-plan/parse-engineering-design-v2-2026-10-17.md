## 1. 管线总览（五阶段 S0–S4）

```
parsed-1（原文态, 5,739件）
  S0 清理层   确定性：样板噪声移除、续行/裸换行归一、标签字剥离、空白归一
              产物：cleaned_text + offset_map（cleaned 位置 → 原文位置，单调映射）
  S1 模型层   远程旗舰（temperature=0, JSON Schema 约束），输入=清理后原文
              输出=结构化 JSON：五段引文 + outcome 字段 + subject/dates/gambling+理由
              ★ 只产出引文，不产出坐标
  S2 定位层   确定性：quote 在 cleaned_text 逐字定位（归一匹配+模糊对齐兜底）
              → offset_map 投回原文坐标＝交付坐标（v2.1 起交付正本即原文，无第三级投影）
  S3 校验层   parse_qc 15 项迁移为管线内阻断校验 + quote 命中率/唯一性/一致性
              通过 → parsed-2（模型态 parsed-1）；失败 → 重试一次（换模型）→ 低置信队列
  S4 人工     低置信队列审核（mask_review 显示辅助）+ 分段评测集标注（100–200件金标准）
```

**脱敏取消（v2.1 关键决策，2026-10-17）**：原 v2.0 将模型调用排在预脱敏之后（模型只见遮蔽文本）。该隐私排序随脱敏限制取消一并解除：主管线不再有预脱敏，模型直接处理清理后的原文。量化收益（数据源：《完全去掉脱敏的链路影响模拟》§2）：

1. **定位链三级投影减为两级**——五段坐标直接绑定交付正本，少一级投影＝少一类错位源；
2. **`text_sha256` 随上游 parse 冻结真正稳定**——"每次重建 42 件正文哈希漂移"消失，已冻结样本（试标、抽检）不再被脱敏规则迭代作废；
3. **脱敏伪影类缺陷整类消失**——伪影人名（姓+代号截断）、别名撞号（乙5 类）、ambiguous_persons 265 / subject_variants 585；
4. **7 轮脱敏打地鼠（22 规则 / 16 处事故注释）与 R6 白名单维护停止**。

要求脱敏的规范条款（text-processing-spec §4.2/§4.3 与冻结点、data-spec §1.1/§1.3/§1.6/§4、sota-gates R6、data-collection 三原则与 §4 SOP）由**协调层承接修订**，本设计不代改规范；设计侧依赖变化见 §11。`deid.py` / `r6_scan.py` 降级保留：转为**外发衍生可选工具**（离线、独立定版），不再是交付门禁；`build.py` 的 deid_case 调用与 `_` 前缀内部字段剥离自 r6 构建起移除。

## 2. S0 清理层（确定性）详细设计

- **输入**：parsed-1 的 `text_full`（原文态）。
- **规则注册表**（有序、可单测）：导航样板模式（"首页>专题专栏"、面包屑残句、走进X）、管道/裸换行续行归一（现 CELL_WRAP 的泛化：管道型 + 短片段裸换行）、字段表标签字剥离（"事由/处罚类别/案件名称"等 LABELS 词与单字残片）、空白/全角归一。
- **核心数据结构**：`offset_map`——单调数组 `cleaned_pos → orig_pos`（每个保留字符一个映射；删除段不映射）。所有下游位置先记 cleaned 坐标，投影回原文由 map 完成；映射本身是纯函数，**单测可穷举**（对每条断言 cleaned[c] == orig[map[c]]）。
- **置信度：高**。纯确定性、逐条可断言；同型映射（三段投影）已在现网 2,267 件实测 0 错位。
- **失败模式**：规则误删正文片段——对策：删除类规则白名单化（只删命中导航模式/纯标签字的 span），并保留删除审计（删除 span 与原因入 extra）。

## 3. S1 模型层详细设计

- **输入**：cleaned_text（原文态；实测 p50=435 / p90=871 / p99=3,397 / max=8,981 字——**95%+ 记录单调用免切块**；>3,000 字的 36 件按句号粗分 2–3 块，段间无跨块依赖的字段独立抽取）。
- **输出 JSON Schema**（约束解码，禁自由文本）：
```json
{
 "segments": [{"type": "facts|evidence|reasoning|decision|review", "quote": "逐字原文引文"}],
 "subject": {"mention": "正文中的本人写法（原称，如'王某某'或真名）", "aliases": ["同案写法"]},
 "outcome": {"type": "枚举7值", "detention_days": 0, "fine": 0, "not_executed": false,
             "confiscation": [], "articles": [{"text": "《…》第X条", "edition": "2012修正|2025修订|未知"}],
             "stated_circumstances": []},
 "dates": {"behavior": {"quote": "…"}, "decision": {"quote": "…"}},
 "gambling": {"verdict": "是|否|待定", "reason": "…"},
 "confidence": "high|low"
}
```
- **字段级规则内嵌 schema**：segments 的 quote 必须能按顺序拼接覆盖 decision 类文书的主体（覆盖度校验）；outcome.type 与五段中 decision 段强关联（校验层交叉核对）；articles 必须带版本注解（直接修 N6 假阳性的口径）。
- **提示工程**：系统提示 = 五段/字段的规范定义（引 data-spec）+ 3–5 个少样本（从人工评测集抽）+ 硬规则（定性句不入事实段、引文必须逐字、"仅输出 JSON"）。提示词版本化（seg-v1），入库注册。v2.1 起提示中不再有任何脱敏相关说明；本人识别直接基于原文写法（真名/发布方遮挡名并存，见 §9 待测项）。
- **调用形态**：每记录一次调用（95%+ 免切块）；重试策略 = 同模型 1 次 → 换旗舰 1 次 → 低置信队列。模型纪律：生产单旗舰（与金标线同档），三模型并行仅用于抽检与分歧复核（金标线既有基建整套复用：run_manifest/receipts/retry）。
- **置信度分析**：
  - 工程 shape：高——金标线 50 件评审（review_deepseek/qwen/kimi + manifest + receipts + retry）已是同构链路的实跑验证。
  - 分段质量：**待测**——这正是评测集存在的理由；在评测集上以边界 F1 对 parse.py 基线作切换判定，不给未经测量的承诺。
  - 引文命中率：**待测**（pilot 100 件先量）；业界 generate-then-verify 是成熟模式，但中文行政处罚文书上的具体命中率必须实测。

## 3A. 要素标签层（L5，2026-10-18 补）

> 解析/分区只把文书变成可用输入；**标签**是另一层。当前项目最大的缺口在这里，不在解析。

- **字段**：7 组 36 字段 + 3 meta；唯一来源 `schema.py`/`element_labels.py`。一人一条记录；`input` 只放 facts/meta 视图与 target/aliases，不能放 decision/reasoning/review/outcome。
- **标签形状**：每字段 `{status, value, evidence}`；`status`=明确/推断/未提及；金额 `{min,max}`；日期 ISO；证据 `{quote,start,end}` 必须逐字命中且只来自 facts/meta。
- **教师**：`element-teacher-v1` 只回 `elements`，不输出 binding；A/B 双盲 + 非 DeepSeek C 仲裁，产物 `model-adjudicated`、`human_review=false`，不计人工真值。
- **绑定**：每字段/证据标 `shared_fact`/`target_specific`/`needs_review`；引擎 `binding_rules.py` 只定语义（8 shared/28 target），具体判定由后处理实现。当前 **v5 证据感知 3 步**：字段语义 → 证据主体（target/others/无）→ 段落类型；212 条计数仍是 61 shared/1120 target/528 review；**切片无多人案例，joint/other-subject 分支没有被实际触发**；528 review 全是 unclassified role（`fine`/`unclassified_count`），不是主体歧义；`resolve_binding` 代码接受 shared/target（1181/1709=69.1%），contract v4 `accept_in_resolve` 仍只写 lexical/target（1120/1709=65.5%）；无绑定准确率；BIND-03/CONTRACT-01 未关闭。
- **验收**：schema/枚举/版本、证据逐字/坐标/来源、target 可定位、无 decision/reasoning/outcome 泄漏、金额/日期合法、`reference_elements` 非空、字段覆盖率、绑定小样本准确率、A/B 或人工复核。完整格式见 [data-spec §8](D:/02_Dev/Projects/大创/.claude/worktrees/discretion-engine/docs/05-research/data-spec.md) 与 [annotation-guideline §3.11](D:/02_Dev/Projects/大创/.claude/worktrees/discretion-engine/docs/05-research/annotation-guideline.md)。
- **当前状态**：`reference_elements=null`；L5 标签为 0；M1 字段准确率暂缺；M4 只能用历史处罚做基线；r7 未放行。

## 4. S2 定位通路（quote → 坐标 → 交付）——完整链路

```
quote(清理后原文中的引文)
 ① 精确定位：cleaned_text.find(quote)（归一空白后）；多处命中 → 全部记录并要求模型给前后文消歧，仍歧义 → 低置信
 ② 仍失败 → 模糊对齐：去空白/标点后再匹配（difflib 锚定搜索，e-discovery 惯用）
 ③ cleaned 坐标 ──offset_map──► 原文坐标（S0 映射）
 ④ 原文坐标即交付坐标：交付 text_full ＝ parsed-1 原文（v2.1 起；原"deid 三段投影"一级整体移除）
 ⑤ 校验：segments 互不重叠、并集覆盖决策类文书主体 ≥95%（覆盖度）、五段 ⊆ text_full
```

- 投影只剩一级（cleaned → 原文）：单调映射复合的数学性质不变，每段仍有逐字符单测；同型机制已在现网 2,267 件实测 0 错位。
- 置信度：高。定位是纯代码；唯一的不确定（模型引文是否逐字）由 ①–② 的确定性检查兜底，失败可见可数。

## 5. S3 校验层（规则的新角色）

- **迁移**：parse_qc 的 15 项检查从"交付后 QC"迁移为"管线内阻断校验"——同一套注册表两个挂点（管线内阻断 + 交付后抽检），口径天然统一（顺带修 N3 双口径问题）。
- **模型态特有校验**：quote 命中率与唯一性、segments 覆盖度、schema 合法性、outcome 内部一致性（类型↔数额↔法条↔版本注解——含"（2025修订）第七十条=新法"口径）、日期顺序、event_key（文号优先）。
- **失败处置**：硬校验失败 → 换旗舰重试一次 → 低置信队列（人工）；软校验（疑级）→ 标记入库不阻断。
- **置信度：高**——这 15 项恰是实测"规则可靠、模型不可靠"的确定性校验；期望套件模式成熟。
- v2.1 变化：原与脱敏绑定的检查（人名残留、别名一致性、doc_no_hash 同源性）移出交付校验注册表；R6 确定性模式（证件/电话/门牌）转入外发衍生工具，不阻断交付。

## 6. S4 人工角色

1. **分段评测集**（100–200 件，分层：叙述式/字段式/表格/OCR 按实占比）：人工标五段起止；交付边界 F1 作模型 vs parse.py 的切换判据。**标注直接在原文正本上进行**——不再有"先脱敏、再冻结、再标注"的顺序约束，证据位置一步绑定，标注规范本线先出草案，标注平台走 Label Studio 族（或最小化：结构化表格 + mask_review 显示辅助）。
2. **低置信队列**：mask_review 复用为可选显示辅助（原为脱敏取证基建，随取消降级为阅读遮蔽工具）；队列量预估 = 校验失败率 × 全量（pilot 先测）。
3. **主动采样**：按模型 self-confidence=low 与校验告警密度优先抽样（不确定性采样，标准做法）。
4. **金标回退重基线**：33 件金标回退中 A/F 两类（脱敏伪影、隐私泄漏）随取消整类关闭，仅需处理解析类回退（B/C/D/E）；正式金标计数仍为 0，切换文本基座无已签署标注需要迁移。

## 7. 版本治理与溯源

- `parser` 字段升级为 `parse-v2|model:deepseek-v4-pro|prompt:seg-v1|clean:v1`（四元组入库）；每个 prompt/模型变更 = parser 版本变更 = 必须过评测集回归。
- 评测集本身版本化（标注人、日期、一致性系数）；变更清单（候选 D）继续：**解析与清理改动分开定版**；"privacy 定版维度"随脱敏取消不再是交付版本化维度（外发衍生工具如启用，另行独立定版）。
- 模型输出缓存：以"输入哈希 + 模型 + 提示版本"为键（与发现层缓存同模式），重跑不重复付费。v2.1 附带收益：输入哈希基于原文，不随脱敏规则漂移，缓存命中率提升。

## 8. 成本与吞吐（量级，准确价格以各控制台为准）

- 全量回填：5,739 件 × 1 调用（输入≈原文正文+提示 ≈1–2k token、输出 ≈0.5k）；周增量数百件。金标线 50 件三模型评审已实跑通该量级与形态。
- 吞吐：顺序+并发（限速按服务商配额），全量回填按小时计。
- 双轨期成本：parse.py 兜底路径保留，模型层只对增量+回填各跑一轮。
