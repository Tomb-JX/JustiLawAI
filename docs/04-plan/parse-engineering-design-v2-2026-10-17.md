# 解析层 v2 工程设计（详细版）：模型语义抽取 × 规则清理校验 × 定位通路

> 2026-10-17。承接《解析架构 v2》的方向判断，本文是可实施的工程设计：每个子问题先翻译成**标准工程问题**，给出**主流方案族**、**选型**、**置信度**与**匹配度分析**。所有设计以本项目的实测约束为输入，不引入未经论证的组件。
> 硬约束（设计前提）：① 证据定位契约——五段必须是交付正本的连续子串，标注证据位置相对正本计算（data-spec §1）；② 隐私排序——远程模型调用不得接触未脱敏原文（交付层 deid 存在的理由）；③ 可溯源——模型 id+提示版本+输入哈希全程可查；④ 确定性校验不得被模型输出绕过；⑤ 模型纪律——仅远程旗舰，禁本地小模型。

## 1. 管线总览（六阶段 S0–S5）

```
parsed-1（原文态, 5,739件）
  S0 清理层   确定性：样板噪声移除、续行/裸换行归一、标签字剥离、空白归一
              产物：cleaned_text + offset_map（cleaned 位置 → 原文位置，单调映射）
  S1 预脱敏   现行 deid.py 规则做第一遍遮蔽（角色：缩小后续外呼的敏感面，不追求完美）
  S2 模型层   远程旗舰（temperature=0, JSON Schema 约束），输入=脱敏后 cleaned_text
              输出=结构化 JSON：五段引文 + outcome 字段 + subject/dates/gambling+理由
              ★ 只产出引文，不产出坐标
  S3 定位层   确定性：quote 在 cleaned_text 逐字定位（归一匹配+模糊对齐兜底）
              → offset_map 投回原文坐标 → 复合既有三段投影 → 交付坐标
  S4 校验层   parse_qc 15 项迁移为管线内阻断校验 + quote 命中率/唯一性/一致性
              通过 → parsed-2（模型态 parsed-1）；失败 → 重试一次（换模型）→ 低置信队列
  S5 人工     低置信队列审核（mask_review 窗口）+ 分段评测集标注（100–200件金标准）
```

**隐私排序（关键工程决策）**：模型调用放在 **S1 预脱敏之后**——模型看到的是"已按现行规则遮蔽一遍"的文本。敏感面=现行 deid 的漏网项（较原文大幅缩小，且金标线评审本来就在脱敏文本上工作，口径一致）。备选方案（模型直接看原文）需要合规批准，不作为默认。**代价与对策**：脱敏漏网会被外呼——对策是 S1 规则持续改进 + R6/模型 NER 复核仍在内网侧兜底 + 该决策入合规记录。

## 2. S1 清理层（确定性）详细设计

- **输入**：parsed-1 的 `text_full`（原文态）。
- **规则注册表**（有序、可单测）：导航样板模式（"首页>专题专栏"、面包屑残句、走进X）、管道/裸换行续行归一（现 CELL_WRAP 的泛化：管道型 + 短片段裸换行）、字段表标签字剥离（"事由/处罚类别/案件名称"等 LABELS 词与单字残片）、空白/全角归一。
- **核心数据结构**：`offset_map`——单调数组 `cleaned_pos → orig_pos`（每个保留字符一个映射；删除段不映射）。所有下游位置先记 cleaned 坐标，投影回原文由 map 完成；映射本身是纯函数，**单测可穷举**（对每条断言 cleaned[c] == orig[map[c]]）。
- **置信度：高**。纯确定性、逐条可断言；同型映射（三段投影）已在现网 2,267 件实测 0 错位。
- **失败模式**：规则误删正文片段——对策：删除类规则白名单化（只删命中导航模式/纯标签字的 span），并保留删除审计（删除 span 与原因入 extra）。

## 3. S2 模型层详细设计

- **输入**：脱敏后 cleaned_text（实测 p50=435 / p90=871 / p99=3,397 / max=8,981 字——**95%+ 记录单调用免切块**；>3,000 字的 36 件按句号粗分 2–3 块，段间无跨块依赖的字段独立抽取）。
- **输出 JSON Schema**（约束解码，禁自由文本）：
```json
{
 "segments": [{"type": "facts|evidence|reasoning|decision|review", "quote": "逐字原文引文"}],
 "subject": {"mention": "脱敏文本中的本人写法", "aliases": ["同案写法"]},
 "outcome": {"type": "枚举7值", "detention_days": 0, "fine": 0, "not_executed": false,
             "confiscation": [], "articles": [{"text": "《…》第X条", "edition": "2012修正|2025修订|未知"}],
             "stated_circumstances": []},
 "dates": {"behavior": {"quote": "…"}, "decision": {"quote": "…"}},
 "gambling": {"verdict": "是|否|待定", "reason": "…"},
 "confidence": "high|low"
}
```
- **字段级规则内嵌 schema**：segments 的 quote 必须能按顺序拼接覆盖 decision 类文书的主体（覆盖度校验）；outcome.type 与五段中 decision 段强关联（校验层交叉核对）；articles 必须带版本注解（直接修 N6 假阳性的口径）。
- **提示工程**：系统提示 = 五段/字段的规范定义（引 data-spec）+ 3–5 个少样本（从人工评测集抽）+ 硬规则（定性句不入事实段、引文必须逐字、"仅输出 JSON"）。提示词版本化（seg-v1），入库注册。
- **调用形态**：每记录一次调用（95%+ 免切块）；重试策略 = 同模型 1 次 → 换旗舰 1 次 → 低置信队列。模型纪律：生产单旗舰（与金标线同档），三模型并行仅用于抽检与分歧复核（金标线既有基建整套复用：run_manifest/receipts/retry）。
- **置信度分析**：
  - 工程 shape：高——金标线 50 件评审（review_deepseek/qwen/kimi + manifest + receipts + retry）已是同构链路的实跑验证。
  - 分段质量：**待测**——这正是评测集存在的理由；在评测集上以边界 F1 对 parse.py 基线作切换判定，不给未经测量的承诺。
  - 引文命中率：**待测**（pilot 100 件先量）；业界 generate-then-verify 是成熟模式，但中文行政处罚文书上的具体命中率必须实测。

## 4. S3 定位通路（quote → 坐标 → 交付）——完整链路

```
quote(脱敏 cleaned 文本中的引文)
 ① 精确定位：cleaned_text.find(quote)（归一空白后）；多处命中 → 全部记录并要求模型给前后文消歧，仍歧义 → 低置信
 ② 仍失败 → 模糊对齐：去空白/标点后再匹配（difflib 锚定搜索，e-discovery 惯用）
 ③ cleaned 坐标 ──offset_map──► 原文坐标（S1 映射）
 ④ 原文坐标 ──deid 三段投影──► 交付 text_full 坐标（现网 2,267 件 0 错位的既有机制）
 ⑤ 校验：segments 互不重叠、并集覆盖决策类文书主体 ≥95%（覆盖度）、五段 ⊆ text_full
```

- 投影复合是**单调映射的复合**——数学上就是区间映射的串联；每一段都有单测（逐字符断言）。
- 置信度：高。定位是纯代码；唯一的不确定（模型引文是否逐字）由 ①–② 的确定性检查兜底，失败可见可数。

## 5. S4 校验层（规则的新角色）

- **迁移**：parse_qc 的 15 项检查从"交付后 QC"迁移为"管线内阻断校验"——同一套注册表两个挂点（管线内阻断 + 交付后抽检），口径天然统一（顺带修 N3 双口径问题）。
- **模型态特有校验**：quote 命中率与唯一性、segments 覆盖度、schema 合法性、outcome 内部一致性（类型↔数额↔法条↔版本注解——含"（2025修订）第七十条=新法"口径）、日期顺序、event_key（文号优先）。
- **失败处置**：硬校验失败 → 换旗舰重试一次 → 低置信队列（人工）；软校验（疑级）→ 标记入库不阻断。
- **置信度：高**——这 15 项恰是实测"规则可靠、模型不可靠"的确定性校验；期望套件模式成熟。

## 6. S5 人工角色

1. **分段评测集**（100–200 件，分层：叙述式/字段式/表格/OCR 按实占比）：人工标五段起止；交付边界 F1 作模型 vs parse.py 的切换判据。标注规范本线先出草案，标注平台走 Label Studio 族（或最小化：结构化表格 + mask_review 复用）。
2. **低置信队列**：mask_review 窗口审阅直接复用；队列量预估 = 校验失败率 × 全量（pilot 先测）。
3. **主动采样**：按模型 self-confidence=low 与校验告警密度优先抽样（不确定性采样，标准做法）。

## 7. 版本治理与溯源

- `parser` 字段升级为 `parse-v2|model:deepseek-v4-pro|prompt:seg-v1|clean:v1`（四元组入库）；每个 prompt/模型变更 = parser 版本变更 = 必须过评测集回归。
- 评测集本身版本化（标注人、日期、一致性系数）；变更清单（候选 D）继续：privacy 与解析改动分开定版。
- 模型输出缓存：以"输入哈希 + 模型 + 提示版本"为键（与发现层缓存同模式），重跑不重复付费。

## 8. 成本与吞吐（量级，准确价格以各控制台为准）

- 全量回填：5,739 件 × 1 调用（输入≈脱敏正文+提示 ≈1–2k token、输出 ≈0.5k）；周增量数百件。金标线 50 件三模型评审已实跑通该量级与形态。
- 吞吐：顺序+并发（限速按服务商配额），全量回填按小时计。
- 双轨期成本：parse.py 兜底路径保留，模型层只对增量+回填各跑一轮。
