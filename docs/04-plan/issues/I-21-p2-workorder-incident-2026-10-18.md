# I-21 事故登记：P2 大批量检索工单未经审核，8,400 分换 42 条 L1（2026-10-18）

> 登记人：协调总控（Zcode 接管会话）· 责任认定：**协调层主责**（工单设计、审核缺失、验收指标错误）
> 严重度：**高**（一次性损失 8,400 分，约 84% 的当日到期积分；L1 转化率 2.4%，为历史批次的 1/40）
> 状态：**已止损（停止继续调用）**；防再犯规则即时生效

## 1. 事故摘要

2026-10-18，协调层向法宝线下发 P2 增量采集工单：≤120 次 MCP 调用、预算 9,000 分，目标"只买密度"。执行结果：119 次调用、8,400 分、1,746 个候选，**解析后仅 42 条 L1（2.4%）**，L3 范围外 1,343 条（76.9%）。

对照历史批次：P1 约 900 分 / 180 L1（5.0 分/条）、P1b 约 450 分 / 113 L1（4.0 分/条）。**P2 为 200 分/条，效率劣化 40–50 倍。**

| 未消耗 | 1,600 分仍在今日到期（建议不再用于检索） |

## 3. 根因（5 Why）

1. **为什么产出只有 42 条 L1？** 1,746 个候选中 1,343 条是非赌博案件（L3）——检索词把大量无关治安案件拉进来。
2. **为什么无关案件被拉进来？** 通用词（`周岁`、`前科`、`被行政拘留`）**没有加 `赌博` 锚**；MCP 是词元 AND，单独检索必然命中所有带年龄/前科的治安案件。222 个通用词候选产出 **0 条 L1**。
3. **为什么没有发现？** 工单**没有要求试点**（pilot）：未先跑 3–5 次调用测 L1 转化率，就直接铺 120 次。
4. **为什么没有审核？** 协调层**单方定稿**：未让执行方（法宝线）复核检索矩阵、未让引擎/数据侧会签、未报用户逐项确认；工单以"用户已批准方向"替代了"检索式审核"。
5. **为什么验收指标没拦住？** 工单的停止规则是"单格新增候选 <5 即停"——**度量的是候选数，不是 L1 转化率**；候选再多、全是噪声也不会触发停止。

| 用户 | 批准了"只买密度"的方向，未参与检索式细节（不应要求用户审检索式） |

## 5. 防再犯规则（即时生效，写入协调流程）

**任何 >20 次调用（>1,500 分）的工单，必须满足以下全部条件才能下发：**

1. **试点门**：先跑 3–5 次调用，实测该检索式的 **L1 转化率**；转化率 <30% 不得放量。
2. **锚定门**：要素词检索一律带 `赌博` 锚（或经书面说明的等价锚）；无锚通用词只允许用于"计数勘探"，不得用于下载工单。
3. **会签门**：检索矩阵由**执行方复核**（它最懂 MCP 噪声形态）+ 协调层定稿；跨线工单需引擎/数据侧至少一方知会。
4. **分批门**：预算分两段释放（如 30% → 验收 → 70%），不得一次性放满。
5. **验收门**：工单验收指标必须是 **L1 转化率、单位成本（分/L1）**，不是候选数；未达标立即停。
6. **事故留痕**：任何大批量工单必须在本文件同目录留"工单评审记录"（谁复核、试点结果、放量依据）。
