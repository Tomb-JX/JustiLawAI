# I-20 要素字段标注缺口：37 要素无任何标签来源（2026-10-18）

> 登记人：协调总控（Zcode 接管会话）· 状态：**待修复**（修复方案已裁定，等接口答复后开工）
> 严重度：**阻断 G2.4「M1 字段准确率」与本地学生模型蒸馏**；不阻断 G2.2/G2.3（seg-v2 标签线）。
> 发现路径：2026-10-18 基础设施审计（用户追问"要素字段标签当前的处理链路无人提供吗"）→ 逐文件核查确认。

## 1. 问题陈述

**37 个要素字段（行为类型、角色、参与方式、参赌人数、个人赌资、现场赌资、抽头渔利、营利目的、前科、年龄、场所等，见 `schema.py` 七组 37 字段）在现行全部链路中没有任何环节生产标签值。**

现有链路能产出的字段只有 seg-v1/seg-v2 的：zones（分区）、subject（本人写法）、outcome（处罚结果）、dates（行为/决定日期）、review（复议结论）、gambling（赌博判定）、confidence。

## 3. 根因（三段，缺一不会发生）

1. **两套字段集从未做过 schema 对账**：网页线的解析 schema（seg 系列：结构/结果/日期）与引擎的要素本体（schema.py 37 字段）是两套独立演进的定义，架构合并时只对齐了"分段与结果"，没有拍平"要素"这一层。
2. **金标线解散时的职能映射不完整（协调层责任）**：协调层把金标线职能映射为"seg-v1 三维仲裁 + S3 校验"，**漏掉了 37 要素标注整块**；映射表里没有"要素标签由谁产"这一行。
3. **设计文档的虚假承诺未被核查**：`parse-format-chain-design §14` 的"parsed-2 要素字段即标注集"是一句对未来的假设，从未进入实现计划；后续设计（parse-interface-v2）收窄为分区接口后，也没有人回头核对这句话。

**定性**：不是任何一条线失职，是**跨线的 schema 接缝无人负责**，加上协调层拆线时的映射遗漏。

## 4. 影响分析

| 受影响目标 | 影响 |
|---|---|
| **G2.4 M1 行政首跑** | 只能产出证据命中率、丢弃率；**"字段准确率"无金标可算**——承诺的四个数字缺一个 |
| **M4 裁量模型** | 特征来自 37 要素；没有要素标签 → 特征只能靠运行时抽取（零样本质量未知），无法用"金标特征"训练/评测；也无法做"特征取舍"决策 |
| **本地学生模型蒸馏（用户既定目标）** | 蒸馏需要教师产出的要素标签；没有标签就没有训练集，"云旗舰产标 → 蒸馏本地"的路径断在第一步 |
| **关键字段出现率（G2.1 防空转）** | `key_field_presence.py` 只能度量"原文有没有"，不能度量"抽得对不对" |
| G2.2/G2.3（seg-v2 标签线） | **不受影响**——分区/结果/日期标签仍由 seg-v2 正常产出 |

## 5. 修复方案（已裁定）

### 5.1 分工

| 主体 | 交付物 | 依据 |
|---|---|---|
| **引擎线** | ① 要素教师提示词 v1（逐字段定义、`{status, value, evidence}` 三态、空值规则、金额开口/营利目的口径按 schema 1.1.0 裁定）② 输出 JSON Schema 与校验夹具 ③ 200–300 件金标验收脚本（证据逐字命中率、枚举合法率、数值一致率、仲裁分歧率） | `schema.py` 1.1.0 + `annotation-guideline.md` v0.2 为唯一字段来源 |
| **网页线** | ① 把要素提示接入管线（复用 `s1.py` 客户端/重试/缓存/回执，S3 值-文对账，仲裁用非 deepseek 模型）② 输入＝seg-v2 zones 的 **facts 区句子**（+必要的当事人段，见 §6.2）③ 先 200–300 件产要素金标并出验收报告，达标后全量 2,451 | 管线基建与仲裁纪律现成 |
| **协调层** | 核账、维护本单状态、预算登记 | — |

### 5.2 节奏与准入

1. **不阻塞 seg-v2 试点收尾**（当前 min40d 硬失败 5%、narr20 运行中）——要素提示设计可并行开始；
2. 要素金标先 200–300 件 → 验收 → 全量；
3. 产物并入 parsed-2 的要素段（字段结构见 §6.3），随 r7 交付；
4. 全量前报预算（按 2,451 件 × 输入 ~1.5k + 输出 ~1–2k token 估算）。

### 5.3 验收标准（首批 200–300 件）

| 指标 | 门槛 |
|---|---|
| 输出结构合法（枚举/类型） | 100% |
| 证据逐字命中原文 | ≥95%（S3 值-文对账） |
| `status=未提及` 的比例 | 与 `key_field_presence.py` 的字段出现率对照，偏差 >20 个百分点即告警 |
| 双模型（非 deepseek 仲裁）数值一致率 | 报告即可，不设门槛（共识口径） |
| 仲裁分歧率 | 单列上报，>20% 回修提示 |
