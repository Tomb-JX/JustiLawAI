# 发现层设计：用百度官方搜索 API 自动化"人工发现"

> 版本 v0.1 · 2026-10-15 · 由**发现层**工作流负责（工作树 `project-data-collection-audit-4bac93`，登记见[分工文档](./workstreams.md) §1）
> 配套：[人工采集指南](./manual-collection-guide.md)（本设计把指南 §1 的人工流程自动化）· [批量采集运维计划](./crawler-ops.md) · [数据收集计划](./data-collection.md)
>
> 一句话：**用百度智能云千帆"百度搜索"API 替代人工搜索**，按查询分片把全国县级政府网站上的赌博处罚决定书和复议决定书找出来；对文书逐篇分诊，再把每篇顺着栏目扩展成可批量收割的整站栏目，交给数据链路收割。

## 0. 范围与分工

| 本工作流（发现层）负责 | 不负责（数据链路负责） |
|---|---|
| 生成检索式、调用搜索 API、缓存与控制预算 | 下载正文、登记台账（manifest） |
| 搜索结果分诊：判断文书类型、是否赌博、地区、年份 | 写站点适配器、全量收割 |
| 从单篇文书找到所在栏目、识别 CMS 家族、生成候选栏目 | 维护 `sites.csv` 状态机 |
| 输出 `urls.tsv` 和 `columns.csv` 两份交付文件（§6） | R6 隐私扫描、脱敏、标注 |

代码放在 `research/discretion/discover/`（只由发现层写），**不改** `research/discretion/collect/`。

## 1. 合规前提：为什么必须走官方 API

| 方案 | 结论 | 依据 |
|---|---|---|
| 脚本直接请求 `baidu.com/s?wd=` 再解析结果页 | ❌ 禁止 | 百度 robots.txt 对通用爬虫写的是 `User-agent: * Disallow: /`，对具名爬虫也逐个禁止 `/s?`（2026-10-15 实测）；批量请求还会触发验证码，绕过它违反项目纪律 |
| 第三方 SERP 转售（SerpApi、DataForSEO 的 Baidu 引擎等） | ❌ 不用 | 本质是替我们抓百度结果页，合规问题只是转移给了第三方；数据卡说不清来源 |
| Bing Web Search API | ❌ 不可用 | 2025-08-11 已下线 |
| **百度智能云千帆"百度搜索"API** | ✅ 采用 | 百度官方付费接口，按次计费，有站点过滤和时间过滤 |
| 人工浏览器 + 结果页提取书签（备用） | ✅ 可选 | 人手动打开的页面，用书签一键把标题和 URL 复制出来；在没有 API Key 或额度用尽时用，不自动翻页 |

## 2. 千帆"百度搜索"API 要点（2026-10-15 官方文档）

- 接口：`POST https://qianfan.baidubce.com/v2/ai_search/web_search`，鉴权头 `Authorization: Bearer <API Key>`；Key 只从环境变量 `QIANFAN_API_KEY` 读取，**不进任何文件**。
- 请求：`messages` 只取最后一轮的 `content` 作为 query；`search_source` 固定为 `baidu_search_v2`；`resource_type_filter` 里网页的 **`top_k` 最大 50**。
- 过滤：
  - `search_filter.match.site`：只在指定站点内搜索，**最多 100 个站点**（文档注明为付费功能、目前限时免费）；
  - `search_filter.range.page_time`：按网页发布时间筛选，`gte`/`lte` 支持 `now-1w/d` 这类日期表达式；
  - `block_websites`：屏蔽站点及其子站点；
  - `search_recency_filter`：只有 week、month、semiyear、year 四档。
- `query_policy.enable_rewrite`：控制是否改写 query。精确检索式应当关闭改写（是否有效由 M0 的 T6 验证）。
- 计费：每月免费 1,500 次（按天发放）；超出后按量付费，约 ¥0.036/次（价格页口径，以控制台为准）；单账号每日上限 10 万次。
- **最关键的约束**：一次调用最多返回 50 条，文档里**没有翻页参数**。所以覆盖面不能靠翻页，只能靠**查询分片**（§3.2）。

**需要 M0 实测才能确认的点**（[`probe_qianfan.py`](../../research/discretion/discover/probe_qianfan.py) 的 T1–T6，共 6 次调用）：query 里写 `site:` 是否生效；`match.site=["gov.cn"]` 是否按后缀匹配所有子域；指定域名列表时是否严格限定；`page_time` 是否按实际发布时间过滤；关闭改写的效果；每次实际返回多少条。§3 的分片策略会根据结果选 A 或 B 两种实现之一。

## 3. 架构

```
 查询模板(yaml) ─► L1 查询规划器 ─► L2 搜索执行器 ─► L3 分诊 ─► L4 栏目扩展 ─► 交付
                    (分片/饱和拆分)   (千帆API/缓存/预算) (类型/赌博/地区/文号) (CMS指纹/栏目参数)  urls.tsv
                         ▲                 │                                         columns.csv
                         └──── 结果满 50 条：继续拆分 ◄────┘                           (→ 数据链路)
                         └──── 新发现域名：写入域名库，供下一轮按站点分片 ◄──── L3
```

### 3.1 L1 查询规划器：模板

检索式由四个维度组合而成（与指南 §1.2 的人工矩阵一致，并补上反向样本）：

| 维度 | 取值 |
|---|---|
| 文书类型 D | 行政复议决定书 / 复决字 / 行政处罚决定书 / 行罚决字 / 执法结果信息 / 行政执法公示 / 双随机一公开 / 不予行政处罚决定书 |
| 赌博特征 F | 赌博 / 赌资 / 麻将 / 扑克 / 网络赌博 / 为赌博提供条件 / 抽头 |
| 法条 L | 第七十条（2025 年及以前的行为）/ 第八十二条（2026 年施行的新法） |
| 区域 R | 31 个省级 → 333 个地级 → 约 2,800 个县级名称（逐级下钻，见 §3.2） |

模板放在 `discover/queries.yaml` 并入库。每个生成的查询带上 `query_id`（模板 id + 分片键的哈希），保证可复现。

### 3.2 饱和拆分：用分片换覆盖面

单次最多 50 条，于是：

1. 从粗粒度分片开始，例如 `D × F × L × 省`。
2. 返回 **<50 条**：认为该分片已经穷尽，停止。
3. 返回 **=50 条**：结果被截断，**必须继续拆分**，按以下优先顺序：
   - **时间**：`page_time` 按年拆，再按季度拆（实现 A，前提是 T5 验证有效）；
   - **区域**：省 → 地级 → 县级，县级名称写进 query；
   - **站点**：用域名库（§3.5）把该省已知的县级域名每 100 个一组放进 `match.site`（实现 B，前提是 T4 验证严格限定）。这一维最精确，因为发现越多、分片越细。
4. 每个分片的返回数、新增 URL 数写入执行日志。**新增率**（新 URL ÷ 返回条数）连续低于 5% 的模板降权，避免在重复结果上花钱。

### 3.3 L2 搜索执行器

- **缓存**：以"请求体规范化后的 SHA-256"为键，原始响应存到 `$JUSTILAW_DATA_DIR/discover/cache/`。同一个查询不重复付费；重跑时默认读缓存，`--refresh` 才重新请求。
- **预算闸门**：`--budget N`（调用次数）和 `--max-cost ¥`，到达上限立即停止并存盘。默认上限为当日免费额度。
- **限速**：默认 1 次/秒，遇到 429 或 5xx 时指数退避，最多重试 3 次。
- **增量模式**：每周例行只跑 `search_recency_filter=week`，加上新发现域名的站点分片。

### 3.4 L3 分诊

每条结果（URL、标题、摘要、日期）生成一条候选记录：

| 字段 | 方法 |
|---|---|
| `url_norm` | 去掉 fragment 和追踪参数，统一用 https；按 `url_norm` 去重 |
| `doc_type` | 标题加摘要的正则分类：复议决定（`复决字`、`行复`、`复议决定书`）/ 处罚决定（`行罚决字`、`处罚决定书`）/ 执法结果表（`执法结果信息`、`季度`）/ 判决 / 新闻宣传 / 法规与裁量基准 / 其他 |
| `gambling` | 强特征词命中，并且**排除法条引用语境**：去掉形如"第十一条……赌具、赌资……应当收缴"的引用片段后再匹配（这条规则也建议数据链路的 `filter_gambling.py` 采用） |
| `doc_no` | 解析文号，例如 `金武政复决字〔2024〕132号`，得到机关简称和年份；在全库内按文号二次去重（同一文书常被多个页面转载） |
| `region` | 域名映射到行政区划（域名库）；映射不到时从文号中的机关简称推断 |
| `year`、`law_article` | 从文号、摘要日期、"第七十条/第八十二条"推断，用于 T-time 预筛 |
| `priority` | 处罚决定（非复议）> 复议 > 执法结果表 > 其他；2026 年加权；`不予处罚` 加权 |

`新闻宣传` 和 `法规` 两类**不交付**给数据链路做正文收割，但法规与裁量基准类单独输出一份 `norms_candidates.tsv` 给法律组（规范库，需求清单第 2 项）。

### 3.5 域名库（滚雪球）

- `discover/domains.csv`（入库）：`domain, region_code, region_name, level(省/市/县), first_seen_query, gov_type(政府/公安/司法)`。
- 初始种子：指南 §1.4 的 14 个样例域名。
- 增长方式：L3 每发现一个新的 `*.gov.cn` 域名就登记一条；行政区划用民政部区划代码表做名称匹配。
- 用途：作为 §3.2 实现 B 的站点分片，也是 L4 的输入。

### 3.6 L4 栏目扩展与 CMS 指纹

单篇文书的价值有限，**能扩展成整个栏目才有规模**。对每个 `priority` 较高的赌博候选：

1. 抓取文书页（只抓这一页，经 `common.session()` 同款浏览器头，间隔 ≥1.5s）。
2. **CMS 指纹**（2026-10-15 实测）：

| 家族 | 指纹 | 栏目参数 | 覆盖面 | 实测样例 |
|---|---|---|---|---|
| 汉网 jpaas | 页面引用 `/api-gateway/jpaas-publish-server/front/page/build/unit` | 从栏目页取 `webId`、`tplSetId`、`pageId` | **浙江省县级站点统一平台** | 武义县：`webId=3558, pageId=1229150592`；与 `collect` 里浙江司法厅的适配器是同一接口，**泛化后一套代码覆盖全省** |
| gkmlpt | URL 含 `/gkmlpt/`，页面有 `SID` | `sid`；`/gkmlpt/api/all/0?page=N&sid=` 返回 JSON，每页 100 条，含 `classify_*` 分类字段和 `document_number` | **广东省政府信息公开统一平台** | 云安公安分局：`sid=766261`，共 250 篇，接口直接返回 JSON |
| TRS 静态 | `t20240816_3223622.html`、`index_N.html` | 栏目目录 | 多省市常见 | 北京东城（已有适配器） |
| JCMS / `.shtml` | `c109939/202504/xxx.shtml` | 栏目路径 | 新疆、北京门头沟等 | 博湖县 |
| 定制站 | 无共同特征 | 需人工看 | — | 定兴 `xzzfcon-467-*`、魏县 `zhifa_show.php?cid=962` |

3. 找栏目入口：优先面包屑最后一级链接；其次"同目录同 URL 模式的兄弟链接"；再次 CMS 特有的栏目 id（jpaas 的 `pageId`、gkmlpt 的 `sid` 加分类）。
4. 估算栏目规模：只抓栏目第一页，统计条目数、标题里赌博词的占比和总页数（不下载正文）。
5. 生成 `columns.csv` 候选行（§6）。**栏目里赌博文书不少于 20 篇**才建议数据链路写适配器；属于 jpaas、gkmlpt 家族的，只需要把参数交给数据链路的"家族适配器"（建议数据链路把 `iter_zhejiang` 泛化为 `iter_jpaas(webId, tplSetId, pageId)`，并新增 `iter_gkmlpt(base, sid)`）。

## 5. 合规与安全

- 只调用官方 API；不抓百度结果页；不用第三方 SERP 转售。
- API Key 只放在环境变量；缓存目录在仓库外。
- L4 只抓文书页和栏目第一页，间隔 ≥1.5s，`trust_env=False` 直连，请求头与 `collect/common.py` 一致；遇到验证码、JS 盾或登录页一律跳过并记录。
- 搜索结果（标题、摘要）只用于内部分诊，不对外发布；交付文件只含 URL 和元数据，不含正文。
- 文书页可能露出个人信息：发现层**不保存**文书正文，只保存派生字段（类型、文号、地区、年份）。正文由数据链路收割后统一做 R6 扫描。

## 6. 交付接口（发现层 → 数据链路）

都写到 `$JUSTILAW_DATA_DIR/discover/out/<批次日期>/`，同目录附 `SHA256SUMS`：

**`urls.tsv`**（单篇文书，与指南 §1.3 的格式兼容）

```
url	title	doc_type	doc_no	region_code	year	law_article	gambling	priority	query_id	found_at
```

**`columns.csv`**（候选栏目）

```
column_id,domain,region_code,cms_family,entry_url,params_json,est_items,est_gambling,sample_urls,found_from
```

- `params_json` 示例：jpaas 写 `{"webId":"3558","tplSetId":"…","pageId":"1229150592"}`；gkmlpt 写 `{"base":"https://www.yunan.gov.cn/yfyagaj/gkmlpt","sid":"766261"}`。
- 数据链路处理完后，把 `column_id` 写进 `sites.csv` 的 `notes` 字段，形成回链；发现层下一轮据此跳过已收割的栏目。

**接口变化时先改本节和[分工文档](./workstreams.md) §5，再改代码。**

## 11. 风险

| 风险 | 预案 |
|---|---|
| `site` 过滤不支持后缀匹配或不严格限定 | 退回实现 A（时间分片 + 区域分片）；域名库只用于 L4 |
| 百度对县级站点收录不全 | 广东用 gkmlpt 的 `/api/all` 按 sid 直接枚举，浙江用 jpaas 栏目接口，不依赖搜索；其他省份后续调研省级集约化平台的站内检索 |
| 免费额度口径变化或涨价 | 预算闸门 + 缓存；每月对账 |
| 搜索结果里的政府页面失效 | 发现后 7 天内交付数据链路收割；`found_at` 字段用于追踪 |
| API 服务条款对结果存储有限制 | M0 时通读条款；响应缓存只在仓库外、仅供内部分诊与复现，不对外分发；条款若有要求，交付后按期清理缓存，只留 URL 与派生字段 |
