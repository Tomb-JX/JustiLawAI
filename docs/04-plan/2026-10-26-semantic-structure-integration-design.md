# 语义结构模型接入设计：金额归属与谓词—论元（2026-10-26）

> 状态：设计稿，待决策。本文**不安装、不启动任何模型**；第 7 节列出需要你确认的事项。
> 依据：[归属实验](../05-research/gate-reports/2026-10-26-ownership.md)、[联合判定实验](../05-research/gate-reports/2026-10-26-joint-amount-roles.md)、[供应契约 v0.1](../../../discretion-engine/docs/05-research/notes/2026-10-21-element-supply-contract-v0.1.md)。

## 1. 要解决什么（来自实验的事实）

- 金额归属（目标／他人／现场共有）：学习模型＋手工归属特征达到准确率 0.73、宏 F1 0.67，“他人”精度仅 0.45。修正人名识别边界前后无差别，**瓶颈不在找人，而在结构**。
- 现有线索表达不了的结构，都是“谁对谁做了什么、钱在谁和谁之间”：
  - 资金流向：“赵xx 通过微信**向**徐xx 转账 2000 元”；
  - 来源方：“诈骗李某南 6000 元”；
  - 分配量化：“四人事先**每人**拿三千元”；
  - 收取方：庄家“收取邝建*购买六合彩的 1100 元”；
  - 列举持有：“申请人赌资 9400 元、王某赌资 100 元、马某某赌资 10900 元”。
- 字段层面：归属特征在开发集上增益明显，但在两套独立留出上不稳定，因此未合入。
- 供应契约 v0.1 已定义 `claims`（谓词、`actor_ids`、`patient_ids`、`quantity_ref_ids`、极性、模态）、`relations`（如 `owns_amount`）和原因码 `relation_ambiguous`，**目前全是空的**。本设计的目标就是把这两层可靠地填起来，不另起结构。

## 2. 问题 → 工程问题映射

| 我们的问题 | 对应工程问题 | 判据 |
|---|---|---|
| 认出脱敏名、真名、角色称呼 | 中文 NER（领域：脱敏法律文本） | 提及召回；“他人”边的上游覆盖 |
| 申请人＝目标、别名、两个“蒙**” | 文档内共指／实体归一 | 同一人簇正确率；碰撞时输出 `subject_ambiguous` 而非猜测 |
| 持有／转账／诈骗／收取／每人拿 | 谓词—论元结构：SRL、语义依存（SDP）、依存句法 | 金额所在谓词与论元角色是否正确 |
| 这笔钱是谁的 | 以数量为锚的关系抽取（MeasEval：数量→被度量实体）；事件抽取中的金额论元 | 人—金额边 P/R/F1；“他人”精度 |
| 每人／共计／其中 | 量化辖域／分配性 | 分配句的个人值是否正确 |
| 只有约 450 条 LLM 草标归属边 | 弱监督；LLM 标注蒸馏进小模型；噪声标签学习 | 小模型对留出的精度与校准 |
| 确定性、8 GB 显卡、Python 3.14、Windows | 部署与环境隔离 | 可复现、离线、许可证合规 |

## 3. 调研结论（按问题）

### 3.1 谓词—论元：现成中文工具

| 工具 | 能力 | 许可证 | 环境风险 |
|---|---|---|---|
| HanLP 2.1 | 多任务：分词、词性、NER、依存、**语义依存（SemEval16/CSDP）**、SRL、成分、AMR | 代码 Apache-2.0；**预训练模型 CC BY-NC-SA 4.0（非商用）** | 依赖 PyTorch；对 Python 3.14 的支持未确认 |
| LTP 4（N-LTP） | 分词、词性、NER、依存、**语义依存（树/图）**、SRL；Base 模型 SRL 80.6、SDP 75.2、依存 89.5 | **学术与个人免费，商用付费** | 依赖 PyTorch 和 Transformers |
| PaddleNLP UIE | 按 schema 抽取实体、关系、事件；零样本，5-shot 微调后提升明显 | Apache-2.0 | PaddlePaddle 3.3.0 才有 cp313 轮子，且有已知 CPU 推理缺陷；Windows 风险最高 |

CSDP 关系集与我们的需要直接对应：施事 Agt、**领事 Poss**、受事 Pat、**涉事 Datv**（转账对象等）、**源事 Orig**（被骗方等）、属事 Belg、**数量 Quan／数量短语 Qp**、范围 Sco，另有反向（r-）与嵌套（d-）前缀。理论上，“谁的钱”可以读成金额节点经谓词到人物节点的语义路径。

### 3.2 句法信息是否真能帮上忙（反证）

Sachan et al.（EACL 2021）：对**已微调的 BERT**，加入**自动**依存句法，关系抽取只提升约 0.3 F1（TACRED 77.09 → 77.38）；只有用**人工标注的金标句法**时，SRL 才有明显提升（+2～3.5）。他们没有测试小数据场景。

含义：
1. 如果走微调编码器路线，不应指望外接句法能带来显著增益；
2. 我们现在用的是稀疏线性模型、约 450 条样本，处在该文没覆盖的区间，句法路径特征**可能**更有用。

所以两条路线都要实测，不能预设。

### 3.3 数量锚定关系与法律领域

- **MeasEval**（SemEval-2021 Task 8）：先识别数量，再判它与被度量实体等的关系，是公认的难任务。主流做法是流水线（数量 → 关系），或多轮问答（“这个数量度量的是什么？”）。
- **CJRC**（CCL 2019）：把裁判文书要素抽取改写为阅读理解，因为预先枚举全部要素类型不可行。
- **LEEC**（IJCAI 2024）、**LexRel**（2025-12）：在中文法律要素和法律关系抽取上，文档级事件抽取模型和 LLM 都明显受限。
- 结论：**没有现成的“赌博文书金额归属”模型或数据集**，只能借方法、用自己的数据训练。

### 3.4 关系分类的主流基线与小数据

- **类型化实体标记**（Zhou & Chen, AACL 2022）：在句中用标记包住两个论元，用编码器分类其关系；该文同时指出**标签噪声**是主要瓶颈。这是句级关系分类的事实标准基线。
- **LLM 蒸馏**：UniversalNER（ICLR 2024）把 ChatGPT 的标注蒸馏进小模型，NER 上比 ChatGPT 本身高 7～9 F1。关系抽取没有现成配方，需要自建。
- **噪声标签**：co-teaching（两个模型互相筛除疑似噪声样本）、用 LLM 的类别置信度代替硬标签、按错误类型加权损失。我们现有的“A/B 一致 + C 裁决”已经是粗粒度的一致性过滤。
- **底座**：`hfl/chinese-roberta-wwm-ext` 为 **Apache-2.0**。Lawformer 由它继续预训练而来，但没有关系抽取的评测。自训模型的许可证干净，因为训练数据是我们自己的。
- GLiNER／GLiREL：只有英文评测，中文支持未确认，不作首选。

### 3.5 环境

- 本机：RTX 5060 Laptop 8 GB（Blackwell sm_120）、31 GB 内存，主环境 Python 3.14，已有 `uv`。
- PyTorch 自 2.7 起，cu128 轮子支持 sm_120。对 Python 3.14 的支持未确认，因此训练和解析放进 **`uv` 建的 Python 3.12 隔离环境**。
- ONNX Runtime 1.24 已支持 Python 3.14：自训的小模型可导出 ONNX，在主环境 CPU 上确定性推理，主环境不必引入 PyTorch。

## 4. 方案

### 路线 A：解析器结构特征（研究期离线教师）

用 HanLP 或 LTP 跑语义依存和依存句法，结果按（原文 SHA256、工具版本、模型名）缓存为 JSONL，复跑时只读缓存。对每个（人物提及，金额）对抽取：
- 两者在 SDP 图上的最短路径标签序列（如 `Quan←持有→Poss`、`Quan←转账→Datv`）；
- 共同谓词的词形；
- 依存路径长度；
- 是否经过并列（eCoo）。

这些作为特征加进现有的三分类归属模型和四分类角色模型。

- 优点：适合小数据，可解释；直接产出契约里的 `claims`（谓词、施事、受事）。
- 缺点：两家的预训练模型都**不能商用**，只适合研究期作教师或特征；脱敏名（“张某福”“韦**”）可能被分词切碎；Sachan 等人的反证。

### 路线 B：自训“人—金额”关系分类器（产品化主路线）

- **输入**：金额所在句（必要时加前一句），用类型化标记包住一个人物提及 `[人]…[/人]` 和一个金额 `[额]…[/额]`。
- **输出**：关系类型 ∈ {持有／投入、分摊（每人各）、给出方（转出、被骗、被收取）、收取方、无关}，外加 NIL。每笔金额对所有候选人打分，再并入“现场共有”选项，得出归属。这等价于 MeasEval 的数量锚定关系，或 CJRC 式的“这笔钱是谁的”选择题。
- **底座**：`hfl/chinese-roberta-wwm-ext`（Apache-2.0），先用 base；如需更快再试 3 层小模型。
- **训练数据**：需要**人—金额对级**的标签。现有 owner 边只标了“他人”，没有指明是哪个人，所以要新做一次数据供给：用同样的 A/B/C 流程，对 735 个事件里的每个（人物提及，金额）对标关系类型。这是新任务的 schema，不是改原有提示词，估计 ¥10–15。
- **噪声处理**：A/B 一致的作为硬标签；分歧样本用 C 票或丢弃；对照 co-teaching 或置信度加权，看是否值得。
- **部署**：导出 ONNX，主环境 CPU 推理，固定 tokenizer 和权重哈希；输出写入契约的 `relations`（`owns_amount`、`pays_to` 等）和 `claims`，附 `provenance=模型名@哈希`。

### 路线 C：PaddleNLP UIE（对照基线，可选）

按 schema 零样本／少样本抽取“人物—持有—金额”。只在 Paddle 环境能稳定跑通时作为对照，不作主路线。

### 不做的

- **推理时调用 LLM**：结果不确定，与此前“降低模型随机依赖”的要求相违背。LLM 只用于离线供给标签。
- **GNN／ILP 全局解码**：此前约束实验和软竞争实验都没有带来增益。

### 架构位置

```
原文 → S1 视图 → 供应包（候选数量、目标提及）
          ↓
   [新] 人物提及＋共指（ownership.py 规则提案 → 后续可由 NER 替换）
          ↓
   [新] 人—金额关系（路线 B 模型；研究期可叠加路线 A 特征）
          ↓ 写入 claims / relations（带置信度与 provenance）
   四分类金额角色模型（softmax/semantic，已冻结）读取关系概率作为特征
          ↓
   字段绑定 bindings（bound / unresolved: relation_ambiguous / subject_ambiguous）
```

## 5. 实验计划与门槛

协议沿用此前的做法：候选固定、事件级划分、开发集嵌套交叉验证、冻结后只测一次留出；效用＝正确 − 2×（错值＋多输出）；冻结链路和现模型都作为对照。

| 编号 | 内容 | 产出／门槛 |
|---|---|---|
| X0 环境冒烟 | 建 `uv` Python 3.12 环境，装 torch cu128、HanLP、LTP；在 20 篇文书上跑 SDP、依存、SRL | 能在 GPU 上运行；**脱敏名被切碎的比例**；每篇耗时 |
| X1 解析器探针（不训练） | 在开发集 A/B 一致的归属边上，统计“金额→人物”的 SDP 路径标签与归属是否一致（Poss/Agt→持有方，Datv/Orig→对手方） | 若结构信号本身就弱（例如判对率低于 0.6），路线 A 止步，不做整合 |
| X2 路线 A 整合 | 解析器路径特征加入三分类归属模型和四分类角色模型 | 与 0.73／0.67 比较；字段效用比较 |
| X3 对级数据供给 | A/B/C 标注人—金额对关系，735 个事件 | 一致性 κ；分歧率；费用 |
| X4 路线 B 训练 | 类型化标记分类器；对比硬标签与置信度加权 | 归属宏 F1、“他人”精度；字段效用 |
| X5 融合 | 路线 B 加上路线 A 路径特征（晚融合） | 只有严格优于单路线才保留 |
| X6 冻结与留出 | 需要**新的封存集**（现有 H1、H2 已用过）：从 `lake-text-706b` 走泄漏修复后的教师输入导出，取 150–250 个事件 | 一次性报告 |

决策门槛（预先设定）：
- 归属“他人”精度 ≥ 0.7，且宏 F1 比 0.67 至少高 0.08；
- 字段效用在开发集和新留出上**都**严格优于 `softmax/semantic`；
- 确定性：同输入重复推理逐位一致；
- 生产路径不依赖非商用模型。

未达标的路线不合入。

## 6. 风险

| 风险 | 对策 |
|---|---|
| HanLP、LTP 模型非商用 | 只作研究期教师和特征；产品化只走路线 B（自训、Apache 底座） |
| 脱敏名分词错误，结构断裂 | X0 先测；必要时把提及替换为占位符（如“甲1”）再解析，并保留坐标映射 |
| LLM 对级标签有噪声 | A/B 一致过滤 + C 裁决；对照置信度加权；报告时只用一致子集估计边级精度 |
| 数据池用尽，新留出需要另一条导出链路 | X6 前单独做 lake 池的教师输入导出，并复用泄漏检查 |
| sm_120 或 Windows 环境问题 | 隔离环境；必要时退回 CPU 推理（编码器规模小，可接受） |
| 增益在独立留出上不稳定（上轮教训） | 预先设定门槛；两套留出都要达标 |

## 7. 需要你确认

1. **安装许可**：在隔离的 Python 3.12 环境里下载并安装 PyTorch（cu128，约 2–3 GB）、HanLP 和 LTP 的模型（各约 0.5–1 GB），以及 `hfl/chinese-roberta-wwm-ext`（约 0.4 GB）。按约定，启动本机模型前要先问你。
2. **许可证立场**：HanLP 和 LTP 只在研究期作教师或特征使用，产品不依赖它们。是否同意？
3. **数据供给预算**：对级关系标注约 ¥10–15；`lake` 池新留出的导出与标注约 ¥10。
4. **执行顺序**：建议 X0 → X1 先做（只装工具、不训练，半天内出结论），用 X1 的数据决定路线 A 是否继续；X3、X4 可以与之并行准备。
