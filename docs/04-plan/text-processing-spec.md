# 行政案例文本处理规范与数据对接分析

> 版本 v0.1（待引擎组、法律组确认 §5 的决策项）· 2026-10-16 · 发现层
> 适用：公开网页收割得到的行政案例（`$JUSTILAW_DATA_DIR/admin/web_cases.pre_deid.jsonl`）从"脱敏前"到"交付引擎"的全部文本处理。北大法宝、裁判文书采购等其他来源入库时也应遵守本规范。
> 依据（规范性来源）：[行政案例数据交付规格](../05-research/data-spec.md) v0.1 · 要素本体 `justilaw-api/app/discretion/schema.py` v1.0.0 与抽取器 `extract.py` · [标注指南](../05-research/annotation-guideline.md) v0.1 · [数据收集计划](./data-collection.md) §4（纳入、排除、脱敏 SOP）· [门禁](../05-research/sota-baselines-and-gates.md) R6、R7、G1.1–G1.4、G3.2 · [阶段总结](./data-pipeline-status.md)

## 0. 结论

1. **下游对文本的核心要求有三条**：
   - 事实与结论分开，模型输入里不能出现答案；
   - 要素证据必须是**最终交付文本**里的逐字片段，所以文本必须先脱敏、再冻结、再标注；
   - 一案一人，本人要能被指认（抽取器接收"目标人员"参数，标注指南要求只标本人的要素）。
2. **当前数据离可交付还差五件事**：
   - 脱敏没做：本人是真名的 385 件，其中红塔 350 件；完整身份证号 9 件、部分遮挡 82 件、出生日期明文 22 件、门牌住址 19 件；
   - 没有本人代称；
   - 没有行政区划代码；
   - 没去重；
   - 汇总条目的事实太短，不够做金标。
3. **规格之间有 5 处冲突需要拍板**（§5）：年龄要整数还是年龄段；日期保留到日还是只到月；文号与来源字段怎么处理；复议结论"驳回"怎么记；要不要新增"本人代称"字段。每项都给了建议。
4. **按纳入标准实测**：1,036 件在范围内的案例中，事实足够、结果明确、能定位到省的有 **437 件**。补上站点→区划映射后（定兴 232 件只是省份没识别出来）约 **700 件**；其中有金额的约 1/3。

## 1. 下游怎么用这些文本

| 下游环节 | 读哪些字段 | 对文本的要求 | 依据 |
|---|---|---|---|
| M1 要素抽取（教师模型预标注） | `text_facts` + 目标人员 | 证据从 `text_facts` 逐字摘录，找不到的值会被丢弃；值由代码规范化（中文数字、金额区间、日期） | `extract.py`：`extract(fact, target)`、`locate()` |
| 人工标注与校正 | `text_facts`（必要时看 `text_full`） | 每人一条；只标本人；状态分明确、推断、未提及；年龄按行为时周岁；日期只到月时取 1 日并标"推断" | 标注指南 §1–§3 |
| 标签（处罚结果） | `text_decision` → `outcome.*` | 结构化：类型、拘留天数、罚款、收缴、法条、明写情节、是否不执行拘留 | 规格 §1.4 |
| 复议、诉讼结论 | `text_review` → `review.*` | 被撤销或变更的原处罚**不能当作正确答案** | 规格 §1.4 |
| 说理训练（M6）、情节标注 | `text_reasoning` | **不作模型输入**（里面常有"情节严重""从轻"这类答案） | 规格 §1.3 |
| 规范层（法律版本、处罚空间） | `behavior_date`、`decision_date`、`region` | 2026-01-01 前后适用不同条文；从重期限 2012 版六个月、2025 版一年；省级裁量基准按 `region` 选 | 规格 §1.2，本体 `CaseMeta` |
| 引擎验收（自动） | 全部 | 必填齐全；日期可解析；处罚在该法律版本合法范围内；`text_facts` 无结论词；完整度达标 | 规格 §4 |

**由此得到的硬约束**：

- **文本冻结点**：脱敏后的 `text_full` 及各段是"正本"，标注证据的字符位置都相对它而言；冻结后任何改动（包括纠正 OCR 错字）都要重新标注受影响字段。每段附 SHA-256（`text_sha256`）。
- **段落是正本的切片**：各段必须能在 `text_full` 中原样找到，交付时附起止位置。
- **一案一人**：公安处罚决定书本来就是一人一份；汇总页每条一人；复议决定书以申请人为本人；同一事件多人时各自成案，用 `event_id` 关联（门禁 G1.3 要求按事件分组划分）。

## 3. 文本要保住哪些信息（对齐本体 37 个字段）

脱敏不能把要素抽取需要的信息一起抹掉。下表是本体字段与文本证据的对应：

| 本体字段（关键字段加粗） | 依赖的原文信息 | 脱敏时怎么处理 |
|---|---|---|
| **`conduct.behavior_type`**、**`role`**、**`method`** | "参与赌博""为赌博提供条件""组织""抽头"；玩法（麻将、牌九、炸金花、网络赌博……） | 全部保留 |
| `conduct.times`、`duration_days` | "多次""2023年9月至2024年6月" | 保留次数；日期粒度见 D2（期间只到月仍可算月数） |
| **`amounts.*`**（本人赌资、现场赌资、抽头）、单注、累计、违法所得 | 金额与其限定词（"个人赌资""现场查获""抽头""底注""封顶""充值"） | **金额与限定词一律保留** |
| **`persons.participant_count`**、累计人数 | 人名列举"陈x、王x、段xx……"或"四人" | 人名换代号时**每人一个不同代号**，否则人数就数不出来；"李xx、李xx"这类同形遮挡标 `ambiguous_persons` |
| `persons.minors_involved` | "未成年人"、年龄 | 保留 |
| `persons.civil_servant` | 工作单位、职业 | 单位名删除，保留身份类别（"国家机关工作人员""公职人员"） |
| `persons.relatives_only` | "亲属""夫妻""兄弟" | 保留称谓 |
| `venue.venue_type` | "家中""棋牌室""麻将馆""宾馆""网络平台" | **保留场所类别词**，删掉具体名称（村名、小区名、门牌号、店名） |
| **`intent.profit_purpose`** | 抽头、收台费、经营 | 保留 |
| **`circumstances.last_prior_penalty_date`**、一年内违法次数、初次违法 | "违法经历：2024年05月因赌博被××拘留三日" | **保留前科事实与日期**（至少到月），删掉作出前科处罚的具体派出所名 |
| 主动投案、如实陈述、认错认罚、消除后果、谅解、受胁迫、立功、阻碍执法、情节轻微 | 对应原文表述 | 保留 |
| **`person.age`** | 出生日期或"××岁" | 见 D1：建议换成"行为时××周岁" |
| `person.pregnant_or_nursing` | "怀孕""哺乳" | 保留 |

**实测**：事实段含"赌资"的 205 件、单注或封顶 46 件、输赢 21 件、抽头 16 件、充值或投注 24 件；有前科或违法经历描述的 138 件；出生日期在源头已被遮挡（"xxxx年xx月xx日"）的 278 件，这些案例的年龄只能标"未提及"。

## 4. 文本处理规范（规则）

### 4.1 规范化与切分

1. 去掉网页导航、页头、"当前位置"、页脚；全角空格、不间断空格转普通空格；连续空白压缩为一个；保留段落换行。
2. OCR 文本：按 `ocr.py` 纠错表处理、把版面折行并回段落；**纠错只能在冻结前做**。
3. 切分按 `parse.py` 的五种形态（叙述式、字段式、汇总、结果表、复议）。各段必须是 `text_full` 的连续子串，并记录起止位置。
4. `text_facts` 若混入"决定给予""情节严重""从轻处罚"等结论词：能移到 `text_reasoning` 的就移走，移不了的标 `facts_contains_conclusion`，留给人工处理（实测 30 件）。

### 4.2 脱敏（替换规则）

| 类别 | 识别 | 替换为 | 例 |
|---|---|---|---|
| 本人姓名（含已遮挡写法） | 违法行为人、被处罚人、申请人、行政相对人后面的称谓 | **甲** | 张绍刚 / 李xx / 王某某 → 甲 |
| 其他自然人 | 人名列举、遮挡写法（"x""×""*""某"） | 按首次出现顺序编为 乙、丙、丁……（超过 10 人用"人员11"）；同一写法视为同一人并标 `ambiguous_persons` | 陈x、王x、段xx → 乙、丙、丁 |
| 民警、执法人员姓名与警号、执法证号 | "民警××""执法人员××（编号）" | 删除 | — |
| 身份证号（完整或部分遮挡） | 18 位、15 位、带 * 的号段 | 删除整项 | 居民身份证号码为 xxx → 删除 |
| 出生日期 | "××××年××月××日出生" | 见 D1（建议"行为时××周岁"）；源头已遮挡的直接删除 | — |
| 民族、文化程度、户籍地、现住址、工作单位名 | 对应字段 | 删除；工作单位换成身份类别（若有） | — |
| 案发地点 | 乡镇、村、小区、道路、门牌、店名 | 保留县（区）一级和场所类别，其余换"某" | 在定兴县xx村朱xx家 → 在定兴县某村丙家 |
| 派出所名称 | "××派出所"（多含镇名） | "某派出所"；县（区）公安局、分局保留（规格要求 `authority`） | — |
| 电话、车牌、银行卡、账号、微信号、邮箱 | 正则 | 删除 | — |
| 文号 | `DOC_NO` 正则 | 见 D3（建议"〔文号 h:6 位哈希〕"） | — |
| 日期 | 年月日、时分 | 见 D2（建议正文到月、去掉时分；元数据保留到日） | 2024年04月18日12时40分 → 2024年04月 |
| **保留不动** | 金额、次数、人数、玩法、场所类别、平台类别、前科事实、情节表述、法条、处罚结果 | — | — |

**实现约束**：
- 替换后记录 `deid_map`，存在仓库外的受控目录，只保存"代号 → 原文位置"，**不保存原文姓名**，用于复核；
- 同一案例内代号必须一致，不同案例之间不追求一致；
- 替换后各段的起止位置要重新计算。

### 4.3 R6 隐私扫描（零命中才算通过）

- **正则**：身份证号（含部分遮挡）、手机号、固话、车牌、银行卡、邮箱、"××号""××室"门牌。
- **姓名残留**：百家姓单字或复姓开头、后接 1–2 个汉字的人名候选，排除"甲乙丙丁"代号和常见词，再交人工复核；有条件时补一道中文 NER。
- **两次扫描**：脱敏后、标注前一次；封存测试集前再一次（数据收集计划 §4）。
- 命中即停用该批次，回到脱敏环节返工（计划 §8）。

### 4.4 去重与关联（R7）

1. **完全重复**：文号哈希相同即合并，保留来源最好的一份（实测文号重复 17 组、34 件）。
2. **近重复**：MinHash，Jaccard ≥ 0.8 视为近重复；训练集与测试集之间近重复必须为 0（R7）。
3. **关联而不删除**：复议决定书引用的原处罚文号，若原处罚决定书也在库，用 `linked_ids` 互相关联（同一事件），划分时放在同一侧。
4. **同一事件多人**：同一现场、同一时间的多份决定书（如魏县同一晚 4 人），用 `event_id` 关联，划分时整组同侧（门禁 G1.3）。

### 4.5 纳入与排除（按数据收集计划 §4 量化）

| 条件 | 判定 | 实测（1,036 件） |
|---|---|---|
| ① 赌博相关、公安依治安法处理 | `in_scope` | 1,036 |
| ② 事实足以支撑要素抽取 | `text_facts` ≥ 30 字，且含赌博行为描述 | 736 |
| ③ 处罚结果明确 | `outcome.type` 已解析 | 948 |
| ④ 能定位到省 | 有区划代码 | 717（补映射后可增约 270） |
| 同时满足 ②③④ | — | **437**（补映射后约 700） |
| 其中有金额 | 规格 §2 完整度口径 | 153（补映射后约 230） |

不满足 ② 的（主要是汇总条目）不进金标，见 D6。

### 4.6 交付格式

文件放在 `$JUSTILAW_DATA_DIR/admin/admin_cases.schema-1.0.0.jsonl`，同目录附 `SHA256SUMS`。每行一件，字段如 §2，另加：

```json
{"id": "W-000123", "event_id": "E-…", "linked_ids": [], "subject_alias": "甲",
 "schema_version": "1.0.0", "pipeline_version": "harvest-0.x", "text_sha256": "…",
 "segments": {"text_facts": [120, 188], "text_decision": [230, 301]},
 "quality": {"ocr": false, "completeness": {"has_amount": true, "has_outcome": true},
             "parse_warnings": [], "ambiguous_persons": false},
 "deidentified": "是"}
```

每批交付在协作记录留一行：件数、来源构成、完整度、R6 结果。

## 5. 需要拍板的冲突（含建议）

| 编号 | 冲突 | 选项 | 建议 | 谁拍板 |
|---|---|---|---|---|
| **D1 年龄** | 本体 `person.age` 要**整数周岁**（关键字段），标注指南按出生日期算；脱敏 SOP 写"出生年月→年龄段" | A 换成"行为时××周岁"；B 按法定阈值分段（不满 14 / 14–16 / 16–18 / 18–70 / 70 以上） | **A**：本体和指南都要整数；周岁本身识别性低；法定阈值可由周岁推出。只有 22 件有明文出生日期、12 件写了"××岁"，影响面小 | 引擎 + 法律组 |
| **D2 日期粒度** | SOP 要"具体日期→年月"；本体 `behavior_date`、`decision_date` 是日期型；"一年内"从重、2026-01-01 新旧法交界都要计算 | A 正文和元数据都只到月；B 正文只到月、元数据保留到日（元数据不进模型输入） | **B**：正文按 SOP 只到月（证据可按"只到月取 1 日并标推断"处理）；元数据保留到日，以免一年期限在边界月出错。日期不含姓名时识别性较低 | 法律组 + 指导老师 |
| **D3 文号与来源** | SOP 要"文号→哈希短码"；规格 `source_ref` 要 URL 或文号；URL 指向的公开页面带原名 | A JSONL 写 URL；B JSONL 只写台账 id 和文号哈希，URL 留在台账里（仓库内 `manifest_web.csv` 已有） | **B**：交付文件本身不能直接反查到原文，溯源走台账。需要规格把 `source_ref` 放宽为"台账 id" | 引擎（改规格） |
| **D4 复议"驳回"** | 规格 `review.result` 只列维持、变更、撤销、确认违法、无；实测有"驳回"（如申请超期，复议机关未审查实体） | A 记"无"并加备注；B 规格新增"驳回" | **B**：驳回不等于原处罚被认可，混进"无"会让引擎把它当未经审查 | 引擎（改规格） |
| **D5 本人代称** | 抽取器需要"目标人员"参数，标注要求只标本人；规格没有对应字段 | 新增 `subject_alias`（固定为"甲"）与 `event_id` | **新增**：否则多人案件无法指认本人 | 引擎（改规格） |
| D6 汇总条目 | 红塔等汇总条目每条只有"因赌博"几个字，不满足纳入标准② | A 排除；B 单独存 `admin_outcomes_only.jsonl`，只用于处罚结果分布和 T-time 的结果核对，不进金标 | **B** | 引擎 |
| D7 OCR 文本 | 扫描件文本有少量错字（已纠正"题""宣告""拘留""元"等） | 冻结前人工通读一遍 OCR 案例（共 38 件） | 冻结前通读 | 发现层 |
