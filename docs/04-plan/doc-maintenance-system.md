# 文档维护体系 v1（2026-10-27，负责人指示立制）

> **立制背景**：2026-10-27 对账暴露的反模式——引擎线 13:56 收官 WP0（净入库 1,156）后，engine-line-status/data-pipeline-status/执行计划三处滞后，宏观会话花一整轮对话额度专门对账修复（dad4350）。此前还有"银标 1,300 vs 实际 1,740"同类事件。**结论：文档滞后不是靠"以后统一补"解决的，是要让每次更新的边际成本降到接近零。**

## 0. 成本分层（为什么这样设计）

| 动作 | 成本 | 用途 |
|---|---|---|
| 看板一行（`coord_event.py metric/note`） | ≈0 额度，秒级 | 快变数字的**第一落点** |
| 状态文档段落编辑（含 changelog 行） | 小额 | 检查点回写、结构性叙述变更 |
| 专门对账会话 | **一整轮对话额度** | 只允许在新会话开工包这种场景做一次，不允许成为常态 |

## 1. 三层文档模型

| 层 | 内容 | 时效要求 | 例子 |
|---|---|---|---|
| **L0 事件层** | 看板 `events.jsonl` → `CURRENT.md` 自动渲染（含指标表） | **即时，append-only** | metric/note/artifact 事件 |
| **L1 快照层** | 状态文档（叙述+数字快照，带 as-of 章） | **检查点同步**（§3 R3） | engine-line-status、data-pipeline-status、briefing |
| **L2 权威层** | 门槛/设计/诊断/执行计划 | **同提交变更+changelog**，门槛类走 deviation-log | gates v0.7、设计文档、ml-review、执行计划 |

## 2. 六条规则

**R1 设计/实现变动 → 同提交文档反馈**。任何改变行为、数据、接口的提交，**同一 commit** 必须包含对应文档更新（代码与 docs 不拆两个 commit 提交后忘记）。确实做不到同 commit 的（如产物只落 $DATA），**同会话收尾前**补齐，并在看板挂 `doc-debt` note（带文档路径）；下一个触及该文档的会话开工先清 doc-debt。

**R2 快变数字 → 立即入板，不等统一更新**。下列"快变数字清单"变化时，第一动作是看板一行 metric/note（秒级），**禁止**"攒着以后专门更新"：
- 湖底账（records / docs / batches）
- 现行训练基座（包名 / 条数 / 事件数 / 划分）
- 各批 S1 供给（产出 / 合格率 / 净入库 / 成本）
- 门禁达成度实测（dev-only 三套 per-cohort 数字，发布必须带口径标签）
- provider 余额 / 累计花费
- 挂账项状态变化（open→done 等）

**R3 检查点同步（L0→L1）**。状态文档在三个触发点任一到达时做增量回写（把看板新数字灌回 + 盖 as-of 章 + changelog 行）：①会话收尾；②工单/WP 完成；③每日循环边界。**"之后再专门对账"模式废除**——积压超过一个检查点即为违规。

**R4 快照标注与单一权威**。看板指标表是快变数字的**运行时唯一权威**；L1 文档头部必须有 as-of 行（"本文数字截至 X；快变数字以看板为准"），文内数字只是快照。引用他文数字必须带 as-of 日期；被取代的数字**就地划线/标注**（保留既有惯例，不删除历史）。

**R5 工单验收含文档项**。所有 handoff 的 accept 条款必须含一条："完成时对应状态文档已更新（或显式声明无需更新）"。已挂出的 open 工单（如 `m4-full-route-20261027`）自本制度发布起**视同附加**此条，由协调线在看板说明。

**R6 权威层变更走登记**。L2 文档的实质性修改必须：changelog 行 +（门槛/口径类）deviation-log D-00X 登记 + 负责人批准留痕。ml-review 这类**冻结合并**文档不就地改——延伸结论写进指针文件（执行计划/状态文档），保持原 blob 稳定。

## 3. 文档×责任矩阵（谁在何时更新什么）

| 文档 | 层 | 更新触发 | 责任线 |
|---|---|---|---|
| 看板 events.jsonl（metric/note/artifact） | L0 | 即时（R2） | 各线自己 |
| collab-log.md | L0.5 | 每个会话动作当日 | 各线自己 |
| engine-line-status | L1 | 模型/评测/引擎侧供给变化后的检查点 | engine（产出方会话） |
| data-pipeline-status | L1 | 湖/批次/S1 供给变化后的检查点 | data/postprocessing（产出方会话） |
| 会话开工包（briefing 类） | L1 | 新会话开工前核对/增补 | 协调线 |
| 执行计划（WP 状态） | L2 | WP 状态变化**同会话** | 协调/宏观 |
| sota-baselines-and-gates | L2 | 仅门槛修订（D-00X + 负责人） | 负责人批准后执行 |
| 设计文档 / ml-review | L2 | R6 登记；ml-review 冻结不就地改 | 协调 |
| deviation-log | L2 | 任何口径/门槛偏离即时 | 提出会话 |
| `docs/06-algorithm/`（算法：问题骨架、现行架构、ADR、结论/问题台账、实验索引、评估协议） | L2 | 算法变动**同提交**改 architecture；实验结束即加索引行与结论；对话中定下的设计当天落 ADR（该目录 README 规则 A1–A5） | 引擎（产出方会话） |
