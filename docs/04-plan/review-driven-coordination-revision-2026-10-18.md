## 1. 评审指出的协调问题（按协调层责任归类）

| # | 问题 | 评审证据 | 协调层判断 |
|---|---|---|---|
| P1 | **阶段依赖扩大**：`stage-plan-v2 §0` 说阶段目标是首跑并量化失败，`§2` 却把全量 2,451 parsed-2 与 I-20 要素标注排在 M1/M4 之前，并称只有两项可并行 | B4 是 TF-IDF＋SVM/LR，输入不依赖 36 要素标签；I-20 明说 M1 仍可报证据命中/丢弃率 | **成立，我的规划错误**；须拆“开发切片首跑”与“正式全量交付” |
| P2 | **职责混合**：网页线同时承担来源获取、文本治理、分段、结果抽取、36 要素教师标注、仲裁、法律锚、质量报告；I-20 又把教师任务并入来源链 | 来源是否可用 vs 教师是否正确是两种失败；同一 parsed-2 版本号不能替两者作证明 | **成立**；须写清逻辑职责边界（不新增服务/schema） |
| P3 | **标注工厂与 M1 重复能力**：教师与学生各自建输入构造、数值/证据处理、字段投影；同一字段两套真实含义 | 网页 S3 能处理部分大写金额，引擎 `parse_amount` 同类写法返回 null；教师缺组→未提及，学生无法解析→丢弃 | **成立**；共享字段定义/归一/最终证据校验，调用与答案仍独立；先同切片对拍再决定公共代码 |
| P4 | **局部指标替代项目成效**：zones/JSON、decision F1、引文坐标、A/B 一致、标签覆盖、S3 硬失败等被当成绩效 | 这些只证明管线内部状态，不证明处罚目标可得、事实未泄漏、抽取改善预测 | **成立**；指标须由消费需求解释，不得把局部合格率当项目增益 |
| P5 | **信息不足当成抽取/模型能力问题**：关键词出现率被当作字段真值，默认加仲裁/提模型档 | 关键词代理非真值；公开文书事实密度与产品输入不同 | **成立**；先查全文与允许输入、按来源/形态分层，再判断买数据还是修提取 |
| P6 | **两类结果混淆**：公开文书的实际处罚（历史观察值）与规范层计算的可行结论被混成一个“正确答案”；法律锚可能改写训练目标 | 既有 F5 是代码表现；若用规范改写后的标签评测，得到自洽而非独立质量 | **成立**；历史观察值保留，规范冲突另报；字段标注使用时点/来源/消费 |

## 2. 协调层裁定（接受/修订）

| 编号 | 裁定 | 生效方式 |
|---|---|---|
| A-01 | **依赖改为“合格开发切片 → 并行诊断；全量 → 正式交付”** | 修订 `stage-plan-v2` §2/§3；正式门禁不变 |
| A-02 | 来源资产、教师参考、学生输出、评测结论各自独立版本/资格 | 写入 workstreams 职责边界；不新建服务 |
| A-03 | 教师与学生共享字段语义、归一化、最终证据验证；调用与答案独立 | 先在同一个开发切片对拍两端输出与失败原因，再决定公共函数边界 |
| A-04 | M3/M5/多专家/丰富 M6 按下游增益逐项进入 | 原门禁增益条件不变；阶段二只做最小可解释实验 |
| A-05 | 分离历史观察目标、规范结论、部署可知输入 | 字段清单逐项写使用时点/来源/消费；F5 按引擎归属修 |
| A-06 | 阶段二退出＝质量报告能支持下一步取舍；正式完成仍按原门禁 | 不把开发首跑/模型共识/卡片数冒充正式认证 |

## 3. 修订后的阶段二依赖（已写入 stage-plan-v2）

```
G2.1 r6 格式关口（已完成）
  ├─ G2.2a 合格开发切片（网页）──┬─ G2.3a M1 诊断首跑（引擎）
  │                              ├─ G2.3b M4 基线首跑（引擎）
  │                              └─ G2.3c I-20 要素参考首批（引擎契约+网页管线，并行）
  └─ G2.2b 质量证据包（正式放行用，不阻塞 G2.3a/b）
        └─ G2.4 全量 parsed-2 装配（正式交付轨，不阻塞 G2.3a/b）
              └─ G2.5 r7 正式交付（原门禁不变）
G2.6 闭环质量报告（协调；G2.3a/b 后可先出阶段性版）
```

**关键变化**：全量 2,451 与 I-20 不再是 M1/M4 首跑的前置；首跑只需“合格开发切片”。切片仍须核对原文、本人、事实/答案隔离、历史处罚目标与事件去重；不得把未过内容检查的数据拿来训练；切片与总体差异要报告，不推广到全库。

## 4. 逻辑职责边界（写入 workstreams，不新增服务）

| 逻辑职责 | 承诺 | 不应代为承诺 |
|---|---|---|
| 来源与案例准备 | 原文不变、出处可追、本人/事件可定位、输入视图与历史结果各有证据 | 模型标签已正确、要素特征一定足够 |
| 抽取能力 | 从被允许的事实视图抽取当前契约，输出可验证候选与未知 | 源头没写的事实、法律应然结论、自己给自己判准确率 |
| 教师与参考标注 | 在冻结案例上产独立有版本的训练/开发参考与分歧记录 | 来源格式通过＝标签通过；模型共识＝人工真值 |
| 规范与预测 | 按已知事实算规范结论；按训练数据预测历史结果 | 修改原文事实以适应规范/预测 |
| 独立评测与报告 | 对特定能力、数据、版本给结论与局限 | 用管线内部 ok 数替代外部正确性 |

## 5. 指标层级（防止指标替代成效）

| 层级 | 回答什么 | 例 |
|---|---|---|
| 项目主线 | 给定处罚前可得案情，能否给可追溯、带不确定性的定性/处罚辅助？ | 端到端卡片可用性、依据可核 |
| 阶段二诊断 | 现有行政材料能否支持这条路线；首跑失败在哪；先改哪一环 | 切片覆盖与事件数、M1 证据/结构/丢弃、文本 vs 特征同切片比较、M2 可处理/需复核比例、成本与失败去向 |
| 模块指标 | 本模块内部是否满足契约 | zones/JSON、decision F1、引文坐标、A/B 一致、S3 硬失败 |

**规则**：模块指标必须由消费需求解释；不得把 S3 门槛、A/B 一致率、标签覆盖条数说成项目增益；局部 F1 低只有在影响处罚目标/事实隔离/产品消费时才是首跑阻塞。

## 6. 两类结果的分离（引擎/数据接口）

1. **历史观察值**：公开文书的实际处罚，是统计模型首先拟合的目标；不得被法律锚改成“合法候选”。
2. **规范结论**：规范层在给定事实与适用规范下的可行/待确认结论，单独输出与报告；冲突单独登记。
3. **部署可知输入**：处罚决定中的“情节严重/从轻”等既成认定可作为文书记载标签/待预测目标；在研究“处罚前事实能否预测结果”时，未经论证不得当输入特征。
4. 字段清单逐项写 **使用时点、来源、消费任务**；这一条交引擎在 element-v2/契约修订中落实。

## 7. 待确认接缝（协调层不单方面改）

| 接缝 | 现状 | 处置 |
|---|---|---|
| I-20 的“分歧 >20% 回修告警” vs 引擎脚本 `pilot_pass` 阻断 | 文档/实现效力不一致 | 保留脚本现判定，同时报两个口径；请引擎确认后统一 |
| decision 边界与 `legal_basis/operative_outcome/execution` 细粒度引用 | 评审建议；涉及契约升版 | 引擎/网页在下一整批前登记实施；本批不改 |
| 教师/学生共享字段语义与公共代码边界 | 评审建议先同切片对拍 | 先在 G2.2a 切片上对拍，再决定抽公共函数 |
| r7 数字条件 | S3<5%、字段级、要素参考、引擎验收 | 原门禁不变；正式放行仍按 G2.2b/G2.4/G2.5 |
| 候选规模 2,918 vs 2,451 | 口径不同（build 前并集 vs 全量） | 正式工单固定来源批次/去重事件/目标本人后重算 N |

## 8. 本修订不做什么

- 不停止任何会话、不重命名资产、不放行 r7、不删改 KEY_FIELDS、不改门禁阈值。
- 不合并评审分支；评审结论由各归属线按契约升版流程采纳。
- 不把开发性首跑、模型共识或卡片数写成正式质量认证。
