## 2. 网页线已给出的结论（你要独立复核，不是照单全收）

来源：`docs/04-plan/model-call-design-reflection-2026-10-18.md`（D1–D6）与 `model-call-design-full-record-2026-10-18.md`（5 调用站 + O1–O12）。

| 编号 | 结论 | 要点 |
|---|---|---|
| **D1** | 一次调用塞异构任务 | seg-v2 一次调用同时做分区/结果抽取/日期规范化/赌博判定/置信自评；elements 一次出 36 字段七类型。错误率由任务种类相加。 |
| **D2** | 让模型抄文本 | v1 引文逐字命中是“恰好抄对”；elements 的 evidence=逐字引文同错重演，S2 定位/消歧/回填是给转写擦屁股。句表已给坐标系，应改用**句编号引用**。 |
| **D3** | 分歧当成本不当信号 | 双盲分歧是**定义歧义探测器**；应出字段级分歧榜回修定义，而不是付钱仲裁掩盖。 |
| **D4** | 没有字段级错误模型 | 36 字段难度差几个量级，共享一套提示与记录级验收；8.7%/95.2% 聚合数掩盖漏水。需 KEY/常规/源头遮蔽三档目标。 |
| **D5** | 设计验证依赖付费批 | 已有 1,600+ 条真实输出，契约改动 90% 可离线重放；付费批应只做终确认。 |
| **D6** | 流程即接口 | 批尾写、补丁未验证即宣称修复、熔断无时间窗、批内改流程——都在给数据集注入不一致。设计变更只从整批边界起效。 |

**开放决策点 O1–O12**（原文见 full-record §9，摘要）：
O1 C 仲裁原始响应不落盘；O2 裁判裸 json.loads；O3 legal_anchor 用两版本较小上限判死；O4 站 2–5 无重试/熔断；O5 教师输出违规不反馈重试；O6 分歧判据含 status/坐标（值同壳异）；O7 公示族仍要模型输出 zones 再覆写；O8 裁判/仲裁正文截断 4000 字；O9 elements 目录混三代代码账；O10 预估兜底 0.12/件 vs 实测 0.085；O11 版本登记分散；O12 C 降级逐字段不写独立 receipts。

## 3. 你的评审任务（必须逐项回答）

1. **D1–D6 是否成立？** 逐条给出：接受 / 部分接受 / 反驳，附证据（可用现有 outputs/日志/代码行号）。特别注意 D2 的“句编号引用”是否真的能消除证据定位问题（多句证据、同一句多字段、句子边界变化时怎么办）。
2. **目标调用架构**：给出调用站清单——每站做**一类**任务；每站的输入、输出 schema、失败语义、重试策略、版本字段。至少回答：分区与抽取是否拆两次？36 字段如何分组（按值类型/按依赖/按难度）？公示族是否单独提示词？
3. **decision 区间语义**：F1 0.487（spec50 0.393）的最大争议是“结果部分”还是“含依据与执行的完整决定块”。给出唯一裁定与提示词/schema 写法，并说明它如何影响后续标签（outcome 抽取、M4 标签）。
4. **字段级错误模型**：36 字段分档（KEY 10 / 常规 / 源头遮蔽）与每档验收口径；给出“未提及率健康区间”的定义；说明首批 88 件分歧榜如何转成 element-v2 定义修订（role/venue/behavior/method/times/participant/age 七项逐一给裁决规则草案）。
5. **免费重放校验**：从现有 1,600+ 条输出中，哪些改动可离线验证、怎么验证（输入重建/输出对拍/字段级统计）；哪些必须付费烟测；给出重放套件的接口与验收。
6. **下一付费批的最小设计**：批大小、每件调用数、预算上限、试点转化率门槛（沿用 I-21 六道门）、成功判据（S3 硬失败、字段级准确率、L1 转化率、分/条）。**不得建议一次性全量 2,451。**
7. **O1–O12 逐项裁定**（采纳/不采纳/延后），并给出实现归属（网页/引擎/协调）。
8. **r7 门禁**：在 r6/r7 严禁混版的前提下，给出 r7 放行的具体数字条件与验收顺序（S3→字段级→要素标签→引擎验收）。
