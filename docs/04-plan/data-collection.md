## 3. 渠道清单

### A. 公安机关脱敏案卷 —— 【搁置】

2026-10-15 团队决定搁置，转公开渠道优先。恢复时从协议（§6.4）与脱敏 SOP 步骤继续；T-admin 非复议构成已由公开网页链路解决（93% 非复议），紧迫性下降。

### B. 行政复议专栏直采 —— 【归档，2026-10-16】

- 实测终值：五站 825 件（浙江 58 / 东城 124 / 门头沟 49 / 北京市局 194 公告 + 103 PDF / 深圳 400）**全量正文初筛强命中 0**。此前"东城强命中 1"经核实是《治安管理处罚法》第十一条收缴条款的引文误报；浙江 58 份 PDF 补抽正文后同样 0。
- 处置：停止新站适配投入；`collect/crawl_reconsider.py` 框架、[crawler-ops.md](./crawler-ops.md) 站点台账与已知坑**留作参考**（若未来需要回采某专栏可直接复用迭代器写法）。台账 `manifest.csv` 保留 869 行（B 867 + D 2）作数据卡来源构成证据。

### B′/E. 公开网页（县级公安公示 + 政府复议决定）—— 行政主力【发现层负责发现与收割】

- 链路：千帆百度搜索官方 API → 分诊（`triage.py`）→ 交付 `urls.tsv` → 收割（`harvest.py`）→ OCR → 解析（`parse.py`）→ `$JUSTILAW_DATA_DIR/admin/web_cases.pre_deid.jsonl`。设计与状态见[发现层设计](./search-discovery-design.md)、[公开网页收割](./web-harvest-design.md)、[阶段总结](./data-pipeline-status.md)。
- 现状：**在范围内 1,036 件**（非复议 93%、结果解析 92%、信息完整 263 件）；每周一 09:00 例行增量交付 `$JUSTILAW_DATA_DIR/discover/out/<日期>/urls_new.tsv`。
- 硬缺口：信息完整度 25%（规格要求 ≥80%）、不予处罚 0 件、汇总页贫信息撑高件数——对应[阶段总结 §8](./data-pipeline-status.md) 第 4、5 项。
- **数据链路职责**：接收交付并核台账、脱敏 + R6 复核（第 1 项）、试标 50 件抽取（第 3 项）。

### C1. 北大法宝 MCP 目录服务 —— 稀缺类与普查【数据链路负责调用】

- 只返回目录（文号、处罚机关、处罚种类、依据法条、链接），**无正文**，每次 ≤20 条、75 积分。三个用途：① **普查**选省（省 × 年份命中总数）；② "机关 + 文号"反查原发布机关公示页取全文（交发现层收割）；③ `documentNo="不决字"` 定位**不予处罚决定书**（G3.2，现有 0 件）。
- 纪律：统一走引擎的共用调用层 `research/eval/pkulaw_mcp/`（预算上限、缓存、按 `--workstream data` 记账）；**积分与引擎共用，8,300 分 11-15 过期**，③–⑥ 类调用先在协作记录对齐再执行。详见[手册 §7/§8](./pkulaw-playbook.md) 与[执法库调研](../05-research/pkulaw-mcp-enforcement.md)。
- ZCode 配置已含 13 服务（行政执法、检察文书、沿革、积分查询 2026-10-16 补入）；MCP 方式需重启会话生效，脚本方式即时可用。

### C2. 北大法宝网页人工导出 —— 订阅绑定后启用

- 检索式 R1–R5 与导出 SOP 见[pkulaw-playbook](./pkulaw-playbook.md)；导出文件经 `import_manual.py` 入台账（channel=C）。当前免费账户只能看结构化字段，**待学院订阅绑定后复测并启用**；仍遵守红线：不写网页抓取脚本、不绕限额。

### C′. 裁判文书第三方采购 —— 引擎提需求、数据链路入库

- 行政（Q1）：全文"赌博"判决+裁定 ~3,970 份，**每份判决 = 带法院复核意见的处罚案例**（复述原处罚 + `review.result`），本地按管辖条款/行为词过滤；刑事（Q2）：案由赌博罪/开设赌场罪、只要判决书、全量 ~19 万，按"省份 × 年份 × 罪名"本地分层抽样。
- 入库（数据链路）：到货放 `$JUSTILAW_DATA_DIR/inbox/wenshu/` → `ingest_wenshu.py` 按替代主键（案号+文书类型+裁判日期+正文 SHA-1）去重、省份自案号推导、丢弃当事人列 → 台账 channel=C（ref=案号#主键短哈希，来源注明第三方采购）→ 脱敏后才进训练流程。
- 合规：来源合规性无法自证，**下单前指导老师确认**；只作研究、不分发；数据卡如实记录。

## 4. 处理流水线（对齐[交付规格](../05-research/data-spec.md) v0.1）

```
原料（发现层 harvest / 法宝导出 / C′ 到货） → 登记台账（collect/manifest.csv 或 harvest/manifest_web.csv）
  → 资格筛选（赌博三态 + 不予处罚必须收） → 脱敏 SOP + R6 扫描 → 去重（文号 + MinHash）+ 区划编码
  → 按"事实/理由/决定/复议审查"分段 → 教师银标（B1） → 人工校正 → 金标 → admin_cases.schema-1.0.0.jsonl 交引擎
```

- **入库硬条件**（规格 §1）：来源五字段齐全、`behavior_date`/`decision_date`/`authority`/`region` 可解析、处罚结果结构化、信息完整度（有金额且结果齐全）≥80%——不达标的批次引擎自动退回。
- **脱敏 SOP**：姓名→编号；删证件号/住址/电话/车牌；出生年月→年龄段；日期粒度、文号处理方式等 **D1–D5 待引擎+法律组拍板**（[文本处理规范 §5](./text-processing-spec.md)），拍板前 3,693 件原料不得交引擎。
- 台账：`collect/manifest.csv`（channel B/C/D/manual，id 前缀=渠道字母）与发现层 `harvest/manifest_web.csv`（W- 前缀）并列；两份都是数据卡 G1.4 的来源构成证据。

## 5. 标注体系（按引擎 2026-10-15 变更：银标 + 主动学习）

- **流程**：教师模型（B1，G0.5 选定）对采集文书与 CAIL 子集全部打**银标** → 人工只校正两类：随机抽样 ≥100 件（估计银标质量，G2.12）+ 引擎挑出的最不确定案例 → 银标只用于训练；**测试集只用金标**，进过测试集的银标件须人工重标（门禁 §7）。
- **试标 50 件**（G0.3，κ≥0.80）：从 263 件信息完整案例中抽，前提是完成脱敏（D1–D5 后）。
- **质控**：分歧仲裁；cleanlab 疑似错误全复核，标签错误率 ≤3%；指南版本化。
- **B-H 专项**（G1.6）：2 名法律组成员对 ≥60 件盲测（只看案情），保管人分发脱敏输入。

## 6. 数据治理与封存

1. **存放**：原始件与派生件统一在仓库外 `$JUSTILAW_DATA_DIR`（默认 `D:/02_Dev/Data/justilaw-research/`）；仓库只留台账、脚本与哈希。含个人信息产物（`pre_deid`、OCR、法宝缓存）**永不入仓库、不上云**。
2. **封存**（门禁 §7）：T-admin / T-time / T-crim 保管人一人持有，SHA-256 登记门禁文档，仅经 `run_gate.py` 访问并记 access-log。
3. **划分协议**：按**事件分组**（同一查处多人同侧；行政判决按"处罚机关+违法行为日期"分组）；时间外推 + 地域外推；预处理只在训练集拟合；MinHash Jaccard ≥0.8 配对必须为 0（R7）。
4. **合作数据协议要点**：用途限定本项目；仅交付脱敏数据；结题后销毁；符合《个人信息保护法》。
5. **数据卡**（G1.4）：来源构成（可直接取[阶段总结 §4–§5](./data-pipeline-status.md)）、采集窗口、选择偏差（复议偏置、公开公示偏轻罚）、脱敏方式、划分方法。
