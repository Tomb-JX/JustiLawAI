# 解析架构 v2：正则退位、模型分段、规则转校验（2026-10-17）

> 定位：对 10-17 评审意见的架构回应。结论先行——**分段/要素/结果抽取是语义任务，正则方案在这个输入分布上不可能收敛，应当由远程旗舰模型承接生成、确定性规则退居校验**。本文先给量化论证（42 项小问题逐类映射），再给新架构与灰度路径。
> 模型纪律（用户既定）：只用远程旗舰（与金标线同款：deepseek-v4-pro / qwen3.8-max / kimi-k3 一级）；**永不用本地小模型**（ollama 9b 类效果有限，禁止进入任何生产环节）。
> **2026-10-17 决策更新**：脱敏限制已完全取消（规范文档的对应修订由协调层承接）。本文"人名脱敏→模型 NER 复核"路线与 §6 候选 A 随之退出主管线（外发衍生可选）；细化修订见《解析层 v2 工程设计》v2.1——主管线去预脱敏（五阶段 S0–S4）、定位链去 deid 投影、标注直接绑定原文正本。

## 1. 承认问题：正则路线的量化死因

过去约 30 小时、7 轮修复的产出不是"正则在变好"，而是**无界长尾的实测曲线**：

| 实测事实 | 数字 | 说明 |
|---|---|---|
| parse 版本补丁节奏 | 0.4→0.5→0.6，仅 0.6 一批就 8 个修复区域，注释里逐条标注事故出处 | 每轮修复都由"发现新形态"触发 |
| 未分段 357 件 | 321 件**无锚点**（公示表格 274 + 无锚叙述 47） | 锚点法对无程式文本是**定义性盲区**——没有锚点可匹配，写多少正则都没用 |
| 定性句混入 132 处 | "行为已构成赌博"出现在"现查明"段内/段中 | 事实 vs 定性是**语义判断**：表面结构相近，正则只能靠词面近似 |
| 证据/理由边界过度延伸 93 处 | "…等证据予以**证实，本机关依法予以认定**。" | 边界由语义决定，8 字窗口式正则注定追着变体跑 |
| 标签字/拼接尾 ~119 处 | "¶事由¶赌博"、逗号尾 251（公示拼接 232） | 字段拼装长尾，每站格式不同 |
| outcome 未解析 90 件 | 结果表述变体长尾 | 同上 |
| 人名脱敏 7 轮/22 规则 | 12 条规则在 2,513 件中命中 <120；金标模型仍能发现漏网 | 人名识别是 NER 任务，规则只能覆盖"列举过的语境" |
| QC 电池对金标回退覆盖率 | **42%**（14/33） | 正则级检测的天花板实测——58% 需要语义理解 |
| 每次重建正文哈希变化 | 42 件/次 | 分段规则一动，边界全变——**规则产出物天然不稳定** |

**结论**：四类最大缺陷（未分段 357、定性句 132、证据/理由边界 93、outcome 未解析 90，合计 **672 处**）全部属于"语义判断/无界长尾"，正则在原理上无法收敛——这不是正则写得不好，是任务性质不匹配。继续调正则 = 在 672 处之外追加补丁。

## 2. 42 项小问题的架构映射（逐类：消灭/保留/上游）

| 问题类（量化） | 为什么正则解决不了 | v2 架构归属 |
|---|---|---|
| 无锚点未分段（357 件，含五河簇 36） | 无程式锚点=定义性盲区 | **模型分段** |
| 定性句混入（132） | 事实/定性是语义区分 | **模型分段**（提示词中显式定义"定性句不入事实段"） |
| 证据/理由边界（93） | 边界语义决定 | **模型分段** |
| outcome 未解析/变体（90+） | 表述长尾 | **模型抽取**（结构化输出） |
| 标签字/拼接尾/导航（~200） | 格式长尾 | **清理层（确定性规则能覆盖大头）**+ 模型容错 |
| OCR 噪声（"06曰17"） | 上游感知问题 | OCR 层（不变）+ 模型对轻度噪声容错 |
| 脱敏人名 7 轮打地鼠 | NER 是语义任务 | **随脱敏取消退出主管线**（2026-10-17）；外发衍生如需人名遮蔽，用模型 NER（同一基建）离线跑、独立定版 |
| 定性句双口径（51 vs 132） | 口径=语义定义 | 模型分段后口径由提示词唯一定义 |
| 日期倒挂 9/数额矛盾/法条-版本 | **确定性校验——规则可靠** | **保留为校验器**（规则的新角色） |
| 事件家族碎裂（4 event/家族） | 键设计问题 | 保留为规则（改键=文号优先） |
| 去重/文号哈希/台账 | 确定性 | 保留 |
| tier/inclusion 两份判定 | 逻辑重复 | 合并为校验器模块（架构重构顺带） |

统计：672 处语义类缺陷 → 模型层；~300 处格式噪声 → 清理层；~30 处确定性校验 → 保留为规则。**正则的存量工作里，真正该留在大意义上的只有"校验"和"清理"两个角色。**

## 3. v2 架构

```
原文 text ─► 清理层（确定性：去导航/合续行/全角归一/标签字，保留位置映射）
   │
   ├─► 模型分段与抽取（远程旗舰，temperature=0，结构化输出）
   │     输入：清理后正文 + 固定提示（五段定义、字段 schema、3–5 个少样本）
   │     输出 JSON：{segments:[{type, quote}], outcome:{…}, subject, dates, …}
   │     ★ 模型只产出【引文 quote】，不产出坐标——坐标由确定性代码在原文中
   │       逐字定位（含唯一性检查）。模型幻觉/错位被结构性消除：
   │       引文找不到原文 = 该字段无效 → 进低置信队列，而不是错着入库。
   │
   ├─► 确定性校验器（规则的新角色）：
   │     quote 定位与重叠检查、outcome 内部一致性（类型↔数额↔法条↔版本）、
   │     日期顺序、事件键（文号优先）、去重、tier/inclusion
   │
   ├─► 失败分级：校验不过 → 换模型/换提示重试一次 → 仍不过 → 低置信队列（人工，
   │     量小且集中——对比现状：357 未分段静默漏斗）
   │
   └─► parsed-1（parser 字段记 "model:deepseek-v4-pro@seg-v1"——模型+提示版本
        进溯源字段，temperature=0 + 固定提示下输出可复现）
```

**三个人工 roles（人力只花在不可替代处）**：
1. **分段答案测试（评测集）**：人工标 100–200 件五段边界做金标准——模型方案的效果分母（这正是"人力进行分段答案测试"的正确定位：人定答案，模型干活）。
2. **低置信队列审核**：量小、集中、有上下文工具（mask_review）辅助。
3. **OCR 校对**：存量 99 件 + 增量。

**可复用的现成资产**：金标线的旗舰调用基建（run_manifest/receipts/retry_history/三模型并行）整套可以搬到 parse 层——`qa/pilot50-r4-flagship-review-20261017/` 就是原型。

## 4. 灰度路径（不推翻 parse.py，双轨对比后切主）

1. **评测集先行**：人工标注 100–200 件分段金标准（分层：叙述式/字段式/表格/OCR 各占比例）。
2. **双轨跑**：同一批正文，parse.py（现行）与模型层各产出一份分段/抽取。
3. **量化切换标准**（在评测集上）：边界 F1、要素出现率（key_field_presence）、outcome 字段准确率、quote 命中率——模型层 ≥ parse.py 基线且校验失败率 <5% 才切主。
4. **切换后 parse.py 降级为**：清理层 + 校验器 + 模型不可用时的离线兜底（产出标 `low_confidence`）。

## 5. 成本量级与风险

- **调用量**：全库 parsed 5,739 件 × 一次旗舰调用（输入约 1.5–2k token、输出约 0.5k）；增量每周数百件。价格以各模型控制台为准；金标线 50 件复检已经验证了这条链路的工程可行性。三模型并行只用于抽检复核，生产分段单模型即可。
- **风险与对策**：
  - 输出不稳定 → temperature=0 + 固定提示 + JSON schema 约束 + quote 定位校验；
  - 幻觉 → 只认逐字命中的引文，找不到即无效（结构性防线，比正则漏网更硬）；
  - 长文截断 → 分段按页处理（现状本来就是页级），超长页先粗切块；
  - 模型服务不可用 → parse.py 兜底产出，标低置信；
  - 复现性 → 模型 id + 提示版本入库（parsed-1 的 parser 字段），评测集定期回归。
