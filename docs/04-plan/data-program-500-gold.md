## 3. 来源到金标的单向交接

| 层 | 唯一写入方 | 交付件与验收点 |
|---|---|---|
| L0 原始 | 各来源负责人 | `$JUSTILAW_DATA_DIR/raw/<来源>/<批次>/` 或现存 `inbox/` 的冻结快照；原件清单、SHA-256、来源和获取日期。原件与登录态不入仓库 |
| L1 解析 | 各来源负责人 | `parsed/<来源>/<批次>/records.jsonl` + `stats.json` + 输入哈希；`records check --layer parsed` 无 error；一文一人、L1–L4 分级和台账 ID 完整 |
| L2 构建 | 网页线指定的一名构建负责人 | 按明确列出的 L1 批次合并，统一脱敏、R6、跨源去重、区划、事件分组和分流；记录代码提交及每个输入哈希 |
| L3 交付 | 同一构建负责人 | `delivery/<版本>/`：主文件、only 文件、排除清单、SHA256SUMS、统计与数据卡草稿；目录发布后只读，任何修订出新版本，绝不覆盖 `admin/` 旧文件 |
| L4 验收 | 引擎线 | `acceptance/<交付版本>-<哈希>/`：验收报告、退回清单；退回记录不能进入标注；内容质量另由金标质检线抽查 |
| L5 标注 | 金标线和法律组 | `labels/<schema版本>/<交付版本>/`：双人原标、仲裁结果、指南版本、证据偏移、标注者与复核者、输入正文哈希；划分只记 ID，测试集封存 |

批次名应含来源与日期，例如 `web-20261016-r1`、`pkulaw-admin-20261016-r1`；交付名如 `20261017-r1`。`LATEST` 只作指针，不能充当版本。任何统计必须同时写版本与主文件 SHA-256；若正文、分段或 `text_sha256` 改变，受影响的标签作废并重标。
