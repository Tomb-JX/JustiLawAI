# 渠道 C 作战手册：北大法宝（学院账号）

> 版本 v0.1 · 2026-10-15 · **数据链路**工作流执行（[分工文档](./workstreams.md)）
> 定位：渠道 B 公开专栏密度 <1% 已量化（[crawler-ops](./crawler-ops.md)），北大法宝是凑足金标 ≥500 的**主力通道**；同时是规范库 G0.1 官方原文的最稳来源。
> 配套：[数据收集计划](./data-collection.md)（§3-C、§4 流水线）· collect/import_manual.py

## 0. 分工边界（与发现层探针的配合）

| 工作流 | 管什么 |
|---|---|
| 发现层（另一工作流） | **公开源** URL 发现：千帆搜索 API → `urls.tsv` → 交数据链路适配公开专栏 |
| 数据链路（本手册） | **付费聚合库**：北大法宝检索 + 官方导出 → inbox → `import_manual.py`（channel=C） |

**红线：不对 pkulaw 写自动抓取脚本、不绕每日导出限额**——只用其官方检索/浏览/批量导出功能（学院账号条款）。若学校采购含"北大法宝开放平台 API"额度，走 API 才算规模化通道（§1 侦察确认）。

## 1. 开工先侦察（半天，结果填 §6）

用学院账号登录 pkulaw.com 逐项确认：

1. **账号形态**：校园 IP 直连还是个人卡号；**每日批量导出上限**（法宝通常限导出篇数/天）；并发限制
2. **四个库的收录试检**（直接决定渠道价值）：
   - 案例库：行政诉讼文书（案由"治安管理处罚"）覆盖省份与年份深度
   - **行政复议决定书**是否收录（试检：全文"赌博" ∧ 文号含"复"）
   - **行政处罚决定文书库**（执法公示聚合）：赌博类命中量——若收录良好，这是金标最直接来源
   - 法律法规库 + **地方法规库**：治安管理处罚法（2025/2012 两版全文）、公通字〔2005〕30 号、六省市赌博裁量基准原文——直接清掉引擎方案里全部【待核验】项
3. **导出格式**：Word/HTML/是否带法宝引证码与文号元数据；一次批量多少条
4. **API**：学校采购是否含"北大法宝开放平台"API 额度（含则申请开通，走正规自动化）

## 2. 检索式清单（试检后命中数记入 §6）

| 编号 | 目标 | 检索式（按法宝高级检索实际语法调整） | 支撑 |
|---|---|---|---|
| R1 | 赌博行政处罚决定 | 全文：赌博 AND 法条：治安管理处罚法（第七十条 OR 第八十二条）AND 文书类型：行政处罚决定 | G1.1 金标主力 |
| R2 | 赌博行政复议决定 | 全文：赌博 AND（文书类型：行政复议决定 OR 文号含"复"） | G1.1；T-admin 构成 |
| R3 | 治安处罚行政诉讼 | 案由：治安管理处罚 AND 全文：赌博，审判程序 一审/二审 | T-admin 复议/诉讼 ≤50% 的诉讼侧 |
| R4 | 省级赌博裁量基准 | 地方法规库：目标省 AND（赌博 OR 治安管理处罚）AND（裁量基准 OR 赌资） | G0.1 规范库【待核验】清零 |
| R5 | 新旧法版本对 | 治安管理处罚法 2012 修正版 vs 2025 修订版条款对照 | M2 时间效力黄金用例（G0.2） |

执行顺序：R4/R5 先（法律组录入规范库，半天可完）→ R1/R2/R3 按**目标省循环**（省选定期后）。每条检索式记录：命中数、可导出数、导出日期、检索式快照——数据卡（G1.4）要写。

## 3. 导出与入库 SOP

1. 检索 → 排序（相关性/日期）→ 分批勾选（≤每日导出上限）
2. 官方批量导出 → 存 `D:/02_Dev/Data/justilaw-research/inbox/pkulaw/<检索式编号>-<日期>/`
3. 入库：`python research/discretion/collect/import_manual.py --channel C --region <省> --source-type <行政处罚决定书|复议决定书|判决书|规范文件> --ref "pkulaw R1 <日期>"`
4. 核对：manifest 行数 = inbox 文件数；抽查 sha256 与文号
5. 金标筛选沿用数据收集计划 §4 纳入标准——**重点保留"不予处罚/不构成违法"类**（G3.2 单独达标）

## 4. 体量与节奏（§6 侦察后校准）

- 需求倒推：金标 ≥500（赌博行政处罚为主）→ 法宝侧导出 ≥800 件原始文书（含筛选损耗）
- 人工批量导出估计 50–100 件/小时 → 全量约 2–3 个半天
- 每日导出上限若偏低：跨周分批，挂进 crawler-ops §4 的每周例行（同一天做，形成"周一适配 + 法宝导出"固定节拍）

## 5. 合规与治理

- 原文只存仓库外数据目录（`JUSTILAW_DATA_DIR`），仓库只留 manifest 元数据 + 哈希（治理同数据收集计划 §6）
- 数据卡记录：来源标注"机构订阅数据库（北大法宝）"、检索式、导出日期、数量；不记录个人账号信息
- 结题材料引用遵守法宝用户协议（"北大法宝" + 文号）；导出文本不得二次公开分发
- 选择偏差照旧入卡：法宝收录偏争议案件（复议/诉讼类尤甚），训练加权 + T-admin 构成上限照门禁 §7 执行
