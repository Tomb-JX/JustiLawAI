## 1. 开工先侦察（半天，结果填 §6）

用账号登录 pkulaw.com 逐项确认：

1. **账号形态**：账号类型；**每日批量导出上限**（法宝通常限导出篇数/天）；并发限制
2. **四个库的收录试检**（直接决定渠道价值）：
   - 案例库：行政诉讼文书（案由"治安管理处罚"）覆盖省份与年份深度
   - **行政复议决定书**是否收录（试检：全文"赌博" ∧ 文号含"复"）
   - **行政处罚决定文书库**（执法公示聚合）：赌博类命中量——若收录良好，这是金标最直接来源
   - 法律法规库 + **地方法规库**：治安管理处罚法（2025/2012 两版全文）、公通字〔2005〕30 号、六省市赌博裁量基准原文——直接清掉引擎方案里全部【待核验】项
3. **导出格式**：Word/HTML/是否带法宝引证码与文号元数据；一次批量多少条
4. **API**：官方 **MCP（mcp.pkulaw.com）** 已接入（见 §7）

## 2. 检索式清单（试检后命中数记入 §6）

| 编号 | 目标 | 检索式（按法宝高级检索实际语法调整） | 支撑 |
|---|---|---|---|
| R1 | 赌博行政处罚决定 | 全文：赌博 AND 法条：治安管理处罚法（第七十条 OR 第八十二条）AND 文书类型：行政处罚决定 | G1.1 金标主力 |
| R2 | 赌博行政复议决定 | 全文：赌博 AND（文书类型：行政复议决定 OR 文号含"复"） | G1.1；T-admin 构成 |
| R3 | 治安处罚行政诉讼 | 案由：治安管理处罚 AND 全文：赌博，审判程序 一审/二审 | T-admin 复议/诉讼 ≤50% 的诉讼侧 |
| R4 | 省级赌博裁量基准 | 地方法规库：目标省 AND（赌博 OR 治安管理处罚）AND（裁量基准 OR 赌资） | G0.1 规范库【待核验】清零 |
| R5 | 新旧法版本对 | 治安管理处罚法 2012 修正版 vs 2025 修订版条款对照 | M2 时间效力黄金用例（G0.2） |

执行顺序：R4/R5 先（法律组录入规范库，半天可完）→ R1/R2/R3 按**目标省循环**（省选定期后）。每条检索式记录：命中数、可导出数、导出日期、检索式快照——数据卡（G1.4）要写。

## 3. 导出与入库 SOP

1. 检索 → 排序（相关性/日期）→ 分批勾选（≤每日导出上限）
2. 官方批量导出 → 存 `D:/02_Dev/Data/justilaw-research/inbox/pkulaw/<检索式编号>-<日期>/`
3. 入库：`python research/discretion/collect/import_manual.py --channel C --region <省> --source-type <行政处罚决定书|复议决定书|判决书|规范文件> --ref "pkulaw R1 <日期>"`
4. 核对：manifest 行数 = inbox 文件数；抽查 sha256 与文号
5. 金标筛选沿用数据收集计划 §4 纳入标准——**重点保留"不予处罚/不构成违法"类**（G3.2 单独达标）

## 4. 体量与节奏（§6 侦察后校准）

- 需求倒推：金标 ≥500（赌博行政处罚为主）→ 法宝侧导出 ≥800 件原始文书（含筛选损耗）
- 人工批量导出估计 50–100 件/小时 → 全量约 2–3 个半天
- 每日导出上限若偏低：跨周分批，挂进 crawler-ops §4 的每周例行（同一天做，形成"周一适配 + 法宝导出"固定节拍）

## 5. 合规与治理

- 原文只存仓库外数据目录（`JUSTILAW_DATA_DIR`），仓库只留 manifest 元数据 + 哈希（治理同数据收集计划 §6）
- 数据卡记录：来源标注"北大法宝"、检索式、导出日期、数量；不记录个人账号信息
- 结题材料引用遵守法宝用户协议（"北大法宝" + 文号）；导出文本不得二次公开分发
- 选择偏差照旧入卡：法宝收录偏争议案件（复议/诉讼类尤甚），训练加权 + T-admin 构成上限照门禁 §7 执行

## 7. 法宝 MCP 接入（2026-10-15 打通 ✅，2026-10-16 补至 13 服务）

**接入方式**：mcp.pkulaw.com 控制台的 Bearer Token（用户级 `~/.zcode/cli/config.json` → `mcp.servers`，**Token 只存本地配置，永不入库**；失效时到控制台重新生成）。ZCode 会话重启后自动连接（MCP 方式需重启生效；脚本方式即时可用）。完整服务清单与单价以引擎的调用层为准（`research/eval/pkulaw_mcp/services.py`，2026-10-16 已对照账户实测）：在原 9 个之上新增 4 个——

| 服务 | 端点 | 单价 | 数据链路用途 |
|---|---|---|---|
| **pkulaw-enforcement-doc** | /pkulaw-enforcement-doc/mcp | 75 | **行政执法库目录**：普查选省、"不决字"定位不予处罚、"机关+文号"反查原公示页（详见[执法库调研](../05-research/pkulaw-mcp-enforcement.md)） |
| pkulaw-procuratorate-doc | /pkulaw-procuratorate-doc/mcp | 75 | 不起诉决定书目录（行刑边界样本） |
| pkulaw-statute-history | /pkulaw-statute-history/mcp | 75 | 法条沿革与新旧对照（规范库核验已由引擎完成，22 项一致） |
| pkulaw-account | /pkulaw-account/mcp | 0 | 查余额、开通状态与单价（对账用） |

原 9 个（case-keyword / case-semantic / law-keyword / law-search / fatiao / law-recognition / case-number-recognition / citation-validator / doc-link）用途见 git 历史 v0.2 版本表；法律智能检索（mcp-law-agg）网关路径未知（404），暂未收录。

**调用方式二选一**：
1. **共用调用层（推荐，有记账）**：引擎维护的 `research/eval/pkulaw_mcp/`，带预算上限、参数缓存（同参数只付一次）、按工作流记账的台账：
   ```bash
   research/.venv/Scripts/python research/eval/pkulaw_mcp/__main__.py --workstream data call enforcement-doc search_enforcement '{"queryText": "赌博", "documentNo": "不决字"}' --budget 75
   ```
   令牌查找顺序：环境变量 `PKULAW_MCP_AUTHORIZATION` → 官方 CLI 配置 → 数据链路的 ZCode 配置。**数据链路调用一律加 `--workstream data`**，月底对账（`__main__.py ledger` + `account` 服务查余额）。
2. ZCode 内 MCP 工具（`mcp__pkulaw-*`，会话重启后出现）：适合单点人工查询，无自动记账。

**积分纪律（与引擎共用一个账户）**：余额 6,250 分，**2026-11-15 全部过期**。普查（省 × 年份命中总数）、不予处罚定向、"不决字"检索等成规模调用，**先在协作记录里与引擎对齐再执行**（[积分分配建议 §5](../05-research/pkulaw-mcp-enforcement.md)）。

**使用纪律**：MCP 是官方合规通道，优先级高于网页导出——单点精确查询、法条原文核对、说理校验走 MCP；**批量成百上千件的文书导出仍走网页批量导出**（MCP 只回目录无正文、每次前 20 条不能翻页）。协议注意：SSE 响应无 charset，requests 必须显式 `content.decode("utf-8")`（latin-1 误读会把多字节序列切成假换行）；"精准查找法条"在标题匹配不上时会**静默返回别的文件**，用前核对返回的文件名与文号。

## 8. T-time 定向：2026 新法 × 叙述式（2026-10-16 用 MCP 全量普查）

**目标**：门禁 G1.1 的 T-time 测试集（2026 年后行为 ≥ 50 件）。**口径**：正文命中叙事短语（= 叙述式文书）+ 公布日期窗口 2026（法宝的日期窗口按**公布日期**筛，行内显示的是处罚日期，批下载后按解析出的行为日期再过滤）。

**检索式（MCP `search_enforcement` 实测命中，2026 窗口全年）**：

| 正文短语 | 命中 | 分布要点 |
|---|---|---|
| `现场查获赌资` | **189** | 月度：1 月 115、2 月 36、3 月 18、5 月 12、6 月 8，**4 月与 7 月起为 0**（收录延迟） |
| `参赌人员` | **99** | 92 在一季度；4–12 月仅 7 |
| `抽头` | **77** | 1 月 66、2 月 8、3 月 3；4 月起 0 |
| `渔利` | **76** | 未拆分 |
| `以营利为目的` | **549** | 宽召回（含非叙事），需人工筛 |
| `赌资` / `赌具` | 2549 / 572 | 宽召回，仅作补充 |

**结论与口径**：① 库内 2026 供给**天然集中在 1–3 月**（4 月后近乎为 0，属公开-收录延迟），窗口直接用"2026 全年"即可，不要按最新月份筛；② 命中的机关高度集中（一次行动十几份）：内蒙古（化德/丰镇/突泉/扎赉特旗/土默特左旗/通辽）、湖南东安、重庆（永川/万州/巫溪）、湖北（钟祥/天门/麻城/安陆）、山东龙口、江苏阜宁、河北阜城等——**下载按机关批次走最省事**；③ 已生成候选清单：`$DATA/inbox/pkulaw/2026T/worklist.csv`（337 个文号，全部为叙述式短语命中）+ **`worklist-2026优先.csv`（185 个，公布日期 2026）**——按该清单在网页端逐条下载即可（一次一页 50 篇）。

**花费**：本轮定向普查 75 次调用 × 75 分 = 5,625 分（含当月/分省拆分与全部宽召回探测）；余额 2,875（11-15 过期）。

> **⚠️ 口径更正（v0.6，2026-10-16 晚）**：上表命中数是 **MCP `queryText` 的计数，口径 = 「词元 AND、同篇级、顺序无关」，不是短语命中**。
> 乱序对照实测：`现场查获赌资` **189** vs `赌资现场查获` **181**（≈同量）vs 子串 `查获赌资` 302——顺序无关即证词元级。
> 因此：① 计数只可当**量级参考**，不能当「叙述式命中数」；② **真短语检索要在网页端做**：全文 → **精确 → 同句**；
> ③ 抽查用户实下 7 份：5 份赌博（1 份高质量 + 4 份源文打码）+ **2 份烟草案**——噪声来自宽词 `以营利为目的`（已列为禁用词）；
> ④ 候选清单已出**清洗版**：`worklist-清洗版.csv`（317）/`worklist-清洗版-2026.csv`（165），剔除「明确非赌博标题」16 条与「仅来自以营利为目的」4 条；
> ⑤ **验证纪律升级**：此后一切「计数型勘探」必须带**乱序词对照**（顺序变化后计数显著下降才说明是短语）。
