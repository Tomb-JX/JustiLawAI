后续工程化拆解与开源选型见 [工程方案补篇](./seg-v2-engineering-solutions-2026-10-18.md)：12 项工程任务、中文日期/金额解析器比较，以及本机合成探测结果。

## 一页结论

**暂不放行 r7，也不续跑 element-v1 全量。先修“契约没有真正交给模型、非法产物仍进入合并、输入坐标混用”三个已证实的问题，再验证调用拆分。** 反思文档指出了方向，但把大量分歧直接归因于定义歧义、把拆调用当作必然提高质量，证据不足。

- **现状复核**：final300 的官方 S3 逻辑离线重算仍为 pass/warn/error＝121/152/26，硬失败率 **26/299＝8.70%**；另有 1/300 调用失败。`validation_clean` 不能替代 S3。
- **更早的阻塞**：88 条 elements 落盘记录只有 **6/88（6.82%）**通过现行结构检查。239 处非法值、27 处证据形状错误；配对验收在数值规范化时直接崩溃。88 是落盘数量，不能称为 88 件有效标签。仅看引文坐标命中 **639/666＝95.95%** 会掩盖这些问题。
- **输入隔离已被破坏**：按 `OffsetIndex.span(cs,ce)` 对照，88 条标签中 **64 条**教师输入不等于应有原文切片，**10 条**实际输入区间与 reasoning/decision/review 区间重叠。W-000630 与 reasoning 的区间重叠累计 163 字符。不能把这些标签直接用于“不见结果”的学生评测。
- **调用架构**：保留确定性清洗、句表、归一化及校验；叙述式的分区与结果抽取分为可独立验收的任务，公示确定性分区成功则跳过模型分区。日期规范化不另叫模型，赌博语义判断可与结构任务同调，模型置信自评不作为门禁。elements 先把完整 schema 真正接入，分组调用须做配对实验后决定。
- **证据改结构引用，但不整体删除 S2 的职责**：模型回句 ID，管线回填原文证据；保留坐标投影、输入权限、本人归属、值与证据支持关系及重放校验。旧 quote 定位只作历史兼容。
- **顺序**：免费重放与契约修复 → 新目录 12 件冒烟、通过后补至 36 件规约实验（建议总 cap ¥12，见 §7）→ 冻结版本后正式 300 试点及 200–300 件要素验收 → 达原门禁再报全量预算。36 件不代替正式试点。

**本评审新增的最优先决策**：拒绝把缺字段当“未提及”；拒绝将不合法 A/B/C 候选交给合并；拒绝用处罚合法空间改写原文记载的历史结果。字段语义、输入允许范围的调整由引擎线升版，下一完整批次生效，旧批不追改。

## 2. 已证实的阻塞与影响

### F1 / P1：schema 在代码里存在，却没有进入实际教师请求

E `element_labels.py:50` 生成完整输出 schema，但 `teacher_system_prompt():76–89` 仅逐行发送 `path: description`，没有七组对象的完整结构、枚举集合和各字段类型。W `s1.py:122–130` 只指定 `json_object`；这不能约束这些值域。A 的 23 条响应为路径平铺对象；B 的多种包裹结构、平铺及额外字段也未被拒绝。按原始形状检查，A 85/88、B 87/88 有结构或值域问题（此计数不含引文不存在问题）。

因此，“参赌人员”与 schema 枚举“参赌者”的差别首先是契约传递失败，不足以证明角色定义本身歧义。合并产物中 `conduct.role` 有值 79 条，其中 **76 条值域非法**；`conduct.method` 为 59/64，`venue.venue_type` 为 73/77。应先发送由引擎生成的完整 schema（含嵌套形状、枚举、类型、空值条件）；支持受限输出的接口可使用它，不支持时也须显式入提示并逐项校验，不能宣称已有 grammar 保证。

### F2 / P1：错误被当作缺省值吞掉，部分“结构通过”是伪成功

W `run_elements.py:344–345` 得到 A/B 校验问题后照样继续；`:164–165` 把读取不到的嵌套字段替成“未提及”。37 条记录至少一侧缺应有分组。5 条 merged 全字段未提及，其中 **4 条**的原始平铺响应实际含非空值：W-000612（A 1 项）、W-002065-d13（A 8/B 5 项）、W-000513（12/10）、W-000327-d4（8/7）。它们均在那 6 条“结构有效”中。

裁定：**缺失/非法/未解决 ≠ 未提及**。前者进入独立的执行状态或字段问题队列，不能伪装成文书未记载。结构合法只是必要条件；6 条也不能据此确认为可用金标。允许在只读重放中对无歧义平铺格式做无损适配评估，但必须保留原响应、适配版本和变换日志；不能顺手猜枚举或补事实。

### F3 / P1：clean 与 orig 坐标被混用，输入串台

`locate.py:65` 的 `span(cs,ce)` 接收 **clean 左闭右开区间**并返回原文左闭右开区间。但 W `run_elements.py:78` 调用 `span(cs,ce-1)`，继而在 `:81` 保存 `(clean_start, orig_end)`；`:84–101` 又把两端当 clean 下标查询 `index.origs`。结果同时有末字丢失、重复映射、越界跳过和多取邻区。

以已选 facts 和前置 meta 的每句 `text_full[index.span(cs,ce)]` 为对照：299 个 S1 成功件中当前代码可构建输入 227 件，**189/227**输入不同；88 个已落盘标签的输入有 **64/88**不同。88 条存储输入与当前错误代码重建结果完全一致，故并非只读重建版本漂移。10 条输入区间与禁用区重叠只是按现有 zones 的区间诊断，**不是已经测得十条标签必然泄露了处罚答案**；逐字段受影响范围待验证。

裁定：输入构造与引用编译必须使用同一坐标接口；每句只映射一次。64 条不得通过修改 input 信封保留旧标签而宣称重标完成：模型当时读到的内容已不同，需隔离并评估是否重新调用。其余记录也须经过 F1/F2/F4 检查。

### F4 / P1：C 不是同契约的第三位教师，合并后缺少最终闭环

W `run_elements.py:226–233,357–389` 的 C 提示没有字段类型/枚举定义，也没有明确 target/aliases；正文和候选 JSON 分别按 4000/9000 字符硬截。`:190–192` 的新值分支可借 A 的第一条引文，且新引文未走 `_candidates`；`:391–392` 只数 `review`，不能捕获“只有 quote、没有坐标”。`:457` 落盘时又去掉 `_diag`。因此“unresolved 仅 1”“loc_fail 很少”不代表最终契约合格。

本次 `evaluate(labels,A,B)` 在 `agreement.normalize` 对 dict 做 `float()` 时崩溃；保留异常，没有修数据绕过去。单独 `evaluate(labels)` 仅用于结构诊断，结果 **6/88 有效、pilot_pass=false**，不是一次完整配对验收。可机械对账数值仅 31 对、25 对一致，**80.65% 是有限机械检查结果，不是字段准确率**。

裁定：A/B/C 同样接收目标、相同字段规则和允许的证据句；C 的新值不得借用候选证据。所有采纳路径最终经过相同 schema、证据和来源校验；失败时保留未解决状态及原候选。验收器应对坏 A/B 输出问题报告而非崩溃，不能先改成字符串掩盖非法类型。

### F5 / P1：法律锚与抽取真实性混为一谈

W `arbitrate.py:67–91` 按各版本最小上限筛候选，不看记录适用版本/单行为或合并执行；一方越限就自动采纳另一方，`resolve():140–144` 记“明确”但无证据。这至少有两类问题：版本/处罚口径不适用；**另一候选合法不证明它被原文支持**。

裁定：先核定历史结果“原文写了什么”，再标记它是否与经引擎确认的规范空间一致。规范冲突不可自动把原文数值改成合法候选。法律锚优先作为校验与训练资格约束保留，但适用条件不明时不作“明确”裁决；适用版本、合并执行、原处罚/复议变更必须分开。这涉及既有“判死”语义，交引擎与协调登记修订后生效；本评审没有改常量、重算或追改仲裁标签。

### F6 / P2：S3 是必要防线，不是本人字段的正确率证明

`s3.py:379–444` 的金额检查最终取全文金额集合；属于别人、赌资或被复议的旧结果中的同数额，也可能通过。日期主要核对年月，不能保证具体日期正确。当前 26/299 保留原口径；补充报告全选 300 件的未成功数和失败构成，不能通过删掉难件、提升 warn 或缩分母把它做低。

## 4. 目标接口与调用架构

### 4.1 按责任拆任务，不按字段的数据类型拆任务

```text
原文 + edits + 句表 + target（冻结哈希）
  → 确定性 form/输入资格检查
  → Z：叙述式分区；公示 zones_det 通过验证则免调 Z
  → O：本人处罚/复议结果抽取 + 日期表达式及其句引用
  → 确定性日期/数额归一化、版本绑定、S3 与本人证据校验
  → E-A / E-B：同契约独立要素标注（只见允许的事实/身份句）
  → 分离错误类别 → 必要时 C：受同契约约束的字段裁决
  → 统一引用编译与最终校验 → parsed-2 候选 → 引擎独立验收
```

Z 与 O 可并行读同一冻结句表；O 不必等待 Z 的错误边界才能看见处罚句，两者分别存任务结果、重试和版本，组装时再交叉验证。Z 的结构标签不传入 E 作为处罚答案。`zones_det` 是有来源的规则判断，必须校验引用范围及语义，不能因“确定性”跳过抽检；其与旧正则的一致不算独立质量证据。

| 工作 | 建议职责 |
|---|---|
| 分区 | Z 只输出覆盖句表的类型区间；必要的目标和赌博三态及证据可同调，无须另设纯分类调用 |
| 结果与日期 | O 输出带主体、事项、原决定/变更/执行口径的结果，以及日期表达式的结构引用；代码解析中文数字、单位、ISO。不另调“日期规范化模型” |
| 赌博判定 | 保留预筛与语义判定双轨；“仅前科提赌博”与“本案赌博”区分。两轨冲突或待定入队，不用预筛充当真值 |
| confidence | 不另调置信模型；旧版字段留兼容。新版可用校验失败、模型分歧、缺源、输入范围生成可解释诊断；未校准的 high 不作放行依据 |
| elements | 首个候选使用 **完整 schema 的单次 A/B**作为基线。对照候选按语义分两组：活动/角色/金额/人数/场所/营利目的（20 字段）与情节/个人属性（16 字段）。两组各保留必要上下文，互不读取对方答案；具体是否增调须验证 |
| C | 仅在候选有效且存在实质冲突时调；按字段语义组组织，一份记录可合并裁决多个字段，但不得裁断无输入证据的字段 |

`age` 需要可靠行为日期，`last_prior_penalty_date` 需要日期精度；日期缺失不能用决定日、采集日补成精确行为年龄。月份不应被无痕填成 1 日：现 1.1.0 的该规则保留兼容，建议下一语义版另存精度/区间，未经升版不能改变现字段取值。

### 4.2 结构引用：移除模型抄写，保留完整证据链

建议请求携带 `record_id + target_id + text_orig_sha256 + sentence_table_hash + input_view_version`；句 ID 在同一原文及句表版本下稳定。模型输出的证据形如 `{"sentence_ids":[12,13]}`，**不由模型生成 quote 或原文字符偏移**。服务端编译为当前消费者需要的 `{quote,start,end}`；多个不连续句分别落证据，不能包成一个大区间。

编译器须检查：ID 属于本记录和当前句表；来自 E 的允许句集合；目标当事人匹配；原文 UTF-8 哈希匹配；坐标使用 Python Unicode 字符索引、0 起左闭右开（JS 消费端不能直接拿 UTF-16 下标混用）；最终切片逐字相等。S0 同长替换不改变原文正本；跨删除区间时原文投影可能非连续，须记录分段 provenance，不能把包围区间中的删除内容静默当作事实。

句级引用保证**位置可回放**，不保证支持字段。对金额/日期再核对引用句中属于本人及正确金额种类的数值；对角色/营利目的检验定义所需条件。“全篇引用”不能作为合格的最小支持证据。长句含多种数值、主体或事实/结论时，采用确定性子句/词元 ID；此为句表下一版，不能在同一批里临时改编号。

S2 的 quote 搜索、模糊对齐、由模型补抄消歧可以在新契约停用；**OffsetIndex/原文投影、引用合法性、回填和最终验证必须继续存在**。新旧路径分版本，不能先删历史读取能力。任何引用路径（A/B 直采、C 采 A/B、C 新值）适用相同规则。

### 4.3 decision 边界的裁定

**主分区采用“原文的完整处罚决定块”**：包括直接引出处罚的适用依据、处罚主文、紧随主文的执行安排；一般的事实评价、情节评价归 reasoning。独立的复议/诉讼救济告知不等于 `review`：`review` 只用于实际复议/诉讼的审查意见与结论；救济告知及文尾机关、落款日期归 meta。该细化属于下一分区规范版本。

另设可重叠的细粒度引用 `legal_basis / operative_outcome / execution / remedy_notice / signature`（字段名为设计建议）。消费者若只需结果，取 operative_outcome；若需完整块，取 decision。处罚复议文书必须区分被引述的原处罚和本次复议主文，不能凭“决定如下”四字覆盖两者。公示一条同时含事实和处罚时保留融合标记及两类引用；没有可分边界就不得伪造独立事实块。

当一句同时有事实与结论，不能按关键词把整句推入 reasoning 或 facts。先使用可审计子句边界；不能安全拆开则标“混合/需复核”，E 不接收其中的处罚结论。`minor_circumstance` 明确依赖原文认定，现事实输入禁入结论会降低其可观测性，必须报告这一契约冲突，不能让教师暗读 decision。

现 **decision F1≈0.487 是相对 regex 的重叠分数**，不能读作 48.7% 正确，也不能以“构造差异”宣称余下都正确。应对同一 36 件同时保存旧正则区间、旧模型区间和新规范下的引用，由隔离裁判按明确边界规则对分歧落判并给句 ID。分别报主分区 F1、operative_outcome 覆盖、reasoning/救济误入率、本人结果引用完整性；保持旧 F1 并列可比。无独立真值时称“规范裁决一致率”。新阈值待该样本验证，不能为提高 F1 把 regex 当答案。

## 5. 双盲分歧与字段契约

### 5.1 先排接口错误，再找语义歧义

541 条已有 diff 按互斥优先顺序分解：值/有无不同 **394（72.83%）**；值相同而状态不同（可同时有证据窗口差）**64（11.83%）**；值与状态相同、仅证据窗口不同 **83（15.34%）**。其中 **236/541（43.62%）至少一个候选值域非法**；这些计数有交叉关系，不能相加。分解是旧合并产物的诊断，已受缺组转空值影响，不是干净的语义分歧率。

| 类别 | 处置 |
|---|---|
| schema/引用/输入不合格 | 先修或定向重试该任务；不交 C 猜测，也不纳入“定义争议”榜 |
| presence/value 真冲突 | 按引擎定义及证据核查；缺规则则记录反例并升版；有规则仍冲突才仲裁 |
| 明确/推断冲突 | 保留两侧状态及推断规则 ID。可由明示规则机械解决的归一化，不需叫 C；否则仍是有效冲突，不能统一降 warn |
| 仅证据窗口不同 | 各自独立通过支持/权限校验后可保留多组证据，不强求同一 span；当前门禁统计照旧，新增“实际需 C 数”另报 |
| 双方缺字段或无效 | 不转成双方“未提及一致”；执行失败单列 |

**不采纳 O6 的裸 value-only 判同**：两人各有 500 元、两种金额各为 500 元都可能值同而归属不同；两边同样的非法值也不能直采。`agreement.py` 的 union 口径保留作为唯一既有一致性实现；不得拿 541/(88×36) 替代它，也不得把“实际发给 C 的比例”称作现行仲裁分歧率。

### 5.2 需要补充的裁决规则（拟下一语义版；不是已证明的全部根因）

| 字段 | 可执行的修订方向 |
|---|---|
| behavior_type / role | 分开“事实活动”与法律定性；同一人可兼任角色，候选保存角色集合及逐项证据。若引擎继续单值，须明确投影及优先序，不能由标注模型自由选“最接近”。无规则时标冲突，不能随意映射“组织者＝聚众赌博” |

| times / participant_count | 明确单次行为单位、计数本人和参赌者、剔除围观/民警；“本人等四人”计 4，“本人与四人”计 5，仅“等人/多次”不猜精确整数。若要保存下界，需升版为计数区间；累计人次与去重人数不得混用 |

| truthful_statement 等情节 | “到案”≠“主动投案”，“如实陈述”≠“认错认罚”。哪些是 facts 可抽的事实、哪些是结论属性，须写字段级允许区，不得用纯 zone 白名单静默丢弃后报源头缺失 |

建议研发目标（**不是替换现行门禁**）：K 有可独立核对证据的子集，值/主体/证据三者联合正确率目标 ≥95%；R 目标 ≥90%，每字段独立显示，不用全空字段拉平均。没有独立真值只报“规范裁决符合率/模型共识”，不得报准确率。每字段可核对正例不足 20 时标“证据不足”，给区间和样本数；这 20 不是统计充分性的承诺。S 同时报告有源正例的召回、缺源负例的错误给值，不能以 95% 未提及率宣布合格。年龄、前次处罚日期、抽头等仍在 K，绝不删减。

协调统计的 text_party=0 是结构化当事人段缺失，不足以证明 text_full 没有年龄。网页整体和法宝新增正文密度不同，按来源/形态分层；先查全文与允许输入，才判断该买数据还是修提取。关键词出现率仅作 >20pp 告警代理，不是字段真值，更不能用其强迫标签比例回归。
