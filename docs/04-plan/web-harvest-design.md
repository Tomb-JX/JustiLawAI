## 2. 收割（`harvest.py`）

| 输入 | 做法 |
|---|---|
| 发现层 `urls.tsv` 中赌博=是的单篇 URL（2026-10-16 起；"待定"经全文验证 <1% 是赌博，不再抓取） | 按优先级逐篇抓取 |
| 栏目主表里 `status=ok` 的栏目 | 自动识别翻页，用第 2 页验证模板后逐页列出条目，再逐篇抓取 |

**翻页识别**（不写站点适配器，按候选模板实测）：`下一页`/`2` 链接替换页码；TRS `createPageHTML(…,'index','html')` → `index_{n-1}.html`；JS `goPage` 里的 `strHref` 拼 `&page=n`（定兴实测）；`_n` 后缀（塔城 `cfqz_2`、辛集 `node/2190_2`）；兜底 `?page=n`。

**混合栏目按标题预筛**：栏目里各部门处罚混在一起时（辛集、大新、山东某栏目估算 13,700 条），只抓标题含公安、"公（…）行罚决字"、赌、治安、派出所的条目；标题只有人名或空泛（敖汉、红塔）时全抓。

**附件**：正文少于 300 字且挂了图片/PDF/Word 附件的页面，下载附件（≥20KB，过滤每页重复的站点小图标）。实测**定兴 2025 年起的处罚决定书只以 JPG 扫描件发布**，正文不在 HTML 里，要靠 OCR（§5 ③）。

**礼貌与合规**：只读公开页；同一主机请求间隔 ≥1.5 秒，失败重试一次；验证码、JS 盾、非 200 记录后跳过，不绕过；已抓过的 URL 不重抓。

## 3. 产物清单（下载下来的到底是什么）

都在仓库外 `$JUSTILAW_DATA_DIR`，仓库里只有台账（不含正文）。

| 产物 | 位置 | 内容 | 能否给引擎 |
|---|---|---|---|
| 原始页面 | `harvest/raw/<站点>/<页面id>.html` | 网页原样存档（取证、重解析用） | 否 |
| 附件 | `harvest/raw/<站点>/<页面id>_att<k>.jpg/pdf` | 决定书扫描件、PDF | 否 |
| 正文 | `harvest/text/<页面id>.txt` | 去掉导航页脚后的正文 | 否 |
| 页面台账 | `harvest/pages.jsonl` | 每页：URL、状态、哈希、路径、附件、来源（单篇/栏目）、台账 id | 否 |
| 来源台账 | 仓库 `research/discretion/harvest/manifest_web.csv` | 与数据链路 `manifest.csv` 同字段，id 前缀 `W-`，只记来源与哈希 | 入库 |
| 结构化案例（脱敏前） | `admin/web_cases.pre_deid.jsonl` | 每案一行：§4 的分段文本、处罚结果、日期、机关、赌博判定、完整度 | **否（未脱敏）** |
| 统计 | `admin/web_cases.stats.json` | 件数、来源构成、结果类型、完整度、待 OCR 数 | — |

一页可能产出多案（汇总页按条拆分，id 为 `W-000123-2` 这样的"页面 id-序号"）。

## 4. 解析（`parse.py`）

| 页面形态 | 实例 | 切分 |
|---|---|---|
| 叙述式处罚决定书 | 定兴 2022–2024 | "现查明"→`text_facts`；"以上事实有…证实"→`text_evidence`；"本局认为"→`text_reasoning`；"根据…之规定，现决定"→`text_decision` |
| 字段式公示 | 魏县、博湖、敖汉、蠡县 | 违法事实/处罚事由、处罚依据、处罚结果/内容、决定日期、实施机关（标签后须有冒号或空格，免得误中标题） |
| 汇总页 | 红塔 | 按"1、2、3、"拆成单案；每条有案由、依据、结果、文号 |
| 复议决定书 | 武义、花都 | 原处罚句→处罚结果；"经审理查明"→事实；"本机关认为…决定如下"→`text_review` 与 `review.result`（维持/撤销/变更/确认违法/驳回） |

**处罚结果**（规格 §1.4）：类型（不予处罚/警告/罚款/拘留/拘留并处罚款/移送刑事）、拘留天数（合并执行取合并后天数）、罚款（含"伍佰元整"等大写）、收缴、引用法条（带法律名）、明写的情节（情节严重/从轻/减轻/从重）、不执行拘留、法律版本（第七十条/"修订前"→旧法，第八十二条→新法）。

**逐案复判**：栏目里是全部治安案件（定兴栏目有殴打、诽谤等），每案用全文按发现层分诊同规则重判赌博；`in_scope` 只收**公安机关依《治安管理处罚法》**作出的赌博处理（岳阳文化执法支队查处赌博游戏机等排除）。

**质量标记**：`segmented`（是否切分成功）、`needs_ocr`、`parse_warnings`（事实段混入结论词、结果未解析等）、`completeness`（有无金额、有无结果，对应规格 §2"信息完整度 ≥80%"）。

**本轮结果**（2026-10-15 首轮）：

| 项 | 数 |
|---|---|
| 收割页面 | 2,100 个成功（发现层单篇 1,179；定兴整栏 550 + 220；辛集 294、环江 33、翁牛特旗 18、塔城 17、敖汉 15 等）；失败约 25 个（403/404/412/拦截页，按规则跳过） |
| 解析出案例 | 3,693 件（汇总页、结果表按条拆分），其中**在范围内（公安依《治安管理处罚法》处理的赌博案）998 件**，来自 88 个站点 |
| 在范围内构成 | 叙述式处罚决定书 403、字段式公示 144、汇总拆分 377（红塔为主）、复议决定书 73、结果表 1；**非复议 925 件（93%）** |
| 处罚结果解析成功 | 911 件（91%）；复议结论：维持 64、撤销 5、驳回 1 |
| 法律版本 | 旧法第七十条 642、新法第八十二条 169、未识别 187；**2026 年行为 162 件**（多为红塔汇总条目） |
| 信息完整（有金额且有结果） | 242 件（24%）：叙述式决定书 148、字段式 55、复议 38；**汇总拆分 377 件全部缺金额** |
| 待 OCR | 110 个页面（定兴 2025 年起的扫描件） |
| 抽查（随机 30 件） | 赌博判定 28/30；两处错误（复议正文里"另查明…曾因赌博被罚款"的前科、一份"权责清单"）已补规则 |

**与规格的差距**：信息完整度 24%，规格要求 ≥80%；"不予处罚"0 件，G3.2 要求单独达标。前者要靠 OCR 补回定兴扫描件、并优先收叙述式决定书，汇总页只作结果分布与 T-time 用；后者要专门检索"不予处罚决定书 赌博""不予行政处罚"（发现层模板 `bycf` 已有，需加大该方向的精扫）。

### 4.1 扫描件 OCR（`ocr.py` + `winocr.ps1`，2026-10-16）

**复用本机已有实现，不新装库**：本机已有两套 OCR——Windows 自带 OCR（`Windows.Media.Ocr`，zh-Hans-CN；调用写法沿用另一个本地项目 astrbot-ops 的 `vision_lib.ps1`）和 Tesseract 5.5（`D:/01_Apps/Tools/Tesseract-OCR`，带 chi_sim）。用同一张定兴扫描件对比：

| 引擎 | 速度 | 质量 |
|---|---|---|
| Windows 自带 OCR | 约 1 秒/张 | 文号、事实、三段决定（含合并执行、"伍佰元整"）全对；错字只有"題""亘告"；落款日期被公章压住认不出 |
| Tesseract chi_sim | 约 1.7 秒/张 | "拘留"→"掏留"（多处）、"违法"→"速法"、"县"→"有具"，会直接破坏结果抽取 |

所以 Windows OCR 作主力（一个 Windows PowerShell 5.1 进程批量识别），返回为空的图（单边超过 10000 像素的长拼图）改用 Tesseract。识别后统一纠错（"題/亘告/掏留"、数字后的"兀"→"元"），并把版面折行并回段落（"行政拘<换行>留十日"会让抽取失败），段首锚点前的换行保留。解析时若"决定"段抽不出结果（OCR 偶尔漏掉"留三日。"这类短行），用"执行方式和期限"一句兜底。

**结果**：112 个扫描件页面、125 张图，约 26 秒；99 页识别出正文（13 页两种引擎都认不出文字，多为非文书图片）。OCR 来源的在范围内案例 38 件，结果解析 37 件（7 件靠执行句兜底），有金额 21 件。**已知限制**：落款日期被公章压住，`decision_date` 普遍为空；新旧法判定以事实段的行为日期为准。

**合并后全量**：在范围内 1,036 件，处罚结果解析 948 件（92%），信息完整 263 件（25%）。

**交付前要特别核对的规格要求**：`text_facts` 不含"决定给予""情节严重"等结论词（解析已打标记）；不予处罚类必须收；复议来源在测试集中 ≤50%（本渠道以处罚决定为主，正好补这个缺口）；2026 年新法案件 ≥50 件。

## 6. 已知限制

- 汇总页（红塔）每条只有"因赌博"三个字的事实，**金额、情节几乎都没有**，对抽取器训练价值低，主要用于处罚结果分布和 T-time；信息完整度要靠叙述式决定书和字段式公示。
- 扫描件要 OCR 才能用；OCR 错字会影响金额抽取，校正阶段要重点看。
- 正文抽取用起止锚点，个别站点会把页头标题、"当前位置"带进正文（不影响切分，但 `text_full` 不够干净）。
- 栏目翻页依赖模板实测，站点改版会失效；失效时收割报告里"翻页"一栏会显示 `no_pagination_found`。
