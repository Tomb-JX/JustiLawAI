# JustiLawAI 阶段交接概览（草稿）

> 2026-10-28 · 面向首次接手项目的成员。本文帮助建立全局认识，不替代设计、实验和数据台账。状态以本地 `main` 工作树、当日协调看板及数据湖核对为准；快变数字请看 `$DATA/coordination/CURRENT.md`。

## 项目在做什么

JustiLawAI 是学生大创项目，目标是让 AI **辅助理解和处理赌博类行政案件**。产品有通用的对话、智能体、知识库和工作流能力；研究重点是把案件事实与适用法律、地方裁量基准、历史执法情况联系起来，给出有依据、可追溯的裁量参考。它提供辅助意见和待核实提示，最终判断仍由人完成。

## 可以把项目分成三块

1. **数据与研究**：收集处罚决定书等材料，整理成统一记录并存入数据湖（项目的材料与记录库），再标出行为、赌资、时间等案件关键信息，用于训练和评测。当前新增采集以北大法宝行政执法文书为主；公开网页数据保留使用，网页采集线已停止维护。
2. **裁量引擎与服务**：先根据法律和河北、江苏的地方基准确定合法空间和可能档位，再用历史数据提供实务参照与档内分布；同时保留计算过程、依据和偏离提示。后端还提供文本解析、要素抽取和决定书审查接口。
3. **产品界面**：网页已有聊天、智能体、数据集、模型、工作流及裁量建议等页面。裁量工作台的新界面仍在其他工作树，尚未进入本地 `main`。

一条典型路径是：**原始文书 → 解析与数据湖 → 人工填写或确认案件要素 → 规则裁量与实务参照 → 可追溯结果**。研究训练使用的批次与线上服务版本分别管理，不能把实验分数当成产品已放行的能力。

## 现在走到哪里

- **数据底座已运行**：截至本次核对，数据湖有 14,257 条记录、12,031 份文书、19 个批次。数据文件主要在仓库外；Git 主要保存代码、配置、清单和文档。
- **裁量链路已有可运行版本**：河北、江苏规则已接入；系统能给出裁量档位、历史实务参照、依据和计算过程，也能在后端处理文书与审查偏离。适用范围仍有限，新法、新省份及更多来源不能直接推断为已验证。
- **评测和交付仍有门槛**：可供后续流程使用的现行数据版本仍是 r6，下一版 r7 未放行；新训练包与多数案件信息标签仍属开发用途。经人工核定的高可信标签（金标）目前为 0，模型结果不能当成完成发布验收的结论。
- **代码在收束中**：本地 `main` 已合入七个分支，但尚未推送远端。法宝 P2 旧分支的采集清单编号需对账，其他工作树也有未提交成果待核收。

## 接手时先做什么

先确认要接的是**产品、数据还是裁量引擎**，再读对应现状文档；运行数字先看协调看板。开始修改前，核对本地 `main` 与远端、目标工作树的未提交文件，并确认所用数据批次和评测口径。项目采用“数据/状态入看板、检查点回写状态文档、设计与代码同提交”的维护方式。
