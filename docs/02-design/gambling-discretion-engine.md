## 1. 背景与目标

PRD §4.2 的"处罚预测、类案检索、情节认定辅助"目前只有前端卡片外壳（`PredictionPayload`），后端没有真正的裁量能力。本设计要做一个面向赌博类案件的**裁量引擎**，输入案情事实，输出：

1. **定性**：不构成违法 / 参与赌博 / 为赌博提供条件 / 涉嫌犯罪需移送（行刑衔接）
2. **情节档次**：一般 / 情节严重，以及从轻、减轻、从重、不予处罚、不执行拘留等修正
3. **处罚分布**：拘留天数、罚款数额的**概率分布 + 带覆盖率保证的区间**，不只给一个点估计
4. **依据**：法条与裁量基准条款（只引用经过校验、在行为时有效的条文）+ 类案
5. **解释**：每个情节对结论的影响、缺了哪些关键事实（以及补上后结论会变多少）、对拟处罚的偏离度预警

**做完的标准**：以[固定对照与阶段门禁](../05-research/sota-baselines-and-gates.md)为唯一验收依据（三层对照：公开基准锚点、冻结基线、人类专家；8 条红线；P0–P5 各阶段硬性指标）。本文档中出现的指标只是摘要，与门禁文档不一致时以门禁文档为准。

**设计约束**：质量优先，不做"if 赌资>X 则拘留 Y 天"这种手写启发式打分；同时，也不把数字直接交给 LLM 生成（理由见 §2.3）。

## 2. 业界调研：法律大模型的主流实现思路

### 2.1 路线谱系

| 路线 | 代表工作 | 核心做法 | 对本项目的启示 |
|---|---|---|---|
| 领域继续预训练 + 指令微调 | DISC-LawLLM（复旦，2023）、ChatLaw、LawGPT | 用法规、裁判文书、法考题做 SFT；DISC 用"法律三段论"格式构造 30 万条 SFT 数据，再挂检索模块 | 三段论（规范→事实→结论）适合作为说理输出格式；从零训大模型超出大创预算，只做小规模 LoRA |
| 检索增强（RAG），多源检索 | JuDGE（清华，SIGIR 2025）、CLaw（EMNLP 2025 Findings） | 法规库 + 判例库多源检索后生成 | CLaw 发现多数 LLM **无法准确复述法条原文** → 法条必须从规范库取原文，并在生成后校验 |
| 判别式推理 / 法律智能体 | ADAPT（人大，EMNLP 2024 Findings）、GLARE（2025） | ADAPT：Ask（按法律要件拆解事实）→ Discriminate（候选罪名/法条两两辨析）→ Predict；GLARE 把候选扩展、判例推理、法律检索做成可调用模块 | GLARE 消融：去掉判例推理模块，罪名准确率从 89.7 掉到 80.0 → **类案是推理的核心输入，不只是展示** |
| 小模型 + 大模型协作 | PLJP（2023） | 领域小模型给候选标签并找判例，LLM 在上下文中读判例后做最终判断 | 论文结论：LLM 单独做刑期这类**数值标签**时表现很差 → 数值裁量交给专门模型 |
| 规则/逻辑增强 | RLJP（2025） | 一阶逻辑规则初始化，再用易混案例做对比学习优化规则 | 规范结构应该显式建模，但规则要能从数据中学习修正 |
| 法理机理模型 | SMS（2025） | 按刑法量刑流程建模：起点 + 情节增量 × 调节系数，再截断到法定区间（"饱和"）；4305 份文书抽取 82 个特征（正则 + LLM，人工抽检 98%） | 重伤组区间准确率 91.3%，高于 CatBoost 的 87.4% → **"法律结构 + 数据学参数"在小数据下优于黑箱** |
| 检索 + 强化学习（过程奖励） | MSR²（2026） | Qwen3-8B 在推理中按需检索四个源（法条 5 万条、法学书籍、1071 万份判决、200 份省市量刑指导文件），GRPO 训练，奖励 = 0.8×刑期落入正确区间 + 0.2×Qwen3-32B 对情节分析的评分 | CAIL2018 区间准确率 46.2%（微调基线 41.8%）；消融：去掉过程奖励 −2.9，去掉多源检索 −4.2 → **地方量刑文件是关键检索源**；但即便如此，端到端准确率依然有限 |
| 多智能体模拟庭审 | AgentsCourt / SimuCourt、JurisMMA（2026） | 法官、控辩等多角色辩论后出判决 | 适合做文书和说理，对裁量数值的提升不明确；本项目暂不采用 |
| 产品级系统 | 通义法睿（阿里云）、上海"206 系统" | 法睿：千问基座 + 精调 + 强化学习 + RAG + 法律 Agent + 司法专属小模型；206：类案推送为核心，量刑建议综合 50 多个变量 | 工业界同样是"大模型 + 专属小模型 + 检索"的混合架构，没有纯端到端方案 |

### 2.2 关键结论

1. **刑期/处罚幅度是法律判决预测中最难的子任务**（CAIL2018、PLJP、RLJP 结论一致），LLM 直接生成数字既不准也没有校准。
2. **类案和地方裁量文件**带来的提升最大（GLARE、MSR² 的消融结果）。
3. **事实→要件的结构化拆解**（ADAPT 的 Ask、SMS 的特征抽取）是后续一切推理的基础，抽取质量决定上限。
4. **法条幻觉**是普遍问题（CLaw），引用必须走"检索原文 + 生成后校验"。
5. 小数据场景下，**法律结构先验 + 统计学习**的模型（SMS）比黑箱模型更准，也更可解释。
6. 司法 AI 的定位是**辅助**：《最高人民法院关于规范和加强人工智能司法应用的意见》（法发〔2022〕33 号）要求辅助结果仅供参考、裁判由人作出、责任由人承担 → 引擎必须让人确认事实、看到不确定性、能推翻结论。

### 2.3 为什么不是规则引擎，也不是纯 LLM

| 方案                   | 问题                                                                                                                          |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 手写启发式规则引擎            | 赌博案件的难点在开放性概念（"以营利为目的""情节严重""影响恶劣"）和**档内裁量位置**（同为情节严重，拘 10 日还是 15 日），这些写不成稳定的 if/else；规则也无法从新案例中学习，更给不出不确定性                 |
| 纯 LLM（提示词或微调后直接输出处罚） | 数值没有校准，会编造法条，结论不能稳定复现，也做不了"去掉某情节后结论变多少"这种反事实分析                                                                              |
| **本方案：神经-符号混合**      | **法定边界**（法条罚则、时间效力、行刑衔接门槛）作为可版本化的数据，硬约束输出空间——这是法律本身，不是启发式；**事实理解、开放性概念判断、档内裁量位置、类案相似度**全部从数据学习；数值由校准过的统计模型给出，LLM 负责理解、辨析和说理 |

## 3. 领域分析：赌博案件的规范结构

### 3.1 行政（主战场）

- **基本罚则**：《治安管理处罚法》（2025 年 6 月 27 日修订，2026 年 1 月 1 日施行）**第八十二条**：以营利为目的为赌博提供条件，或参与赌博赌资较大的，处五日以下拘留或一千元以下罚款；情节严重的，处十日以上十五日以下拘留，并处一千元以上五千元以下罚款。
  - 旧法（2012 修正）**第七十条**：罚款上限分别为 500 元、3000 元。
- **修正情节**（新法）：第二十条从轻/减轻/不予处罚；第二十一条认错认罚可从宽；第二十二条从重（含"一年以内曾受过治安管理处罚"）；第二十三条不执行行政拘留（已满 14 不满 16 周岁、16–18 周岁初次、70 周岁以上、孕期或哺乳不满一周岁婴儿等）；第十六条多个违法行为合并执行拘留，最长不超过 20 日。
  - **与 2012 版的差异**（已逐字核对条文）：旧法第十九条只能"减轻或不予处罚"，条件是"情节**特别**轻微"、"消除后果**并**取得谅解"；新法第二十条增加"从轻"、条件放宽，并新增第二十一条"认错认罚"；从重期限由"六个月内"改为"一年以内"；不执行拘留新增"情节严重、影响恶劣"和"一年内二次以上"的例外。所以"从旧兼从轻"要按具体案情比较新旧两部法的整个处罚空间，不能只比罚款上限。
  - **减轻处罚的展开**：公通字〔2007〕1号第四项规定了"拘留并处罚款"减轻后的四种组合；赌博条款一般档的"拘留**或者**罚款"不在该项覆盖范围内，引擎只给出"不予处罚"并提示人工复核【待核验】。
- **时间效力**：《行政处罚法》第三十七条"从旧兼从轻"。新法提高了罚款上限，因此对 2026 年以前的行为、2026 年以后作出决定的案件，通常仍适用旧法幅度。**引擎必须按"行为时 + 决定时"选择罚则**，这是纯 LLM 方案最容易出错的地方。
- **赌资认定**：公安部《关于办理赌博违法案件适用法律若干问题的通知》（公通字〔2005〕30 号）第五、六条规定了赌资范围和人均计算方法（个人投注数额无法确定时，按参赌财物总额除以人数）【待核验原文】。
- **"赌资较大""情节严重"由省级裁量基准细化**，各省差异很大。已检索到的有：山西（晋公通字〔2022〕82 号）、湖南（湘公发〔2022〕6 号）、云南（云公规〔2024〕1 号）、安徽（皖公通〔2023〕17 号）、浙江（浙公通字〔2021〕12 号）、上海（沪公行规〔2023〕5 号）。这些文件大多发布于新法施行前，与新法罚款档次的衔接情况需逐一确认【待核验】。国办发〔2022〕27 号要求裁量基准公开，所以原文可以拿到。

### 3.2 刑事（行刑衔接边界 + 后续扩展）

- 《刑法》第三百零三条：赌博罪（聚众赌博或以赌博为业，三年以下）；开设赌场罪（五年以下 / 情节严重五年以上十年以下，刑法修正案（十一）后）；组织参与国（境）外赌博罪。
- 入罪门槛：两高 2005 年赌博刑事司法解释第一条"聚众赌博"（抽头渔利累计 5000 元以上 / 赌资累计 5 万元以上 / 参赌累计 20 人以上 / 组织 10 人以上出境赌博收取回扣）【待核验】；2010 年网络赌博意见、2014 年赌博机意见、2020 年跨境赌博意见中的"情节严重"标准【待核验】。
- 量刑：两高《关于常见犯罪的量刑指导意见（二）（试行）》中开设赌场罪的量刑起点（"二年以下""五年至六年"）与修正后的法定刑不再对应，有资料标注其已失效，**省级实施细则需逐省核实**【待核验】。

### 3.3 对建模的含义

| 特点 | 建模应对 |
|---|---|
| 法定边界清晰、分档 | 符号层计算"合法输出空间"，作为硬约束（mask） |
| 档内裁量空间大（如 10–15 日） | 统计模型学习档内位置的分布 |
| 地域差异大（省级基准不同） | 地域作为分层随机效应；裁量基准按地域版本化入库 |
| 法律在 2026 年变更 | 规范库带效力区间；模型以"在法定幅度中的相对位置"为目标之一，使旧法数据可以迁移（假设需用 2026 年后数据验证） |
| 开放性概念多 | 有结果标签的（如"情节严重"，可由实际处罚档次反推）由 M4 从数据学习；没有结果标签、又必须读懂原文的定性辨析才交给 LLM，输出**概率**作为 M4 的特征 |
| 衍生量依赖计算（人均赌资、累计额） | LLM 只抽原始量，**衍生量由代码按规范公式计算**，避免 LLM 算错 |

```
要素 E ─→ M2 省级分档 ─┬─ 唯一种类 ─────────────→ 种类（规则）
                        ├─ 多个候选 ─→ M4/文本概率在候选内选 ─→ 种类
                        └─ 无分档（缺赌资、省份未录入）─→ 文本概率（统计参考）
种类 ─→ 法定幅度过滤后的档内数额历史分布（众数 + 前 2 + 频率），不做点预测
```

档内数额对未见机关不可预测（四个目标在机关分组评估上均未超过众数 0.05），故只出分布。省份未录入基准的地区只给国家法定空间与统计参考。

## 5. 模块设计

### M0 知识层：规范库、要素本体、案例库

- **规范库**（`norms/`，YAML，入 Git）：每条规范包含 `id、来源文号、原文、效力起止、适用地域、类型（罚则/修正情节/门槛/计算规则）、结构化参数`。由法律组按原文录入，每条都要附原文链接。规范库就是"法律本身"的机器可读版本，不包含任何经验打分。
- **赌博要素本体**（`schema.py`，Pydantic → JSON Schema），约 40–60 个字段，分组如下：
  - 行为：行为类型、赌博方式（麻将/扑克/赌博机/网络/私彩/六合彩…）、角色（组织者/提供条件者/参赌者/望风/放贷）、次数与持续时间、是否作弊（可能转为诈骗）
  - 数额：个人投注额、单注额、现场查获赌资、累计赌资、抽头渔利额、违法所得
  - 人员：参赌人数、是否有未成年人、是否有国家工作人员、亲属关系
  - 场所：住宅 / 经营场所 / 公共场所、是否境外或网络
  - 主观：营利目的的证据
  - 修正情节：一年内受过治安处罚、主动投案、如实陈述、认错认罚、主动消除后果、阻碍执法
  - 个人状况：年龄、孕期/哺乳、初次违法
- **案例库**（SQLite + FTS5）：事实原文、要素标注、处罚结果、辖区、行为与决定日期、适用法律版本、来源（文号/URL），以及复议或诉讼结果（如有）。沿用仓库现有的语料纪律：**只收有出处的真实材料**。

### M1 要素抽取

- **模型**：沿用 `ollama/qwen3.5:9b`，通过 Ollama 的 `format` 参数传入 JSON Schema 做受限解码；第二阶段用 LoRA SFT 微调（云 GPU 训练，本机只做推理）后转 GGUF 部署。
- **单底座**：LoRA 训练在平台现用的同一个 qwen3.5:9b 上。通用能力回归不超过 2 分（门禁 G2.8）时，微调版直接替换平台默认对话模型；否则 8GB 显存里两个约 5GB 的模型来回装卸，每次切换都要多等数秒。若微调后的 4B 能通过 G2 门禁，可改用 4B 换取速度。
- **输出约束**：每个字段都带 `evidence`（原文引用）和 `status`。证据校验器做模糊匹配，找不到原文的值会降级为"推断"或直接丢弃，从源头防止事实幻觉。
- **数值规范化**：中文数字、"三千余元""1.2 万"等表述由确定性解析器处理；"余""左右"保留为区间。
- **按需升级**：所有案件先做一次关闭思考的抽取；只有关键字段置信度低、证据校验失败或字段之间互相矛盾时，才升级为"思考 + 3–5 次采样投票"，仍不一致则标记低置信并触发追问。目的是让本机 8GB 显存下的平均耗时满足门禁 G5.5。
- **衍生量**：人均赌资、累计额等不交给 LLM 计算，由 M2 按规范库中的计算规则算出。
- **训练数据（教师蒸馏 + 主动学习）**：
  1. 教师模型（冻结基线 B1，版本固定）给 CAIL 赌博子集 4,160 件与采集到的公开文书打**银标**，同时输出抽取理由；
  2. 法律组只校正两部分：随机抽样（用于估计银标质量）和学生模型最不确定的案例（主动学习），校正结果即**金标**；
  3. 学生模型（9B LoRA）用"银标 + 金标"联合训练，同时学习字段值与理由（Distilling Step-by-Step）；银标只用于训练，**任何测试集只用金标**。
  4. 双人标注一个子集，计算 Cohen's κ 检验标注指南的质量。

### M2 规范层（符号约束，不是启发式）

- **时间效力解析**：根据行为时和决定时，选出适用的罚则版本（从旧兼从轻）。
- **地域基准选择**：取辖区在行为时有效的裁量基准条款，用于计算"赌资较大""情节严重"等门槛是否满足（门槛本身是规范库中的数据）。
- **行刑衔接检查**：要素一旦触及刑事门槛，就输出"涉嫌犯罪，建议移送"的概率与依据，不再给出行政处罚结论。
- **合法输出空间 Ω**：枚举在适用法律下可能的处罚组合，例如 {不予处罚, 罚款 ≤1000, 拘留 1–5 日, 拘留 10–15 日并处罚款 1000–5000}，再叠加不执行拘留、合并执行上限等修正。M4 的输出只能落在 Ω 内。
- ~~**门槛只作约束和特征，不直接决定结果**：基准中"赌资较大"之类的数额线进入 Ω 和特征，但开放性条款（"影响恶劣"）以及门槛附近的取舍，由 M3/M4 从数据中学习。~~ **2026-10-28 改为（D-005）**：省级基准各档直接对应处罚种类，**分档结果决定种类**；只有要素不足以选定分档（类别不明、赌资区间跨档、升档条件下赌资不明）时才返回候选集合，由 M4 在候选内选择。开放性条款（"其他情节严重的情形"）仍不由规则判定。
- **计量口径（河北，2026-10-28）**：个人赌资查明按个人定档；个人不明按一场赌资门槛；一场赌资达到起罚线而个人未达第一档按第一档。参与赌博以"赌资较大"为前提，有升档条件而赌资不明时返回{未达起罚标准, 升档}。依据见 `130000.yaml` 注释与 D-005。
- **输出语义**：省级分档是"已知要素的建议"（`stake_threshold.scope`），`hard_filter_allowed=false`；基准未生效~~、与新法衔接未核验~~时返回空档位。~~（v0.6 取代）~~ 新法案件推定沿用省级门槛与档次判断处罚种类，标 `law_alignment=新法推定沿用`、applicability=provisional，档位原文中的罚款数额是旧法数额、本案数额以新法法定幅度为准（D-006）。

### M3 开放性概念判断（LLM 判别式推理）

- **职责收窄**：凡是能从实际处罚反推出标签的判断（"情节严重"由处罚档次反推，从轻从重的效果体现在处罚里），一律交给 M4 从要素学习，得到带校准的概率，不让 LLM 判断。M3 只处理没有结果标签、又必须读懂原文的定性辨析。依据：GLARE、ADAPT 的判别式推理用于罪名定性；PDP-Bench 显示 LLM 在"是否追责"这类边界上明显偏弱。
- **只在需要时调用**：M1 抽出的要素已能确定定性（例如明确有抽头、明确是亲属之间少量输赢）时不调用 M3。
- 采用 ADAPT 的思路：先拆要件，再列出候选定性，然后**两两辨析**（"参与赌博 vs 为赌博提供条件"、"为赌博提供条件 vs 开设赌场罪"、"带彩娱乐 vs 赌博"、原文含糊时"是否以营利为目的"），推理时把检索到的规范原文和 M5 类案放进上下文。
- 输出**概率**，不输出结论（多次采样估计频率，再用验证集校准），作为 M4 的特征，同时为 M6 的说理提供材料。
- 后期可选：用复议决定书、判决书中的说理做 SFT；数据量足够时，参照 MSR² 用 GRPO 训练（结果奖励 = 处罚落在共形区间内，过程奖励 = 情节分析评分），需要租用云 GPU，列为扩展项。

### M4 裁量模型（核心）

- ~~**分层预测目标**：定性 → 档次（"一般 / 情节严重"，以实际处罚档次为标签直接学习）→ 处罚种类（罚款 / 拘留 / 并处）→ 拘留天数（有序）、罚款金额（分桶有序，同时预测在法定幅度中的相对位置）。~~ **2026-10-28 改为（D-005）**：两目标省内档次与种类由 M2 分档确定，M4 只负责①分档留有多个候选时在候选内选择；②档内拘留天数、罚款金额的分布（目前为事件加权历史分布 `data/band_quantities.json`，按法定幅度过滤）。未录入基准的地区，M4 文本模型给出种类的统计参考。下列专家设计保留为档内分布与候选选择的后续改进方向。
- **三个专家**：
  - **A 分层贝叶斯有序回归**（NumPyro）：地域作为随机截距，省份数据少时可以部分共享（partial pooling）；在法律方向明确的特征（赌资、抽头、前科等）上使用符号受约束的先验，保证单调性；系数就是"情节效应"，可以直接解释。思路接近 SMS 的"法律结构 + 学参数 + 截断到法定区间"。
  - **B 单调约束 GBDT**（LightGBM `monotone_constraints`）：捕捉特征之间的非线性交互，作为挑战者模型。
  - **C 类案近邻**：M5 返回的相似案例处罚，按相似度加权得到经验分布。
  - **D 表格基础模型 TabICLv2**（BSD-3-Clause）：在小样本表格数据上是目前公开最强的方法之一，开箱即用、无需调参；同时保留为冻结基线 B6 的默认配置版本作对照。
- **小数据对策**：省份之间部分共享（专家 A）；单调约束降低方差（专家 A、B）；刑事赌博案件中"抽头、赌资越多处罚越重"的方向性规律只作为专家 A 系数方向和量级的**先验**，不与行政案例混合训练（两套罚则不同）。
- **融合**：在验证集上按对数损失学习堆叠权重 → 用 Ω 掩码后重新归一化 → 温度校准。
- **不确定性**：分组（Mondrian）共形预测，按地域 × 档次分组标定，保证 90% 区间在各组都有接近名义水平的覆盖率（普通共形只保证整体平均覆盖，组间可能差异很大）。
- **预测集是若干合法区段的并集**：Ω 本身不连续（拘留 1–5 日与 10–15 日之间的 6–9 日不属于任何档次），所以输出 `pred_set: [[5,5],[10,12]]` 这样的区段列表，不能给出跨越非法区间的 `[5,12]`。
- **为什么不用 LLM 直接出数字**：见 §2.2 第 1 条；LLM 的作用体现在 M1/M3 产出的特征和 M6 的说理里。

### M5 类案检索

- **召回**：BM25（FTS5 + jieba 分词）+ bge-m3 向量（复用现有 RAG）+ 要素硬过滤（同行为类型、同法律版本附近的档次区域）。
- **重排**：bge-reranker-v2-m3 交叉编码器 → **要素对齐打分**（按定性、处罚、情节分维度加权，权重由法律组标注的相关性数据学出；LeCaRDv2 正是按定性、处罚、程序三个维度标注相关性）。
- **输出**：每个类案附"相同点 / 不同点"（由 LLM 基于两边的要素表生成，并校验），以及类案处罚的整体分布。

### M6 解释、校验与交互

- **反事实情节影响**：逐个把要素置空或调整，重算分布，得到"去掉抽头渔利后，情节严重档概率从 0.81 降到 0.27"这样的解释，比注意力权重之类的事后解释更忠实。
- **追问排序**：对缺失字段在合理取值上做期望，计算对预测分布熵的降低量，取信息价值最高的 3 个生成追问（对应 ADAPT 的 Ask）。
- **偏离度预警**：输入拟处罚意见时，给出它在预测分布和类案分布中的分位数；超出 90% 区间就提示，并列出主要原因。
- **说理生成**：LLM 以三段论格式写说理（规范 → 事实 → 情节评价 → 裁量结论 → 类案对照），**只能使用结构化结果中已有的内容**。
- **校验器**（不通过就重写，重写仍失败则只给结构化结果）：
  1. 引用的每个条文都能在规范库中定位，并且在行为时有效；引文与原文逐字一致
  2. 说理中的数字与结构化结果一致
  3. 每个事实陈述都能对应到 M1 的证据引文
- **审计**：每次评估记录引擎版本、规范库版本、模型版本和输入哈希，保证结论可复现。

## 6. 数据方案（最大的风险点）

| 来源 | 内容 | 用途 | 注意事项 |
|---|---|---|---|
| CAIL2018 中第 303 条相关案件 | 刑事事实 + 罪名 + 刑期 | 行刑衔接边界、刑事扩展、抽取器预训练 | 仓库已导入 30 件；需按事件分组划分数据，防止泄漏 |
| 行政复议决定书（各地政府公开） | 事实 + 原处罚 + 复议结论 | 行政裁量标签、说理 SFT | **选择偏差**：进入复议的案件偏争议、偏重罚，需加权，且不能单独作为评测集 |
| 行政诉讼裁判文书（裁判文书网 / 学校的北大法宝、威科账号） | 同上，附法院审查意见 | 同上 | 同上；注意平台使用条款 |
| 公安机关公开的处罚决定、执法公示 | 处罚结果，事实通常较简略 | 校准地域分布 | 信息稀疏，主要用于分布校验 |
| **与公安机关合作获取的脱敏案卷**（通过指导老师） | 完整事实 + 处罚 | **代表性最好的训练集与评测集** | 需签数据使用协议；按《个人信息保护法》脱敏；原始数据不入库 |
| 合成数据（LLM 由要素向量生成案情） | 只用于增强抽取器的鲁棒性 | 抽取器训练 | **绝不作为类案，也不作为裁量标签** |

- **划分**：按事件分组（同一案件的多名违法行为人放在同一份）；另设时间外推（2025 训练 / 2026 测试）和地域外推两个测试集。
- **规模估计**：抽取器金标 300–500 件即可微调；裁量模型每个目标省份至少 300 件行政案例才能得到稳定的分层估计，数据少的省份依靠部分共享。

## 8. 评测体系

> 下表是摘要。指标的精确定义、阈值、对照基线和统计判定规则见[固定对照与阶段门禁](../05-research/sota-baselines-and-gates.md)，以该文档为准。

| 层 | 指标 | 目标 |
|---|---|---|
| M1 抽取 | 字段级准确率 / F1；证据引文命中率；关键字段（赌资、抽头、人数、前科）准确率 | 关键字段 ≥ 95% |
| M2/M3 定性与档次 | 准确率、Macro-F1；行刑移送召回率 | 移送召回率优先（漏移送的代价最高） |
| M4 裁量 | 拘留天数 MAE、±2 日准确率；罚款对数距离；90% 区间实测覆盖率与平均宽度；ECE | 各地域组的覆盖率都在 88%–92% |
| M5 类案 | nDCG@10、MAP（法律组标注的相关性） | 优于纯向量检索基线 |
| M6 说理 | 法条可定位率、数字一致率（硬指标）；法律组盲评（1–5 分，与人工说理对比） | 硬指标 100% |
| 鲁棒性 | **单调性**测试（赌资增加不会使处罚变轻）；**不变性**测试（改动姓名、性别、民族、籍贯等无关属性，分布变化 < ε）；变形测试（同义改写事实，结论不变） | 全部通过才能发布 |

**必须对比的基线**：① qwen3.5:9b 零样本 + 现有 RAG；② LLM + 判例少样本（PLJP 式）；③ 只用要素的 GBDT。同时做消融：去掉类案专家、去掉 M3 特征、去掉 Ω 约束、去掉共形校准。

## 9. 分期计划（约 12 周）

> 每个阶段的硬性完成指标见[固定对照与阶段门禁](../05-research/sota-baselines-and-gates.md) §9；门禁未通过不得进入依赖它的下一阶段。

| 阶段 | 周 | 产出 | 验收 |
|---|---|---|---|
| P0 规范与本体 | 1–2 | 要素本体 v1、标注指南、规范库（国家层 + 1–2 个目标省）、评测协议、契约草案 | 法律组签字确认规范库原文；契约评审通过 |
| P1 数据 | 2–4 | 案例库（CAIL 303 + 复议/诉讼文书 + 合作数据）、教师模型预标注、金标 300+ | κ ≥ 0.8；数据卡（来源、偏差说明） |
| P2 抽取器 | 4–6 | 提示词 + Schema 基线 → LoRA 微调；证据校验；追问 | 关键字段 ≥ 95% |
| P3 规范层 + 裁量模型 | 6–9 | Ω 求解、时间效力、行刑衔接；专家 A/B/C、融合、分组共形 | 优于三个基线；覆盖率达标 |
| P4 类案 + 说理 + 校验 | 8–10 | 混合检索与重排、三段论说理、三类校验器、反事实解释 | nDCG 优于基线；校验硬指标 100% |
| P5 集成与评测报告 | 10–12 | API、卡片、智能体、工作流节点；鲁棒性测试；评测报告 | 端到端演示；全部鲁棒性测试通过 |
| 扩展（可选） | — | M3 的 SFT / GRPO（云 GPU）、刑事量刑分支 | — |

**算力分工**：

| 任务 | 在哪做 | 依据 |
|---|---|---|
| 9B 推理（M1 / M3 / M6）、bge-m3 召回 | 本机 RTX 5060 8GB | Q4_K_M 权重 5.24 GiB，混合注意力的 KV 缓存很小 |
| M4 全部统计模型的训练与推理、重排器推理 | 本机 CPU（31 GB 内存） | 表格数据量在千件级 |
| 9B LoRA 微调 | 租用云 GPU（≥24GB） | Unsloth 官方数据：9B 的 bf16 LoRA 约需 22GB |
| 4B 及以下 QLoRA | 本机可尝试 | 4B 的 bf16 LoRA 约需 10GB，4-bit 量化后大概率能放下，Qwen3.5 混合架构的兼容性待验证 |
| 教师模型银标 | 云 GPU 上的开源大模型或国内大模型 API | 公开文书可走 API；涉及个人信息的数据不出受控环境 |

## 10. 风险与合规

| 风险 | 应对 |
|---|---|
| 行政案例数据少且有偏 | 多源组合 + 偏差加权；推动公安合作数据；数据卡如实记录偏差 |
| 地域基准差异、新旧法切换 | 规范库版本化；地域分层模型；时间外推测试；2026 年数据积累后重新校准 |
| 事实幻觉、法条幻觉 | 证据引文校验 + 法条原文校验；校验失败时降级为只输出结构化结果 |
| 被当成"自动定罚" | 辅助定位（法发〔2022〕33 号）；要素须人工确认；始终展示区间和不确定性；显著提示"不构成法律意见" |
| 个人信息 | 脱敏后入库；日志不记录原文；原始案卷不进仓库 |
| 不公平 | 不变性测试纳入发布门禁；不把与法律无关的个人属性作为特征 |
