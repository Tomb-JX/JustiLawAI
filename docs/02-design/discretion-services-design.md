## 0. 申报书怎么定的

申报书的"研究内容"写得很明确：
- **用户**："法制审核人员与公安民警"；
- **输入**："自动提取笔录等材料中的赌资数额、参赌人数、组织形式、前科劣迹等关键因子"；
- **输出**："建议处罚区间、推送适用法规，并对偏离基准的异常决定实时预警"；
- **架构**："规则—案例"双轮驱动。规则引擎层负责结构化转译基准；案例学习层用决定书校准；双模校验在"偏差过大时触发人工干预"；
- 参照的实务系统是金华市公安局的"行政处罚智能辅助裁量应用"（输入裁量因子、按预设公式出结果）。

也就是说，**原始目标本来就是面向执法人员的裁量计算器**。产品需求后来加上的"公众：结果预期"和"基于 CAIL2018 的判决预测"，才是判决预测框架的来源。两者都可以做，但必须分开设计。

## 1. 两类服务对照

| | **A 执法裁量计算器**（主服务） | **B 公众结果预期**（辅服务） |
|---|---|---|
| 用户 | 办案民警、法制审核人员 | 当事人、公众、法学学生 |
| 使用阶段 | 调查后、作出决定前（呈批、法制审核） | 案发后任何时候，通常在决定前或决定后想了解"会怎样" |
| 输入 | 已查明的要素：人工填写；或从笔录、案卷抽取后由办案人确认（ADR-009） | 自己的叙述或引导式问答；**单方、信息不全、可能不准确** |
| 法律内核 | 相同：法定空间（B）→ 省级基准定档（C） | 相同 |
| 学习部分 | RAP 实务分布（E），作为"同类案件实际怎么处理"的参照 | RAP 实务分布 + 公开文书类案检索；文本模型可作"类似公开案例"的统计参考 |
| 主要输出 | 法定空间与适用法律；成文档位与处罚种类；建议幅度（法定幅度内的历史分布）；**对拟处罚意见的偏离提示**；依据原文；缺失要素的补查提示；审计记录 | **可能结果的范围**（不是单一结论）；哪些事实会改变结果（"如果赌资超过 X 元……"）；适用法条的通俗解释；类似公开案例；程序权利提示（陈述申辩、听证、复议诉讼期限） |
| 不确定性处理 | 要素缺失 → 列出候选，并提示"补查哪一项能定档"；不猜 | 要素缺失 → 给出各种可能的结果及条件，主动追问；必须展示不确定性 |
| 评测口径 | ①规则正确：依据基准原文的黄金用例 100% 通过；②要素齐全时规则能定档的覆盖率；③参照分布校准（RPS、预测集覆盖）；④偏离提示的触发率与可解释性；准确率只作诊断 | ①预测集覆盖：标称 80% 的结果集合实际覆盖率；②校准；③在**模拟的不完整输入**上测（对人工要素做遮蔽，模拟当事人说不清的情况）；④追问能否收窄结果 |
| 合规要点 | "人在回路内"：结果可改、可推翻，修改留痕；不替代法制审核；行刑衔接临界提示人工复核（申报书"逸脱机制"） | 显著提示"不构成法律意见"；不得用于规避执法（不提供"怎样说能少罚"类建议）；不收集超出必要的个人信息 |

## 1a. 第三类：已作出决定的偏离审查（C，负责人 10-28 提出，待确认）

| | C 决定书偏离审查 |
|---|---|
| 用户 | 法制部门案后评查、复议机关、律师 / 当事人评估是否申请复议、同案同罚研究 |
| 输入 | **已作出的处罚决定书**（事实段 + 实际处罚） |
| 与训练数据的关系 | 输入与训练、评测数据是同一种文书，**不存在 R8 的文体错位**；文本特征在这里是正当输入 |
| 输出 | 偏离分三级：①超出法定空间（违法）；②偏离省级基准档位（成文偏离）；③在实务分布中概率很低（实务偏离）。附依据与同类决定分布 |
| 评测 | 有真实标签来源：湖里有 517 份行政复议决定书（含被撤销 / 变更的原处罚），可作"复议机关认定不当"的标签；另可用人为替换处罚的扰动样本测召回 |
| 局限 | 决定书写法会为结论服务，文本模型可能把偏离"解释掉"；未写入的从轻情节会导致误报，所以输出是"提示复核"而非"认定违法" |

判决预测算法（文本 + 要素 + 规则 + RAP）在这里可以成为**核心**，而不只是参考。

## 2. 共用内核与资产复用

```
                ┌─ A 计算器：要素表单 / 笔录抽取 → 人工确认 ─┐
输入 ──────────┤                                              ├→ 要素
                └─ B 公众：叙述 / 引导问答 → 大模型抽取（带不确定性）┘
                                      │
              法律内核（确定）：适用法律、法定空间 Ω → 省级基准定档 → 成文种类与候选
                                      │
              学习层：RAP 实务分布（E）；档内数额分布（D）；类案检索（M5，待建）
                                      │
             ┌────────────── A ──────────────┐   ┌─────────── B ───────────┐
             │ 建议幅度 + 偏离提示 + 补查提示 + 审计 │   │ 结果范围 + 条件说明 + 追问 + 权利提示 │
             └───────────────────────────────┘   └─────────────────────────┘
```

| 大模型要素抽取（ADR-002） | 笔录 → 要素，人工确认 | 叙述 → 要素，带不确定性标记 |

## 3. 判决预测研究在 B 里的位置

这段时间做的判决预测工作，对 B 有直接价值，前提是**输出语义改为"结果范围 + 条件"，而不是"预测你会被罚多少"**：
- 公开决定书正是当事人能看到的参照系。"公开案例中类似情况的处罚分布"是诚实的描述统计；判决后文书的偏差（R8）在这个语义下是透明的，而不是被包装成预测；
- RAP 与规则内核让结果范围受法律约束，不会给出法律上不可能的结果；
- 当事人的叙述与决定书事实段不是同一种文本，所以 B 也应先把叙述抽成要素再进内核，文本模型只作参考。

## 6. 能力封装现状与接口规划（2026-10-28 探查）

### 6.3 接口规划（先改契约、评审后实现；均挂在 `/discretion/` 下）

| 接口 | 输入 | 输出 | 依赖 | 优先级 |
|---|---|---|---|---|
| `GET /meta` | — | 枚举、省份、法律版本 | 已有 | — |
| `POST /decide`（扩展） | 要素；可选 `proposed` 拟处罚 | 现有字段 + `practice`（RAP 分布，标"参照"）+ `missing`（追问）+ `deviation`（有 `proposed` 时） | RAP 导出、追问、偏离 | P0 |
| `POST /extract` | `text`、`doc_kind`（笔录 / 叙述 / 决定书）、`target?`、`model?` | 要素草稿：每字段值 + 原文证据 + 状态；`outcome`（仅决定书） | 抽取改走网关 | P0 |

| `POST /review` | 决定书文本，或 要素 + 实际处罚 | 三级偏离报告 + 依据 + 同类分布 | 抽取、结果解析、偏离 | P1 |
| `GET /cases` | 要素或文本 | 类案列表与处罚分布 | M5 | P2 |

**对话引导**：
- 新增工作流节点 `discretion`（或智能体工具），在对话中按"抽取 → 追问 → 定档 → 出卡片"编排；
- SSE `card` 增加 `card_type: "discretion"`，载荷复用 `/decide` 的输出；
- 页面与对话共用同一组接口。
